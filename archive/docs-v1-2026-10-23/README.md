# lap-backstop

给无人值守的自动化脚本配一个**看门人**和一个**手机遥控器**：脚本照旧跑，出问题先自己救，你在哪都能看和改。

## 项目定义

| 项 | 内容 |
|---|---|
| 一句话目标 | 把一台 Windows 电脑上的自动化脚本托管起来：按编排自动运行，无人值守时保证任务被判定为完成；在任何地方都能看到它在做什么、改它接下来做什么；出问题按规则自动补救，救不回来立即通知。 |
| 目标用户 / 场景 | 单人、自用。第一台机器跑方舟日常（MAA + MuMu）；长期用不同密钥管理不同电脑。 |
| 技术栈 | Python 3.12 + FastAPI + SQLite；电脑端 React + TypeScript + Vite + Tailwind CSS + shadcn/ui，构建为静态文件由 FastAPI 托管；手机端 Kotlin + Jetpack Compose 原生 APK；运行环境 Windows 10/11。 |
| 首个里程碑 | 方舟日常一条完整链路：到点触发 → 前置操作 → 对账并写入脚本配置 → 运行 MAA → 判定 → 通知 → 手机可看可改。 |
| 验收方式 | 整体验收见 [docs/01](docs/01-需求与边界.md)；一期验收记在 `TASKS.md`。 |

## 对象模型

```text
编排（第一层）
  └─ 脚本运行：脚本 + 可选前置操作 + 可选后置动作
        └─ 脚本任务（第二层）：任务流程 → 步骤
```

| 词 | 含义 |
|---|---|
| 编排 | 什么时间、按什么顺序跑哪些脚本 |
| 脚本 | 被托管的外部程序；当前是 MAA |
| 前置操作 | 挂在脚本上的可选准备动作，让脚本能跑起来 |
| 后置动作 | 挂在脚本上的可选收尾动作，在脚本结束后、判定前执行；当前用于图像核对脚本任务完成情况 |
| 脚本任务 | 脚本内部要做的事，由任务流程组成 |
| 任务流程 | 一组步骤，可增、删、改 |
| 步骤 | 流程里的单项，带参数 |
| 运行 | 一次从触发到出结论的完整执行 |
| 冲突 | 程序里的脚本配置与脚本实际配置不一致 |

## 系统结构

| 层 | 职责 |
|---|---|
| 编排 | 时间、脚本顺序、前置操作挂载 |
| 对账 | 脚本配置读写、差异、冲突处理 |
| 执行与兜底 | 启动脚本、看画面、读日志、重试换路 |
| 后置动作 | 脚本结束后执行核对动作，产出判定证据 |
| 判定 | 按判定等级取脚本结果与画面证据 → 完成 / 未完成 / 判不出 |
| 控制 | 本机 HTTP API + SSE，电脑端与 Android 客户端 |
| AI | 识别兜底、任务编排、失败归因，只出主意 |

四条地基原则：

1. **流程是数据，不是代码。** 编排、前置操作、脚本任务都写在配置里。
2. **脚本是黑盒 + 适配器。** 主程序不认识 MAA，只认识适配器。
3. **以结果判定完成。** 不看进程存活，看任务结果；判定等级可选（脚本 / 画面 / 双证据），每个判定留证据。
4. **配置可对账。** 程序侧是唯一编辑入口，脚本侧被改动时能发现、能选择、能留痕。

## 范围

项目做：

- 编排：时间、多脚本顺序、可选前置操作。
- 脚本任务：任务流程与步骤的增删改，程序侧写入脚本侧。
- 运行与兜底：启动、监控、重试、换路、停手通知。
- 后置动作：脚本结束后执行核对动作，当前核对 MAA 任务完成情况。
- 判定：判定等级可选（脚本 / 画面 / 双证据），三态结论。
- 更新模式：按官方公告在更新日先更新再补跑。
- 界面：电脑端窗口与 Android 安装包，能力对等。
- AI：识别兜底、自然语言编排、失败归因、公告解读。
- 多机：不同密钥管理不同电脑。

项目不做：

- 不重写 MAA，不修改游戏客户端，不修改 MAA 的程序文件。
- 不做多用户、不做对外服务、不做跨平台。
- 不做游戏内作弊、绕过检测。
- 不追求 100% 自动：救不回来就停手叫人。

## 技术选择

| 选择 | 理由 |
|---|---|
| Python 3.12 | 图像识别、Windows 窗口操作、MAA 生态都在 Python。 |
| FastAPI | 本机 HTTP 服务与接口，轻量，异步，自带接口文档。 |
| SQLite | 运行记录单文件保存，免部署、可备份。 |
| React + Vite + TypeScript | 电脑端界面；生态最大，组件现成，构建产物是静态文件。 |
| Tailwind CSS + shadcn/ui | 现代外观与深色模式；组件复制进项目，可自由修改。 |
| SSE | 状态实时推送，不轮询，省电省流量。 |
| Kotlin + Jetpack Compose | 手机端原生 APK，直连核心 HTTP API；不依赖浏览器，可使用 Keystore、前台服务与本地通知；可定向借用 dsh-mobile 的 MIT 组件。 |

界面按手机竖屏设计：一屏看到「现在在做什么 / 今天成没成 / 一键叫停」。

## 工作方式

- **证据优先**：每个任务有可验收的判据；没有测试、数据或差分证据，不宣布完成。
- **函数级质量**：改函数先过 `function-spec`；新增或修改函数后用 `function-attack` 找漏；性能问题用 `perf-evidence` 拿基线。
- **交付物通道**：文档、界面文案、注释只写「此刻为真」；交付前跑 `python scripts/check_artifacts.py .`。
- **结构留痕**：顶层目录、技术选型、公共接口变化写进文档或 ADR。
- **任务清单**：没做的事记在 `TASKS.md`。
