# 01 · 需求与边界

[返回总览](00-总览与索引.md)

本文件写项目要达到的完整形态，不分期。一期范围与先后顺序记在 `TASKS.md`。

## 用户与场景

- 使用者：机主本人，单人。
- 第一台机器：家里常开的 Windows 电脑，跑方舟日常。
- 日常：脚本按编排自动跑；人在外面用手机看状态、改编排、改脚本任务、处理冲突。
- 长期：不同密钥管理不同电脑，一台电脑一个核心。

## 对象模型

```text
编排（第一层）
  └─ 脚本运行：脚本 + 可选前置操作 + 可选后置动作
        └─ 脚本任务（第二层）：任务流程 → 步骤
```

| 对象 | 含义 |
|---|---|
| 编排 | 什么时间、按什么顺序跑哪些脚本 |
| 脚本 | 被托管的外部程序；当前是 MAA |
| 前置操作 | 挂在脚本上的可选准备动作，让脚本能跑起来 |
| 后置动作 | 挂在脚本上的可选收尾动作，在脚本结束后、判定前执行；当前用于图像核对脚本任务完成情况 |
| 脚本任务 | 脚本内部要做的事，由任务流程组成 |
| 任务流程 | 一组步骤，可增、删、改 |
| 步骤 | 流程里的单项，带参数 |
| 运行 | 一次从触发到出结论的完整执行 |
| 冲突 | 程序里的脚本配置与脚本实际配置不一致 |

## 功能需求

### R-100 编排

| 编号 | 需求 | 判据 |
|---|---|---|
| R-101 | 按时间点或时间段触发 | 到点启动，误差不超过 30 秒 |
| R-102 | 同一次编排里按顺序运行多个脚本 | 上一个脚本结束后启动下一个 |
| R-103 | 脚本可挂载可选前置操作 | 未挂载时直接启动脚本 |
| R-104 | 错过的触发在窗口内补跑 | 开机后补跑一次 |
| R-105 | 立即跑、叫停、当天跳过 | 叫停 10 秒内收尾，不记为失败 |
| R-106 | 远程修改编排 | 改动在下一次触发生效 |
| R-107 | 修改下次运行生效 | 运行中保存的修改不打断当前运行，下一次触发使用新配置 |

### R-200 前置操作

| 编号 | 需求 | 判据 |
|---|---|---|
| R-201 | 每个脚本可选一个前置操作 | 由准备段与收尾段组成 |
| R-202 | 准备段让脚本能跑 | 环境准备、启动或复用模拟器、拉起游戏、等到主界面 |
| R-203 | 收尾段恢复环境 | 恢复音量、释放防睡眠等 |
| R-204 | 前置操作失败则不启动脚本 | 按兜底处置并通知 |
| R-205 | 前置操作可编辑 | 增删步骤、改顺序、改参数 |
| R-206 | 动作以内置为主 | 识别画面、点击、按键、等待、调音量、启停进程 |
| R-207 | 必要时调用外部程序 | 设超时、捕获输出、拍前后截图；成功由本程序探针确认 |
| R-208 | 方舟的准备好判据 | 识别到主界面（支持多套主题） |

### R-250 后置动作

| 编号 | 需求 | 判据 |
|---|---|---|
| R-251 | 脚本结束后执行后置动作 | 后置动作在判定之前、收尾段之前执行 |
| R-252 | 后置动作是步骤序列 | 步骤可增删改，复用步骤引擎 |
| R-253 | 当前内置核对：图像判定脚本任务完成 | 结束画面为主界面，且没有错误框、掉线、维护、更新或未知画面 |
| R-254 | 后置动作产出判定证据 | 截图、命中模板、得分、结论进入证据库；证据缺失时按判定等级记判不出 |
| R-255 | 程序接管脚本的完成后动作 | 脚本不得提前关闭游戏或模拟器；关闭由收尾段执行 |
| R-256 | 后置动作可编辑 | 步骤、参数、启用开关在两端可改，下一次运行生效 |
| R-257 | 逐项核对可增加步骤 | 通过增加步骤核对理智、每日任务、基建、公招、信用等，每步有独立判据与证据 |

### R-300 脚本任务

| 编号 | 需求 | 判据 |
|---|---|---|
| R-301 | 程序保存脚本任务清单 | 任务流程与步骤都以程序里的为准 |
| R-302 | 增删任务流程 | 手机端与电脑端都能操作 |
| R-303 | 编辑流程内的步骤与参数 | 例如只保留清体力、去掉领奖励 |
| R-304 | 首次接入时导入脚本现有配置 | 导入后由程序管理 |
| R-305 | 开跑前把程序配置写入脚本 | 写入失败则不启动脚本 |
| R-306 | 冲突检测 | 开跑前、打开界面、脚本升级后各查一次 |
| R-307 | 冲突处理 | 以程序为准 / 以脚本为准 / 逐项选择 / 暂不处理 |
| R-308 | 未处理时按默认策略 | 默认策略可设置，默认以脚本为主；脚本完成后动作由程序接管，不适用此默认策略 |

### R-400 运行与监控

| 编号 | 需求 | 判据 |
|---|---|---|
| R-401 | 启动脚本 | 进程存在且窗口出现 |
| R-402 | 采集信号 | 进程、窗口、日志、画面 |
| R-403 | 脚本运行期以日志为主、定时抽帧 | 日志长时间无进展或画面长时间无变化时深入识别 |
| R-404 | 画面识别 | 模板匹配与静止检测，单帧不超过 200 毫秒 |
| R-405 | 进度展示 | 手机端实时看到当前步骤与已用时间 |
| R-406 | 运行结束即通知 | 完成、未完成、判不出都发，不设静音时段 |
| R-407 | 通知渠道可选 | 钉钉、Server酱³，可单独开关；更新失败与兜底停手单独发 |

### R-500 兜底

| 编号 | 需求 | 判据 |
|---|---|---|
| R-501 | 卡住判定 | 画面连续 N 秒无变化且未推进 |
| R-502 | 崩溃判定 | 进程消失或窗口关闭 |
| R-503 | 错误框处置 | 识别游戏自带错误框，先关闭再重试 |
| R-504 | 重试预算 | 每次运行的重试次数与总时长有上限 |
| R-505 | 升级策略 | 重试 → 换路 → 停手 |
| R-506 | 停手通知 | 附截图、人话原因与建议 |

### R-600 判定

| 编号 | 需求 | 判据 |
|---|---|---|
| R-601 | 三态结论 | 完成 / 未完成 / 判不出 |
| R-602 | 判定依据 | 按判定等级选取脚本运行结果、本程序画面识别或两者 |
| R-603 | 不依赖第三方数据接口 | 不登录账号拉取数据 |
| R-604 | 判定留证 | 每条结论附截图、日志片段或退出状态 |
| R-605 | 矛盾即判不出 | 脚本说完成但画面不符，记判不出 |
| R-606 | 判定等级可选 | 脚本口径（只看脚本结果）/ 画面口径（只看本程序画面）/ 双证据（脚本 + 画面）；每个脚本运行可配，设置页给默认值，默认双证据，运行开始时冻结 |
| R-607 | 画面证据来源 | 画面口径与双证据使用后置动作产出的截图与识别结果；证据缺失记判不出 |

### R-700 AI

| 编号 | 需求 | 判据 |
|---|---|---|
| R-701 | 识别兜底 | 规则认不出时给出结构化建议 |
| R-702 | 自然语言编排 | 一句话生成或修改任务，先出草稿与差异 |
| R-703 | 失败归因 | 把证据压成一段人话 |
| R-704 | 公告解读 | 判断公告是否包含版本更新与维护时间 |
| R-705 | 识别辅助 | 模板连续失配时建议采集区域与尺寸 |
| R-706 | 只出主意 | AI 输出建议，动作由规则校验后执行 |
| R-707 | 预算与降级 | 每次运行有次数与金额上限，超限退回规则 |

### R-800 更新模式

| 编号 | 需求 | 判据 |
|---|---|---|
| R-801 | 抓取官方公告 | 定时拉取，缓存正文，解析维护时间 |
| R-802 | 版本检测 | 客户端版本或资源版本变化 |
| R-803 | 更新日让路 | 更新临近时当天那一轮日常让路 |
| R-804 | 更新后补跑 | 更新完成后把当天日常补上 |
| R-805 | 失败处置 | 超时重试一次，仍失败则停手通知并顺延 |
| R-806 | 更新是独立运行 | 有自己的触发、步骤、判定与通知，不属于前置操作 |
| R-807 | 开跑前检查未完成的更新 | 有则先更新再跑，没有则直接跑 |

### R-900 界面与远程

| 编号 | 需求 | 判据 |
|---|---|---|
| R-901 | 电脑端界面 | 托盘常驻，可打开窗口 |
| R-902 | 手机端界面 | Android 安装包；同一局域网直连，不依赖浏览器 |
| R-903 | 本地与远程对等 | 远程能做的，本地都能做 |
| R-904 | 主程序与界面分离 | 界面退出不影响运行 |
| R-905 | 参数全部可配 | 阈值、重试次数、时间窗都在界面里 |
| R-906 | 冲突可见可处理 | 两端都能查看与处理 |
| R-907 | 打开即见待处理 | 第一屏列出冲突、失败、判不出等需要人处理的事项 |
| R-908 | 运行期右下角小窗 | 运行开始后出现，显示当前步骤与停止按钮；关闭小窗收进托盘，运行继续 |
| R-909 | 停止运行即退出 | 停下本次运行，关闭 MAA、游戏与模拟器，并退出程序；下一次由计划任务拉起 |
| R-910 | 关闭主窗口可设置 | 收进托盘或直接关闭窗口，两者都不影响运行 |
| R-911 | 开机自启可设置 | 开启时登录自动启动；关闭后由手动或兜底任务拉起 |
| R-912 | 触发时间可设置 | 界面与手机都能改，保存时同步更新兜底计划任务 |
| R-913 | 脚本完成后动作由程序接管 | 程序把设置映射为脚本的完成后动作；统一写入退出脚本，游戏与模拟器由收尾段关闭 |

### R-1000 留痕与回放

| 编号 | 需求 | 判据 |
|---|---|---|
| R-1001 | 事件流 | 步骤、判定、动作按时间记账 |
| R-1002 | 证据归档 | 截图、日志片段按运行归档 |
| R-1003 | 回放 | 可按事件流重看一次运行 |
| R-1004 | 配置改动记录 | 每次写入脚本的配置与结果都留痕 |

### R-1100 多机（长期）

| 编号 | 需求 | 判据 |
|---|---|---|
| R-1101 | 不同密钥管理不同电脑 | 一台电脑一个核心、一份配置 |
| R-1102 | 不依赖公网 | 局域网或组网工具访问 |

## 非功能需求

| 编号 | 指标 |
|---|---|
| N-101 | 连续 7 天无人值守，人工干预 0 次 |
| N-102 | 常驻内存不超过 300 MB，空闲 CPU 不超过 2% |
| N-103 | 界面首屏 1 秒内可交互 |
| N-104 | 运行时数据本地存储，可整体备份迁移 |
| N-105 | 支持 Windows 10 与 Windows 11 |
| N-106 | 证据默认保留 30 天 |
| N-107 | 开跑前的冲突检测耗时不超过 2 秒 |
| N-108 | 局域网内操作响应不超过 200 毫秒 |

## 安全边界

| 编号 | 约束 |
|---|---|
| S-101 | 不修改游戏客户端文件，不注入、不破解、不绕过检测 |
| S-102 | 不修改 MAA 程序文件，只读写其配置与日志 |
| S-103 | 点击使用固定安全坐标，并设危险区域黑名单（如「清除缓存」按钮所在区域） |
| S-104 | 控制面只在局域网可达，不直接暴露公网 |
| S-105 | AI 给出的坐标与动作必须经白名单与黑名单校验后才执行 |
| S-106 | 密钥只存本地，不写日志、不进备份 |
| S-107 | 每次写入脚本配置前先备份脚本原配置，可回滚 |

## 整体验收

1. 方舟日常连续 7 天无人值守完成并被判定为完成。
2. 手机端可看状态、改编排、改脚本任务、处理冲突。
3. 脚本任务可增删流程与步骤，改动在脚本中生效。
4. 前置操作可挂载、执行、编辑。
5. 至少两类真实故障自愈并最终完成。
6. 每次运行可回放。
7. 三种判定等级都能给出结论；画面证据缺失时记判不出，不降级为完成。

## 不在范围

- 游戏内作弊、修改客户端、绕过检测。
- 对外提供服务、做 SaaS。
- 平台迁移（Linux、macOS）。
- 100% 全自动：救不回来就停手叫人。
