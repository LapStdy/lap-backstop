# 12 · 测试与质量门禁

[返回总览](00-总览与索引.md)

## 为什么

没有测试，重构就是赌博；没有门禁，测试也只是摆设。项目后期的「不敢改、改了就坏」，多数是没有这两样东西。

## 测试分层

| 层级 | 测什么 | 速度 | 占比 |
|---|---|---|---|
| 单元 | 纯逻辑：判定、兜底、解析、状态机 | 毫秒 | 最多 |
| 契约 | 适配器接口、HTTP 与 SSE 的格式 | 毫秒 | 较多 |
| 集成 | 数据库、文件、配置加载 | 秒级 | 少量 |
| 端到端 | 真机：模拟器与游戏（手动或半自动） | 分钟 | 最少 |

原则：能下沉到下一层的，绝不在上一层测。

## 必须测

| 模块 | 原因 |
|---|---|
| 判定器 | 结论错了，整条链路都白跑 |
| 判定等级 | 三种模式的判定矩阵与证据缺失 |
| 后置动作 | 顺序、证据产出、失败处置 |
| 兜底策略 | 出错时的行为决定能不能无人值守 |
| 计划与配置解析 | 配置写错要立刻发现，不能带病运行 |
| 步骤引擎 | 流程调度是核心 |
| HTTP API 与 SSE 格式 | 界面依赖它，改坏了界面就空 |
| 错误码与异常映射 | 通知与排障依赖它 |

## 判定等级矩阵

| 等级 | 脚本证据 | 画面证据 | 结论 |
|---|---|---|---|
| 脚本口径 | 完成 | 任意 | 完成 |
| 脚本口径 | 未完成 | 任意 | 未完成 |
| 脚本口径 | 缺失 | 任意 | 判不出 |
| 画面口径 | 只作触发 | 主界面且无异常 | 完成 |
| 画面口径 | 只作触发 | 明确错误或未完成 | 未完成 |
| 画面口径 | 只作触发 | 未知画面 | 判不出 |
| 双证据 | 完成 | 主界面且无异常 | 完成 |
| 双证据 | 完成 | 异常 | 判不出 |
| 双证据 | 未完成 | 主界面 | 判不出 |
| 双证据 | 完成 | 缺失 | 判不出 |

## 后置动作测试

- 顺序：后置动作在判定之前、收尾段之前执行；脚本重试时只在最终一次之后执行。
- 证据：每次核对产出截图、命中模板、得分与结论；缺任一项记证据缺失。
- 接管：脚本完成后动作被写成退出游戏或退出模拟器时，对账重写并记冲突；收尾段负责关闭游戏与模拟器。
- 失败：后置动作超时或识别失败不进入兜底重试；画面口径与双证据记判不出，脚本口径只记录。
- 逐任务：额外步骤各自有独立判据与证据，不共享成功结论。

## 不必测

- 界面像素级样式。
- 游戏内部行为与第三方程序。
- 一次性脚本与迁移工具。

## 覆盖率

| 范围 | 门槛 |
|---|---|
| 核心模块（`core/`、`storage/`、`config/`） | 85% |
| 整体 | 70% |
| 新增或修改的代码行 | 90% |

门槛只升不降。降低门槛需要 ADR 与人确认。

## 事故回归

每条真实事故对应一条回归用例，放在 `tests/regression/`，命名带事故日期与简述。事故复盘见 [13](13-变更与演进.md)。

## 门禁

每次改动依次执行，任一失败即未完成：

```bash
ruff check .
ruff format --check .
mypy src
pytest -q
lint-imports
python scripts/check_artifacts.py .
```

| 检查 | 拦住什么 |
|---|---|
| ruff | 风格漂移、未使用变量、可疑写法 |
| mypy | 类型不一致、返回值漏判 |
| pytest | 行为回归 |
| import-linter | 跨层调用、循环依赖 |
| check_artifacts | 交付物里的过程文字与施工用语 |

## 提交前自检

- [ ] 新行为有对应用例，修 bug 有先红的用例。
- [ ] 全部门禁命令通过。
- [ ] 变更涉及的文档已同步。
- [ ] 结论有证据：截图、日志或数据。
- [ ] 回滚路径明确。

## 持续集成

- 本地用 pre-commit 钩子跑门禁，提交即检查。
- 远端用 GitHub Actions 跑同一套命令，配置放在 `.github/workflows/`。
- 门禁命令写在一个脚本里，本地与远端共用，避免两套口径。

## 测试数据

- 截图与日志用录制件，放在 `tests/fixtures/`。
- 敏感信息脱敏后再入库。
- 假实现放在 `tests/fakes/`，不连真实网络与模拟器。

## 性能基线

| 指标 | 门槛 |
|---|---|
| 单帧识别（ROI 内模板匹配） | 20 毫秒内（实测主界面 ROI 约 7 毫秒） |
| 全屏单模板匹配（1280×720） | 200 毫秒内（实测 100 到 190 毫秒，一帧最多查一个） |
| adb 截图（1280×720 PNG） | 700 毫秒内（实测约 600 毫秒） |
| MuMu 原生截图 | 200 毫秒内（实测 10 到 150 毫秒） |
| adb 点击 | 100 毫秒内（实测约 55 毫秒） |
| 后置动作核对（单帧截图 + 识别） | 2 秒内 |
| `GET /api/status` | 100 毫秒内 |
| 核心启动到可访问 | 5 秒内 |
| 常驻内存 | 300 MB 内 |

性能改动需给出前后对比；基线只升不降。

## 紧急例外

线上故障可以绕过门禁先修，但必须：

1. 在 `DEBT.md` 记一笔，注明绕过了哪些检查。
2. 24 小时内补齐用例与门禁，补齐后删除该笔。
