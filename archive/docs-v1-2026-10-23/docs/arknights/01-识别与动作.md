# 识别与动作

本文件讲方舟日常里「看画面、做动作、再看画面」这一套怎么运转。一期只服务六个判断点，其余交给 MAA。

## 截图与点击

| 项 | 方案 |
|---|---|
| 截图 | `adb -s <地址> exec-out screencap -p`，得到 1280×720 PNG |
| 点击 | `adb -s <地址> shell input tap x y` |
| 滑动 | `adb -s <地址> shell input swipe x1 y1 x2 y2 毫秒` |
| 返回 | `adb -s <地址> shell input keyevent 4` |
| 连接模拟器 | MuMu 需显式 `adb connect 127.0.0.1:16384` |

实测耗时：

| 动作 | 耗时 |
|---|---|
| adb 截图（1280×720 PNG） | 约 600 毫秒每帧 |
| adb 点击 | 约 55 毫秒 |
| adb 滑动 | 约 350 毫秒（含 300 毫秒动画） |
| adb 返回键 | 约 50 毫秒 |
| MuMu 原生截图 | 10 到 150 毫秒 |

- 坐标空间是模拟器的 1280×720，与窗口位置、Windows 显示缩放无关。
- 走 adb 的好处：窗口被挡住、被移动、被缩放都不影响；与 MAA 是同一条控制通道。
- 截图转 WebP 存证，原图不长期保留。
- MuMu 另有原生截图与触屏通道：`external_renderer_ipc.dll` 的 `nemu_capture_display` 与 `nemu_input_event_*`，MAA 的 `MumuExtras` 正在使用。调用签名未公开，接入前需逆向；一期用 adb，原生通道作为快速截图备选。

## 分辨率与缩放

- 模拟器固定 1280×720。
- Windows 显示缩放固定 100%。
- 启动前校验；不一致时拒绝运行并提示怎么改。

## 识别与动作的循环

```text
截图 → 模板匹配（ROI 内）→ 候选与得分 → 决策 → 动作 → 等画面变化 → 记录
```

## 决策规则

一期要解决的核心问题：这一帧看到什么，下一帧变了怎么办。

1. **每步声明期望**：当前步骤只认它期望的画面，其他命中先当干扰。
2. **命中优先级**：错误框、掉线提示等安全类最高；其次是当前步骤期望；再次是挡路的弹窗；其余忽略。
3. **去抖**：期望画面连续 N 帧命中才允许动作，避免动画中途误判。
4. **动作后验证**：动作后等待画面变化；规定时间内没变化视为失败，重试。
5. **重试与升级**：同一动作连续失败 M 次，记录证据后交给兜底；不进入盲点循环。
6. **冷却**：同一动作两次之间留最小间隔，避免连点。
7. **互斥**：同一帧命中多个模板时按优先级只取一个，其余记日志。
8. **中断**：任何时刻命中安全类模板（错误框、掉线提示），立即中断当前步骤优先处理。

N、M、等待时间、冷却间隔全部可配，实现时用样本回放校准。

## 安全红线

- 只点只增无损失的动作：登录、确定、继续、关闭弹窗、页签。
- 黑名单：清除缓存、资源修复、退出账号、注销、购买、抽卡、消耗源石。
- 点击用固定安全坐标，并做区域钳制；任何配置都点不进危险区域。
- 先干跑：只识别、只打印坐标与得分，跑通后才开真实点击。
- 每步留证：截图、ROI、得分、坐标、动作、结果。

## 六个判断点

| 判断点 | 期望 | 动作 |
|---|---|---|
| 模拟器就绪 | 窗口与 adb 双确认 | 无 |
| 登录界面 | 模板 | 点固定安全坐标的登录按钮 |
| 主界面 | 多主题模板，任一命中 | 无，交给 MAA |
| 运行中卡住 | 帧差与日志同时无进展 | 交给兜底 |
| 结束状态 | 主界面模板 | 判定 |
| 弹窗与错误框 | 模板 | 关闭或停手 |

## 后置动作的识别点

结束画面核对只读画面，不点击。核对使用以下判断：

| 检查项 | 期望 | 证据 | 不符合时 |
|---|---|---|---|
| 主界面 | 任一主界面模板命中 | 截图、模板名、得分 | 记未完成或判不出 |
| 错误框 | 没有游戏错误框 | 截图、模板名、得分 | 记未完成 |
| 掉线提示 | 没有掉线提示 | 截图、模板名、得分 | 记未完成 |
| 维护/更新 | 没有维护或更新等待画面 | 截图、模板名、得分 | 记未完成或判不出 |
| 未知画面 | 能归入已知画面类 | 截图与候选得分 | 记判不出 |

- 主界面模板支持多套主题；任一命中即可。
- 逐任务核对由额外步骤组成：理智、每日任务、基建、公招、信用等；每步先声明期望，再截图核对，动作与判据分开记录。
- 画面证据必须包含截图、模板名、得分与时间；缺一项记证据缺失，判定记判不出。
- 逐任务核对需要切换界面时，按识别与动作的循环执行，并使用固定安全坐标。

## 证据

每次动作记录：截图路径、ROI、模板名、得分、坐标、动作类型、动作后画面是否变化。运行结束可按事件流回放。

## 实现前要讨论的问题

1. **MuMu 原生截图与点击**：MuMuManager 是否提供这两类接口、命令与权限、与 adb 如何取舍；旧项目里只确认了它用于查模拟器状态。
2. **帧间规则的具体参数**：连续命中帧数 N、重试次数 M、冷却间隔、动作后等待时间，用样本回放校准。
3. **ROI 划分**：每帧查几张模板、各查多大区域，单帧耗时的预算与拆分方式。
4. **动画中间态**：加载转圈、过场动画、渐变切换怎么排除，避免把中间态当成目标画面。
5. **阈值边缘**：得分接近阈值时是动作、等待还是重新截图。
6. **多主题主界面**：十几套主题的模板怎么组织、怎么自动选择。
7. **弹窗策略**：弹窗种类多、位置不固定时，继续采模板还是交给 AI 识别。
