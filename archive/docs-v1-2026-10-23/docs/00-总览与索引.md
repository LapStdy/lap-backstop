# 00 · 总览与索引

[返回 README](../README.md)

## 一句话

把一台 Windows 电脑上的自动化脚本托管起来：按编排自动运行，无人值守时保证任务被判定为完成；在任何地方都能看到它在做什么、改它接下来做什么；出问题按规则自动补救，救不回来立即通知。

## 系统边界

```text
┌──────────────────── 电脑（Windows，常驻）────────────────────┐
│  核心进程 backstop                                            │
│    编排：时间、脚本顺序、前置/后置动作                         │
│    对账：脚本配置读写、差异、冲突                              │
│    执行：启动脚本、看画面、读日志                              │
│    后置：脚本结束后核对画面，产出判定证据                      │
│    判定：按等级取脚本结果与画面 → 三态                         │
│    兜底：重试、换路、停手                                      │
│    AI：识别兜底、编排、归因（只出主意）                        │
│    存储：SQLite + 截图 + 日志                                  │
│    控制面：HTTP API + SSE                                     │
└───────────────────────────┬───────────────────────────────────┘
                            │ 局域网 HTTP
              ┌─────────────┴─────────────┐
        电脑端窗口（WebView2 + 托盘）   手机端 Android App
```

核心进程不认识「明日方舟」，只认识适配器；适配器不认识界面，只认识核心提供的上下文。

## 对象模型

```text
编排（第一层）
  └─ 脚本运行：脚本 + 可选前置操作 + 可选后置动作
        └─ 脚本任务（第二层）：任务流程 → 步骤
```

| 词 | 含义 |
|---|---|
| 编排 | 什么时间、按什么顺序跑哪些脚本 |
| 脚本 | 被托管的外部程序；当前是 MAA |
| 前置操作 | 挂在脚本上的可选准备动作，让脚本能跑起来 |
| 后置动作 | 脚本结束后、判定前执行的动作序列；当前核对脚本任务完成情况 |
| 脚本任务 | 脚本内部要做的事，由任务流程组成 |
| 任务流程 | 一组步骤，可增、删、改 |
| 步骤 | 流程里的单项，带参数 |
| 运行 | 一次从触发到出结论的完整执行 |
| 适配器 | 认识某个脚本的一层薄壳：动作、探针、配置读写 |
| 动作 | 适配器提供的操作，如「启动模拟器」 |
| 探针 | 适配器提供的判断信号，如「是不是登录界面」 |
| 对账 | 比较程序侧配置与脚本实际配置，发现差异并处理 |
| 冲突 | 对账发现的差异，需要人或默认策略决定以谁为准 |
| 兜底 | 运行出错时的处置：重试、换路、降级、停手叫人 |
| 证据 | 判定所依据的截图、日志片段、数据快照 |
| 判定等级 | 判定使用哪类证据：脚本 / 画面 / 双证据 |
| 结论三态 | 完成 / 未完成 / 判不出 |
| 回放 | 按事件流重看一次运行的过程与依据 |

## 一期范围

一期只做一件事：以 MAA 为例，让《明日方舟》清日常在没有人工干预时顺利完成，并被判定为完成。技术验证与实现顺序记在 `TASKS.md`。

## 不可妥协的四条

1. **无人值守**：连续 7 天按编排完成，中间不需要人碰。
2. **以结果判定**：不看进程是否存活，看任务结果；判定等级可选（脚本 / 画面 / 双证据），每个判定有证据。
3. **配置可对账**：程序侧是唯一编辑入口，脚本侧被改动时能发现、能选择、能留痕。
4. **安全**：不改游戏客户端、不改 MAA 程序文件、不暴露公网、危险动作有黑名单。
