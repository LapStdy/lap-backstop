# 04 · AI 服务

## 定位

AI 是旁路增强，不在地基上。规则能判断的不调用；规则认不出时才调用；调用失败退回规则。

## 五个职责

| 职责 | 触发时机 | 输出 |
|---|---|---|
| 看图指导 | 规则认不出当前画面 | 结构化动作建议 |
| 自然语言编排 | 用户在助手里改任务 | 任务草稿与差异 |
| 失败归因 | 运行失败或判不出 | 人话原因与建议 |
| 公告解读 | 抓取到新公告 | 是否更新、维护时间窗 |
| 识别辅助 | 模板连续失配 | 建议采集的区域与模板 |

## 介入时机

| 时机 | 例子 |
|---|---|
| 前置操作识别失败 | 等登录界面超时、画面认不出、游戏弹了没见过的框 |
| 后置动作识别失败 | 结束画面认不出、异常画面分类不明确 |
| 脚本运行异常 | 日志长时间没有进展、画面长时间无变化、脚本报错退出 |
| 判定矛盾 | 脚本报告完成但画面不符，需要解释 |
| 任务编排 | 用户用一句话描述想改什么 |
| 公告解读 | 抓到版本更新公告，需要判断维护时间窗 |

规则能处理的一律不调用 AI。AI 只出主意，所有动作由规则校验后执行。

## 统一约束

- AI 只输出建议，不直接操作鼠标与进程。
- 输入只给必要证据：截图（压缩后）、日志尾部 50 行、事件摘要、当前步骤与期望。
- 输出必须是 JSON，经 schema 校验后才采用。
- 单次调用超时 20 秒，失败最多重试一次。
- 所有调用记录：用途、模型、耗时、token、费用、输入摘要、输出摘要。
- 关闭 AI 时，所有功能退回规则路径，功能降级但不停摆。

## 看图指导

输入：

```json
{
  "screenshot": "<webp 路径或 base64>",
  "context": {
    "task": "arknights_daily",
    "step": "close_popup",
    "expected": "主界面",
    "recent_events": ["等待 90 秒未见主界面", "画面静止 45 秒"],
    "safe_area": [0, 0, 1280, 720],
    "forbidden_areas": [[140, 30, 90, 40]]
  }
}
```

输出：

```json
{
  "observation": "画面是活动公告弹窗，右下角有确认按钮",
  "diagnosis": "固定弹窗挡路",
  "action": { "type": "click", "target": [1000, 640], "why": "关闭公告" },
  "confidence": 0.82,
  "fallback": "wait"
}
```

采用前校验：

1. 动作在允许集合内：点击、等待、按键、滑动。
2. 坐标在截图范围内，且不落在禁止区域。
3. 置信度低于阈值时只记录，不执行。
4. 执行后必须验证效果：画面变化或探针通过；未通过则回退到 `fallback`。

## 自然语言编排

输入：用户文本、当前计划与任务 schema、适配器提供的动作与探针清单。

输出：

```json
{
  "draft": { "schedules": [] },
  "diff": [
    { "path": "schedules.afternoon.at", "from": ["15:00"], "to": ["20:00"] }
  ],
  "explanation": "把下午那次改到 20:00",
  "risk": "low"
}
```

流程：生成草稿 → schema 校验 → 显示差异 → 用户确认 → 生效 → 记录版本，可回滚。

风险分级：

- 低：改时间、开关、阈值。
- 中：增删步骤、改顺序。
- 高：涉及危险动作或删除任务，必须二次确认。

## 失败归因

输入：结论、最后截图、日志尾部、事件流摘要。

输出：

```json
{
  "cause": "游戏客户端提示连接丢失，MAA 按上游配置停止任务",
  "human": "游戏掉线了，MAA 自己停了；这次没跑完，下次会自动重试",
  "suggestion": "检查网络后手动跑一次",
  "confidence": 0.9
}
```

## 公告解读

输入：公告标题与正文。输出：是否包含版本更新、维护时间窗、更新类型、活动信息、置信度。结果写入更新模式的计划，不直接改动计划。

## 识别辅助

模板连续失配时，建议需要采集的区域与模板尺寸，引导用户采集。采集一次后，下次不再调用 AI。

## 安全规则

- 只允许无损失动作：点击、等待、按键、滑动。
- 禁止：向游戏输入文字、关闭系统窗口、账号与充值相关操作、删除存档。
- 禁止区域清单可配置，默认包含「清除缓存」按钮所在区域。
- AI 不能直接修改计划与记录，只能产出草稿。
- 每个 AI 决策留证：截图、输入摘要、输出、执行结果。

## 成本控制

| 手段 | 规则 |
|---|---|
| 按需调用 | 规则失败后才调用 |
| 次数上限 | 每次运行默认 8 次；每天默认 40 次 |
| 金额上限 | 每天默认 1 元 |
| 缓存 | 相同截图哈希与上下文复用结果 |
| 模型分级 | 看图用轻量模型，复杂归因用强模型 |
| 降级 | 超限或不可用时退回规则，记录一次降级 |

## 学习闭环

- 有效判断：记录截图特征与动作，人工确认后沉淀为规则或模板，下次不调用。
- 无效判断：记录反例与原因，避免重复调用。
- 每周回顾一次：命中率、误动作率、平均耗时与费用。

## 评估

样本集由历史截图与人工标注组成。改动提示词或模型前，在样本集上回放，比较命中率与误动作率。
