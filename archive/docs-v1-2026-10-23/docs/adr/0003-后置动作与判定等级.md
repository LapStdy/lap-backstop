# ADR 0003 · 后置动作与判定等级

- 状态：已采纳
- 日期：2026-10-22

## 背景

脚本运行结束后，程序需要判断任务是否完成。MAA 日志能报告队列完成，但日志是脚本自述；画面能反映结束状态，程序需要一个固定的核对阶段来产出画面证据。外部数据接口存在滞后与矛盾，不能作为判定依据。

## 决策

1. **脚本运行增加可选后置动作。** 后置动作在脚本结束后、判定之前、收尾段之前执行，复用步骤引擎。
2. **后置动作当前内置结束画面核对。** 截图识别是否回到主界面，且没有错误框、掉线、维护、更新或未知画面；产出截图、模板名、得分与结论。
3. **判定等级是可配置项。** 取值为脚本口径、画面口径、双证据；每个脚本运行可配，设置页给默认值，运行开始时冻结。默认双证据。
4. **三种等级的证据边界。** 脚本口径只使用脚本结果，证据是日志与退出状态；画面口径只使用后置动作的画面证据，脚本结束信号只用于触发；双证据两者都参与，矛盾记判不出。
5. **程序接管脚本的完成后动作。** 统一写入退出脚本，游戏与模拟器由收尾段关闭；不写入退出游戏或退出模拟器；该字段不适用以脚本为主的默认策略，外部改写按程序值重写并记冲突。
6. **逐任务核对由额外步骤组成。** 理智、每日任务、基建、公招、信用等各用独立画面探针与证据；默认启用结束画面核对。

## 后果

- 一次脚本运行的顺序是：准备段 → 脚本 → 后置动作 → 判定 → 收尾段。
- 新增 `core/postop` 模块；`core/judge` 接收后置动作证据；运行器负责调用顺序。
- 编排项新增 `post_action` 与 `judgement` 字段；新增后置动作配置、数据库字段、API、SSE 事件与错误码。
- 每次运行多一次截图与识别：adb 截图约 600 毫秒，MuMu 原生截图 10 到 150 毫秒；结束画面核对在 2 秒内。
- 工程宪法第 4 条按判定等级要求证据类型：脚本口径不要求截图，但必须有日志或退出状态；画面口径与双证据必须有截图。
- 后置动作拿不到画面时，画面口径与双证据记判不出，不降级为完成。
- 画面口径与双证据依赖游戏结束画面，脚本的完成后动作必须由程序接管；MAA 配置出现退出游戏或退出模拟器时按冲突处理。
- 逐任务核对需要切换游戏界面，按识别与动作的安全规则执行，耗时与误点风险高于结束画面核对。

## 替代方案

| 方案 | 不采纳的原因 |
|---|---|
| 只用 MAA 日志判定 | 日志是脚本自述，脚本报告完成时可能停在异常画面 |
| 只用官方数据接口 | 数据滞后与矛盾，不能作为判定依据 |
| 后置动作放进收尾段 | 收尾段会关闭游戏与模拟器，之后无法截图 |
| 依赖 MAA 自己的完成后动作 | MAA 退出后无法再核对画面 |
| 只做逐任务核对 | 每个任务都要切换界面，成本与误点风险高；结束画面核对先覆盖整队收尾 |
