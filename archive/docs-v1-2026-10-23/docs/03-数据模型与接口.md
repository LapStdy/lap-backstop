## 编排定义

`config/orchestrations/<id>.yaml`：

```yaml
id: arknights_daily
name: 方舟日常
at: ["03:00", "15:00"]
days: all
catch_up_minutes: 180
ensure_updated: true
scripts:
  - script: maa
    pre_op: arknights_ready
    post_action: arknights_verify
    judgement: both
    enabled: true
```

| 字段 | 含义 |
|---|---|
| `at` | 时间点列表，也支持时间段 |
| `days` | `all` 或 `mon,tue,wed,thu,fri` |
| `catch_up_minutes` | 错过触发后的补跑窗口 |
| `ensure_updated` | 开跑前检查未完成的更新，有则先更新 |
| `scripts` | 按顺序运行的脚本，可挂载前置操作与后置动作 |
| `scripts[].post_action` | 后置动作 id；脚本结束后、判定前执行 |
| `scripts[].judgement` | 判定等级：`maa`、`vision`、`both`；运行开始时冻结 |

## 脚本定义

`config/scripts/<id>.yaml`：

```yaml
id: maa
name: MAA
adapter: arknights_maa
enabled: true
```

## 前置操作定义

`config/preops/<id>.yaml`：

```yaml
id: arknights_ready
name: 方舟准备

steps:
  - id: env_prepare
    name: 环境准备
    action: system.prepare_env
    params: { volume: 10, prevent_sleep: true }

  - id: cleanup
    name: 清理残留
    action: system.cleanup_processes
    params: { names: [MuMuPlayer.exe], enabled: false }

  - id: start_emulator
    name: 启动或复用模拟器
    action: arknights.start_emulator
    params: { reuse_if_running: true }
    success_when: arknights.emulator_ready
    timeout: 3m
    on_timeout: retry
    retry: 1

  - id: launch_game
    name: 拉起游戏
    action: arknights.launch_game
    success_when: arknights.login_screen
    timeout: 5m

  - id: enter_main
    name: 进入主界面
    action: arknights.tap_login
    success_when: arknights.main_screen
    timeout: 5m
    on_timeout: retry
    retry: 2

teardown:
  - id: restore_env
    name: 恢复环境
    action: system.restore_env
    params: { restore_volume: true, release_sleep: true }
```

需要调用外部程序时用同一种步骤格式：

```yaml
  - id: run_opener
    name: 调用已有打开脚本
    action: system.run_program
    params:
      path: "D:\tools\open_game.exe"
      args: ["--emulator", "mumu"]
      timeout: 120
    success_when: arknights.main_screen
```

外部程序只负责动作；成功与否由 `success_when` 的探针判断。

## 后置动作定义

`config/post_actions/<id>.yaml`：

```yaml
id: arknights_verify
name: 方舟任务核对
steps:
  - id: verify_tasks
    name: 核对 MAA 任务完成
    action: arknights.capture_end_state
    success_when: arknights.end_state_ok
    timeout: 1m
```

| 字段 | 含义 |
|---|---|
| `id` | 后置动作 id，编排项通过 `post_action` 引用 |
| `steps` | 步骤序列，复用步骤引擎；当前核对步骤为结束画面核对 |
| `success_when` | 画面探针：主界面命中，且没有错误框、掉线、维护、更新或未知画面 |

逐任务核对由额外步骤组成：理智、每日任务、基建、公招、信用等，每步使用独立的画面探针与证据。后置动作步骤失败记证据缺失，不进入兜底重试预算。

## 脚本任务定义

`config/script_tasks/<script>.yaml`：

```yaml
script: maa
flows:
  - id: daily
    name: 日常
    enabled: true
    steps:
      - id: fight
        name: 清体力
        task: Fight
        params: { stage: "1-7", medicine: 1 }

      - id: award
        name: 领奖励
        task: Award

      - id: infrast
        name: 基建换班
        task: Infrast
```

- `flows` 是任务流程，可增、删、改。
- `steps` 是流程内的步骤，顺序即执行顺序。
- `task` 与实际脚本的对应关系由适配器解释：MAA 适配器把 `Fight`、`Award` 映射到 MAA 的任务项。

## 配置对账

程序侧保存两份数据：

| 数据 | 用途 |
|---|---|
| 期望配置 | 程序里编辑后的脚本配置 |
| 写入指纹 | 上次成功写入脚本后的配置哈希 |

开跑前比较脚本实际配置与期望配置：

| 情况 | 判定 | 处置 |
|---|---|---|
| 完全一致 | 无冲突 | 记录指纹，启动 |
| 不一致且实际等于指纹 | 写入没有生效 | 按程序为准重写 |
| 不一致且实际不等于指纹 | 脚本侧被外部修改 | 生成冲突，按默认策略处理 |

冲突记录字段：

| 字段 | 含义 |
|---|---|
| `id` | 冲突编号 |
| `script` | 脚本 id |
| `detected_at` | 检测时间 |
| `trigger` | 开跑前 / 打开界面 / 脚本升级后 |
| `items` | 差异项列表：键、程序值、脚本值、类型 |
| `resolution` | 程序为准 / 脚本为准 / 逐项 / 暂不处理 |
| `resolved_by` | 人或默认策略 |
| `resolved_at` | 处理时间 |

脚本的完成后动作是程序接管字段：需要画面核对时写入退出脚本，游戏与模拟器由收尾段关闭；该字段不适用以脚本为主的默认策略，外部改成退出游戏或退出模拟器时按程序值重写并记冲突。

## 运行时数据

SQLite 表：

| 表 | 内容 |
|---|---|
| `orchestrations` | 编排：时间、脚本顺序 |
| `devices` | 配对设备：id、名称、客户端设备 id、令牌摘要、创建/最后在线/撤销时间 |
| `runs` | 运行：编排来源、开始与结束时间、状态、结论、判定等级 |
| `run_steps` | 步骤：运行 id、步骤 id、状态、进入与离开时间、重试次数 |
| `run_events` | 事件流：序号、类型、时间、载荷 |
| `judgements` | 判定：运行 id、判定等级、结论、依据、核对项、证据引用 |
| `evidence` | 证据：类型、来源（脚本 / 画面）、路径、校验值、可读摘要 |
| `conflicts` | 冲突：差异项、处理结果 |
| `config_writes` | 配置写入：脚本、时间、结果、备份路径 |
| `ai_calls` | AI 调用：用途、模型、耗时、token、费用、结果摘要 |

文件：

```text
data/
├─ backstop.db
├─ runs/<runid>/
│  ├─ screenshots/*.webp
│  ├─ logs/*.txt
│  └─ summary.md
├─ backups/<script>/<时间>-config.<扩展名>
└─ exports/
```

## HTTP API

所有接口以 `/api` 开头，请求头带 `Authorization: Bearer <token>`；电脑端本地页面也可用 `X-Backstop-Token`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 存活、版本与能力位 |
| GET | `/api/status` | 当前运行、队列、最近结论、AI 用量 |
| GET | `/api/orchestrations` | 编排列表 |
| PUT | `/api/orchestrations/{id}` | 修改编排，返回差异 |
| GET | `/api/scripts` | 脚本列表与状态 |
| GET | `/api/scripts/{id}/tasks` | 脚本任务定义 |
| PUT | `/api/scripts/{id}/tasks` | 修改脚本任务，返回差异 |
| GET | `/api/preops` | 前置操作列表 |
| PUT | `/api/preops/{id}` | 修改前置操作 |
| GET | `/api/post-actions` | 后置动作列表 |
| PUT | `/api/post-actions/{id}` | 修改后置动作 |
| GET | `/api/conflicts` | 冲突列表 |
| POST | `/api/conflicts/{id}/resolve` | 处理冲突，参数 `{choice, items}` |
| GET | `/api/settings` | 设置，含默认冲突策略 |
| PUT | `/api/settings` | 修改设置 |
| POST | `/api/runs` | 立即跑一次 |
| POST | `/api/runs/{id}/stop` | 叫停 |
| GET | `/api/runs` | 运行列表 |
| GET | `/api/runs/{id}` | 运行详情与步骤 |
| GET | `/api/runs/{id}/events` | 该运行的事件流（SSE） |
| GET | `/api/runs/{id}/evidence/{name}` | 证据原图或日志片段 |
| GET | `/api/events` | 全局事件流（SSE） |
| POST | `/api/ai/plan` | 自然语言生成草稿，返回差异 |
| POST | `/api/ai/confirm` | 确认草稿并生效 |
| GET | `/api/ai/spend` | 当日与当月用量 |
| POST | `/api/pair` | 用配对码换设备令牌 |
| GET | `/api/devices` | 设备列表、在线状态、最后在线 |
| DELETE | `/api/devices/{id}` | 撤销设备 |

## SSE 事件

| 事件 | 载荷 |
|---|---|
| `run.started` | run_id、orchestration、trigger |
| `step.started` | run_id、step_id、name |
| `step.finished` | run_id、step_id、status、耗时 |
| `post_action.started` | run_id、action_id、name |
| `post_action.finished` | run_id、status、证据摘要 |
| `evidence` | run_id、kind、url、摘要 |
| `judgement` | run_id、mode、conclusion、reason、checks |
| `conflict.detected` | script、差异项数量、冲突 id |
| `config.written` | script、结果、备份路径 |
| `alert` | level、message、evidence |
| `run.finished` | run_id、conclusion、耗时 |
| `heartbeat` | 时间戳，每 15 秒一次 |

## 错误码

| 码 | 含义 |
|---|---|
| `E_NO_ORCHESTRATION` | 编排不存在 |
| `E_NO_SCRIPT` | 脚本不存在 |
| `E_BUSY` | 已有运行在执行 |
| `E_BACKSTOP_EXHAUSTED` | 兜底预算用尽 |
| `E_PREOP_FAILED` | 前置操作失败，脚本未启动 |
| `E_POST_ACTION_FAILED` | 后置动作失败，判定缺画面证据 |
| `E_JUDGE_UNKNOWN` | 判不出 |
| `E_CONFLICT` | 存在未处理的冲突 |
| `E_CONFIG_WRITE` | 脚本配置写入失败 |
| `E_AI_BUDGET` | AI 预算超限 |
| `E_AI_UNAVAILABLE` | AI 不可用 |
| `E_BAD_CONFIG` | 配置校验失败 |
| `E_AUTH` | 令牌缺失或不匹配 |

## 认证

首次启动生成一次性配对码，显示在电脑端窗口。Android App 扫码配对，换取长期设备令牌；令牌存 Android Keystore，服务端只存 SHA-256 摘要。电脑端可查看设备列表并撤销；令牌只放在请求头，SSE 也不放 URL。

配对载荷、设备台账与令牌摘要的参考实现见 [research/01](research/01-远程访问与配对.md)。

## 保留与备份

- 运行记录默认保留 30 天。
- 脚本配置备份保留最近 20 份。
- `GET /api/export` 导出配置、编排、后置动作与运行摘要为 zip。
