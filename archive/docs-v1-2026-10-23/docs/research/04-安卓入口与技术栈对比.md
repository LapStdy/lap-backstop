# 04 · Android 入口与技术栈对比

[返回调研总览](00-dsh-mobile-调研总览.md)

## 结论

> 本对比的结论已采纳：见 [ADR 0002](../adr/0002-手机端采用Android原生客户端.md)。

手机端入口定为 **Android 安装包**，电脑端 WebView2 窗口保留，后端 Python + FastAPI + SQLite 不变。

在「Android-only、单人开发、重 UI 动效、后端不变」四个前提下，首选：

- **Kotlin + Jetpack Compose 单模块**，首期不引入 KMP。
- **HTTP + SSE** 作为状态与事件通道，命令走 HTTP POST；不另造 WebSocket 业务协议。
- **二维码配对 + 一次性码 + 长期设备令牌**；令牌存 Android Keystore，服务端只存 SHA-256 摘要。
- **局域网直连 + Tailscale 出门**；不默认开公网 Tunnel。
- **签名 APK + GitHub Releases**，应用内更新可选；不依赖应用商店。
- UI 借 dsh-mobile 的 Compose 结构与动效（MIT），玻璃库用 `io.github.kyant0:backdrop`（Apache-2.0）或 Haze（Apache-2.0）。

这套组合在 UI 保真与原生能力上不打折，代价是放弃现有 React 页面在手机端的复用，并接受 Kotlin/Gradle 的学习成本。

## 背景与边界

- 手机端不再是浏览器/PWA；安装包直接连电脑上的核心进程。
- 电脑端仍是 WebView2 窗口 + 托盘，加载本机 React 页面；它和 Android 客户端共用同一套 HTTP API。
- 核心仍是单进程、单用户、单机；Android 客户端是瘦客户端，业务判断与数据都在电脑侧。
- 不改变的对象模型：编排 → 脚本运行（脚本 + 可选前置操作）→ 脚本任务（任务流程 → 步骤）；结论仍是完成 / 未完成 / 判不出。
- 公网边界仍是 S-104「控制面只在局域网可达」；出门访问优先 Tailscale 这类组网工具，不开公网入口。

## 产品形态对比

### 配对与首次连接

四种主流做法：

| 做法 | 代表 | 优点 | 缺点 | 对 lap-backstop |
|---|---|---|---|---|
| 一次性二维码 + 长期令牌 | dsh-mobile、Happy、Trifecta、dsh-remote-control、dsh-live | 无需账号、局域网可用、可撤销 | 需要电脑端显示二维码 | 首选 |
| mDNS/UDP 自动发现 + 配对确认 | KDE Connect、OnYx、Home Assistant | 打开即见设备 | 网络设备多时不可靠；需处理欺骗 | 二期可选 |
| 账号登录 + 服务器地址 | Jellyfin、Immich、AgentPilot | 多用户、远程简单 | 单用户场景过重；引入账号体系 | 不采用 |
| SSH 隧道 + 手填地址 | ClawNest | 不暴露端口、复用 SSH | 要求电脑开 SSH；体验差 | 不采用 |

推荐参数：

- 二维码载荷：`version`、`baseUrl`、`pairingCode`、`expiresAt`、`serverId`、`endpoints`；Base64URL 编码 JSON，无 padding。
- 配对码：256 位随机、一次性、默认 5 分钟；进程重启即失效。
- 长期令牌：32 字节随机；服务端只存 SHA-256 摘要；手机存 Android Keystore（AES-GCM）。
- 设备 ID：安装级随机 UUID，只用于复用设备行，不能替代令牌。
- 撤销：服务端删设备行/记 `revoked_at`，在线连接立即断开；手机收到 401/403 后清令牌重新配对。
- 拒绝深链改绑：已绑定设备不接受任意二维码/链接改指向另一台主机；换绑必须显式操作。

同形项目补了三条：

- **先探测再保存**：添加电脑时先打 `/api/health`，成功 / 失败 / 超时三态明确后再入库；不要保存后才报连不上（Jellyfin 的 `CheckUrlState`）。
- **mDNS + 手填兜底 + 超时**：手机端查 `_backstop._tcp`，发现不到就让用户填 `IP:端口`，两边都失败给明确错误；首期可以只做二维码 + 手填，mDNS 放二期（Home Assistant、OnYx）。
- **内网/远程双地址**：数据库存 `lan_url` 与 `remote_url`，每次请求前判断当前网络，判断结果不落盘；Tailscale 地址归到 `remote_url`（Home Assistant 的 `SecurityState`）。

### 本地/远程入口

| 入口 | 做法 | lap-backstop |
|---|---|---|
| 局域网 | 手机与电脑同一 WiFi，直连 `http://<私网IP>:port` | 首选；二维码里带私网地址 |
| 组网 | Tailscale/WireGuard 给电脑一个私有地址 | 出门首选；手机装 Tailscale，App 连私有 IP；不暴露公网 |
| 反向代理/Tunnel | Cloudflare Tunnel、Nginx + TLS | 与 S-104 冲突；需要单独决策与 ADR |
| SSH 隧道 | ClawNest 模式 | 不采用；Windows 开 SSH 的维护成本高 |

安全取舍：局域网 HTTP 的令牌可能被同一网络嗅探；可在后续加「自签 TLS + 证书指纹固定在二维码里」或统一走 Tailscale。首期先保证令牌只在请求头、不写日志、不落明文。

### 后台与通知

Android 的硬限制：

- App 退到后台后，普通 SSE/WebSocket 会被 Doze/厂商省电切断；页面内提示不能当通知。
- 要「出问题立即通知」，只有三条路：前台服务常驻、系统推送（FCM/厂商）、自托管推送（ntfy/UnifiedPush）。

推荐分层：

| 场景 | 方案 |
|---|---|
| App 正在前台 | SSE 实时更新 + 应用内提示 |
| 用户主动「监控本次运行」 | 前台服务 + 常驻通知，保持 SSE；可一键停止 |
| App 被杀死/锁屏 | 服务端发 ntfy（或现有钉钉/Server酱³）；手机装 ntfy App 订阅；可选 FCM |
| 完成/需要人工/失败 | 三类通知分开，事件 ID 去重，点击回到对应 run |

不把「后台常驻 WebSocket」作为唯一方案；前台服务要显示常驻通知，用户可随时关。

### 离线与更新

- 离线只读：缓存最近一次快照、今天结论、当前 run 摘要；不允许离线写操作，不做本地排队重放。
- 更新：GitHub Releases 发签名 APK；App 检查版本、下载、校验 SHA-256、调用系统安装器；签名密钥固定并备份，换签名会导致必须卸载重装。
- 首期可以手动更新；应用内更新作为二期。

### 从同形项目借来的具体机制

| 机制 | 来源 | 用法 |
|---|---|---|
| 地址先探测后保存 | Jellyfin | 添加电脑时 `/api/health` 三态；失败可改地址，不写半条记录 |
| mDNS + 手填 + 超时 | Home Assistant、OnYx | `_backstop._tcp` 发现；失败回退手填；超时给明确提示 |
| 双地址 + 网络状态现算 | Home Assistant | `lan_url` / `remote_url`；每次请求前判断，不缓存「在不在家」 |
| 证书 pin + 人工校验码 | KDE Connect | 开公网/WSS 时用：TLS 自签证书固定，两端显示同一短码；比纯 token 更强 |
| 应用层 ping/pong | Home Assistant | SSE 心跳 + 客户端超时判断；收不到心跳即断开重连，不等 TCP 超时 |
| 一条常驻通知表达状态 | OnYx | 固定通知 id、低优先级渠道；运行状态变化原地更新，不刷屏 |
| 失败通知带证据 | MaaFwApp | 判定失败附日志尾部 + 关键截图；与现有「判定留证据」一致 |
| 多通道 Webhook | MaaFwApp | Server酱、Bark、Gotify、钉钉等统一出口；国内无 FCM 时尤其有用 |

## Agent 客户端对比：哪些是刚需

手机遥控长任务的五件刚需：

| 刚需 | 最小语义 | 参考 |
|---|---|---|
| 实时进度 | 当前 run / step、已耗时、最近判定；失败有原因 | Trifecta 流式渲染；dd2673 只显示 Host 的 projection |
| 一键停止 | 停当前 run；区分「停任务」与「停程序」 | br0k3nb 独立 Ctrl-C；dd2673 停止/排队/引导分开 |
| 审批/提问 | 展示要做什么、为什么、影响面；一次性放行 | dsh-live 按住允许 + fail-closed；4uthen7 展示命令/目录/理由 |
| 断线恢复 | 保留现场、退避重连、重订阅，不回到首页 | 4uthen7 2s<<n 上限 15s；Trifecta 1→30s；ClawNest 只弹横幅 |
| 通知 | 需要人时必达，能分级 | br0k3nb 三通道 + 声音 + 去重 + 开机恢复 |

两条工程刚需：

1. **待命态保活**：电脑程序没在跑时，手机仍要能发「启动」命令；dd2673 用 Windows 生命周期 agent + 55 秒 long-poll。lap-backstop 的「待命 / 干活」两态正好对应。
2. **迟到与重放防护**：命令带 2 分钟过期与已消费 ID；手机网络切换频繁，不能重放旧命令。

Agent 专属、不适用于 lap-backstop：

- 会话线程、消息历史、多 Agent 聚合、模型/推理等级选择。
- 文件编辑、diff、Git/SSH 工作台、终端预览。
- 语音输入、多人协作、Live Activity。
- 在手机本机执行 Agent（androidagent）。

### 总表

| 栈 | 代表 | UI 保真 | 原生能力 | 开发成本 | 复用 | 未来 iOS | 主要风险 |

### 评分（按本项目权重）

权重：UI/动效 30%、原生能力 20%、开发成本 15%、复用 dsh-mobile 15%、未来 iOS 10%、生态/维护 10%。分数 1–5，主观评估。

| 栈 | UI | 原生 | 成本 | 复用 | iOS | 生态 | 加权 |
|---|---|---|---|---|---|---|---|
| Compose | 5 | 5 | 3 | 5 | 1 | 5 | **4.30** |
| Compose Multiplatform | 5 | 4 | 3 | 4 | 4.5 | 3.5 | 4.15 |
| Flutter | 4.5 | 4 | 3.5 | 0 | 5 | 5 | 3.68 |
| React Native/Expo | 4 | 3.5 | 4 | 0 | 5 | 4.5 | 3.45 |
| Capacitor/WebView | 2.5 | 2.5 | 5 | 0 | 4 | 4 | 2.80 |

结论：Compose 以 UI 与原生能力胜出；CMP 是「未来 iOS/桌面共享 UI」的第二选择；Flutter/RN 只有在「复用现有 TS 逻辑」或「iOS 同等重要」时反超；Capacitor 只适合过渡。

### 玻璃与动效库

- `io.github.kyant0:backdrop` 1.0.6（dsh-mobile 使用，Apache-2.0，仓库 Kyant0/AndroidLiquidGlass，最新 2.0.1）：与 dsh-mobile 的 `DshLiquidGlass.kt` 同源，复刻成本最低；库本身不含高层组件。
- Haze 2.0.1（Apache-2.0，Compose Multiplatform，Home Assistant 已用 2.0.0）：模块更完整、跨端更好，2.0 仍标 beta。
- 选择：复刻 dsh-mobile 观感用 backdrop 1.0.6；未来要 iOS/桌面共享 UI 用 Haze 2.x。
- 流体背景：Android 13+ 用 AGSL `RuntimeShader`（dsh-mobile 已验证 30fps 节流、手势期间冻结）；低版本降级为径向渐变 + 光弧。不要在低端机常开。

### 为什么不是 KMP / Flutter / RN / Capacitor

- **KMP**：dsh-mobile 用 KMP 是因为同时做 iOS 与 Android；Android-only 阶段只会增加构建与调试面。等出现第二个端、且协议/状态机复杂到无法维护两份实现时再抽 shared。
- **Flutter**：如果 iOS 在可预见周期内成为同等目标，Flutter 是合理选择；但 Android-only + 重 UI + 可借 dsh-mobile Compose 组件时，Flutter 的跨端优势用不上，还要补平台通道。
- **RN/Expo**：Happy/Trifecta 证明 RN 能做复杂客户端；但玻璃/流体背景仍要 Skia 或原生模块，Expo 版本与原生模块绑定是单人项目的隐性成本。现有 React 页面在手机端不能直接复用，只能复用 TS 逻辑与类型。
- **Capacitor/WebView**：dsh-remote-control 证明它能最快出包；但它的 UI 是 WebView，玻璃/流体只能近似，旧 WebView 还缺 `backdrop-filter`。用户要的是原生观感，不作为目标。

## 推荐方案

### 客户端

- 单模块起步，包结构：`ui/`（Compose 页面与组件）、`data/`（API、SSE、缓存）、`domain/`（模型与用例）、`platform/`（Keystore、通知、前台服务、扫码、更新）。
- 架构：MVVM + Repository；ViewModel 持 `UiState`，SSE 事件进 `EventStream`，按序号更新状态；不做 MVI/Redux 式强类型信封。
- 依赖：Compose BOM + Material3；Navigation Compose；Kotlin Coroutines/Flow；OkHttp + `okhttp-sse` + kotlinx.serialization；DataStore（设置）；Room（可选，只缓存最近快照/历史）；Android Keystore（AES-GCM）；CameraX + ML Kit/ZXing；WorkManager（更新检查，可选）。
- 不首期引入 Hilt：用 Application 级手动依赖图，模块变多再引入。
- minSdk 26，target 最新稳定版；ABI 先 arm64-v8a，必要时加 armeabi-v7a。

### 页面

| 页面 | 内容 |
|---|---|
| 总览 | 现在在做什么、今天成没成、最近一次结论、待处理事项、叫停 |
| 运行详情 | 步骤时间线、已用时间、判定与证据、日志摘要、叫停 |
| 冲突 | 差异项、程序值/脚本值、四个选择、revision |
| 历史 | 运行列表、结论、证据、回放 |
| 设置 | 配对/设备、通知、连接（局域网/Tailscale）、更新、关于 |

复杂编辑器（编排、任务流程、步骤参数）首期不在手机做，保留电脑端；若要求完全对等，再单独排期。

### 后端接口

保持现有 API 风格，补 Android 需要的部分：

| 接口 | 用途 |
|---|---|
| `POST /api/pair` | 配对码换长期令牌；返回 `token`、`device` |
| `GET /api/devices` | 设备列表、在线状态、最后在线 |
| `DELETE /api/devices/{id}` | 撤销设备 |
| `GET /api/health` | 版本、能力位、服务器时间 |
| `GET /api/status` | 全量快照；SSE 重连后先取 |
| `GET /api/events` | SSE；支持 `Last-Event-ID` / `since_seq` |
| `POST /api/runs` | 立即跑一次；带幂等 requestId |
| `POST /api/runs/{id}/stop` | 叫停；带幂等 requestId |
| `GET /api/runs/{id}/events` | 历史分页，`before_seq` / `limit` |

认证：`Authorization: Bearer <token>`；服务端只存摘要；SSE 用 OkHttp 请求头带令牌，不把令牌放 URL。

### 安全

- 令牌只存 Keystore；不写日志、不进备份、不出现在二维码。
- 配对码一次性、5 分钟、只存摘要；配对成功后立即失效。
- 设备可撤销；撤销/失效返回 401/403，App 清令牌并回到配对页。
- 公网只在 Tailscale 私有网络内；不开公网 Tunnel。若未来要开，必须 WSS + 设备令牌 + 登录限速 + 路径白名单，并先改 S-104。
- 局域网 HTTP 首期可用；后续可加自签 TLS + 证书指纹固定。

### 发布

- 签名 APK 发 GitHub Releases；提供 `.sha256`；App 内检查更新、下载、校验、调用系统安装器。
- 签名密钥离线备份；换签名会导致必须卸载重装并丢本地缓存。
- 首期手动更新即可；应用内更新作为二期。

## 迁移顺序

1. 后端补配对、设备表、`/api/health`、SSE 游标与 `gap`；现有电脑端页面继续可用。
2. Android 骨架：单模块 Compose、API/SSE 客户端、Keystore、配对扫码、总览页。
3. 运行详情、叫停、冲突页、历史页。
4. 通知与前台服务；ntfy/钉钉/Server酱³ 兜底。
5. 签名、GitHub Releases、应用内更新（可选）。
6. 手机端 PWA 下线，只保留电脑端 WebView；域名/端口不变。

## 风险与未验证

- Compose 自绘代码量大：dsh-mobile UI 目录 46 个 Kotlin 文件，`ConversationScreen.kt` 3228 行；只对首页与关键弹层做定制，其余用 Material3。
- AGSL 需 Android 13+，真实背景采样需 Android 12+；低版本降级必须实现并测试。
- 低端机玻璃/流体掉帧与耗电未实测；需在目标机上量帧率。
- 应用内更新的厂商安装限制、未知来源权限、签名校验需实机验证。
- Tailscale 在手机上的电量与断线行为未实测。
- ntfy/钉钉/Server酱³ 的通知到达率与锁屏行为未实测。
- 低星项目（ClawNest、Agent Remote、dsh-remote-control、dsh-live）成熟度有限，只借模式，不直接依赖。
