# 02 · 架构

[返回总览](00-总览与索引.md)

## 目标与约束

- 无人值守：核心长期稳定运行，任何单点失败都有降级路径。
- 可回放：判定与动作必须有证据。
- 界面与执行分离：界面只经 HTTP API 与核心通信。
- 脚本可插拔：核心只认识适配器，不认识具体脚本。
- 配置可对账：脚本侧被改动时能发现、能选择、能留痕。
- 证据分级：画面高于进程与退出码，进程与退出码高于日志；判定等级决定哪些证据参与结论。
- AI 旁路：AI 不可用时规则路径照常工作。

## 对象模型

```text
编排（第一层）
  └─ 脚本运行：脚本 + 可选前置操作 + 可选后置动作
        └─ 脚本任务（第二层）：任务流程 → 步骤
```

编排、前置操作、脚本任务都是数据，保存在程序侧。脚本只是执行器：程序在开跑前把脚本任务写入脚本自身的配置，并在开跑前对账。

## 进程模型

| 进程 | 职责 | 生命周期 |
|---|---|---|
| 核心 `backstop` | 编排、运行、对账、后置动作、判定、兜底、存储、HTTP 服务 | 常驻，开机自启 |
| 电脑端外壳 | 托盘 + WebView2 窗口，加载 `http://127.0.0.1:port/` | 随登录启动，退出不影响核心 |
| 手机端 | Android 安装包，访问 `http://<局域网 IP>:port/` | 用时打开 |

核心是单进程：单机单用户，运行线程以等待为主，部署与排障最简单。同一时刻只执行一个脚本运行，其余排队。

## 启动与调度

- 程序由 Windows 计划任务拉起：登录时启动（可关），任务时间兜底拉起。
- 触发时间属于程序配置，界面与手机都能改；保存时同步更新兜底计划任务。
- 待命状态只提供 HTTP 服务与配置读写，不加载图像识别、不启动模拟器。
- 停止运行会退出程序；下一次由登录触发的计划任务或兜底任务拉起。
- 程序不在时手机连不上，因此开机自启默认开启。

运行隔离规则：

- 每次运行在独立线程内执行，动作带超时。
- 运行内异常转为运行失败，不影响核心与界面。
- 核心启动时把上次未结束的运行标记为 `interrupted` 并通知。

- 运行开始时读取配置快照并冻结；运行期间界面的修改只写入程序侧，下一次运行生效。

## 模块划分

| 模块 | 职责 | 允许依赖 |
|---|---|---|
| `core/orchestrator` | 编排解析、触发、补跑、多脚本顺序 | storage、config |
| `core/preop` | 前置操作的步骤执行 | engine、adapters |
| `core/postop` | 后置动作的步骤执行与证据产出 | engine、adapters、probe |
| `core/runner` | 运行生命周期、排队、后置动作、收尾 | storage、engine、backstop、postop |
| `core/engine` | 步骤引擎：进入条件、动作、成功条件、超时 | adapters、probe |
| `core/configsync` | 脚本配置读写、差异比较、冲突记录、对账 | adapters、storage |
| `core/probe` | 探针调度：进程、窗口、日志、画面 | adapters |
| `core/judge` | 按等级合成脚本结果与画面证据，三态结论 | probe、adapters、postop |
| `core/backstop` | 兜底规则与重试预算 | engine、ai |
| `core/evidence` | 截图与日志归档 | storage |
| `adapters/base` | 适配器协议与注册表 | 无 |
| `adapters/arknights` | 模拟器、游戏、MAA、画面、MAA 配置 | core 上下文 |
| `ai/` | 识别兜底、编排、归因、公告解读 | adapters 不感知 ai |
| `web/` | FastAPI 路由、SSE、静态资源 | core 的只读视图 |
| `storage/` | SQLite 与证据文件 | 无 |
| `config/` | 默认值、加载、校验 | 无 |

依赖方向单向：`web → core → adapters`。`ai` 被 `core` 调用且可被禁用。`adapters` 不得依赖 `web` 或 `ai`。

## 数据流

```text
编排 → 开跑前检查未完成的更新 → 前置操作（准备段）
     → 启动脚本 → 配置对账 → 写入脚本配置
     → 脚本运行（日志为主 + 定时抽帧）→ 兜底（重试 / 换路 / 停手）
     → 后置动作（脚本结束后核对画面，产出证据）
     → 判定（按等级取脚本结果与画面）
     → 前置操作（收尾段）
     → 证据归档 → 通知
```

## 前置操作、后置动作与动作类型

前置操作是挂在脚本上的可选步骤序列，分两段：

| 段 | 时机 | 作用 |
|---|---|---|
| 准备段 | 脚本启动前 | 环境准备、启动或复用模拟器、拉起游戏、等到主界面 |
| 收尾段 | 运行结束后 | 恢复环境：音量、防睡眠等 |

后置动作是挂在脚本上的可选步骤序列，在脚本结束后、判定之前执行，不承担环境恢复：

| 项 | 内容 |
|---|---|
| 时机 | 脚本结束（含兜底重试的最终一次）之后、判定之前 |
| 当前用途 | 用本程序图像识别核对脚本任务完成情况，产出判定证据 |
| 步骤来源 | 复用步骤引擎，步骤可增删改 |
| 与收尾段的分工 | 后置动作看画面、出证据；收尾段恢复环境、关闭游戏与模拟器 |
| 失败处置 | 拿不到画面或识别不出时记证据缺失，按判定等级记判不出，不进入重试预算 |

一次脚本运行的顺序：准备段 → 脚本 → 后置动作 → 判定 → 收尾段。

动作分两类：

| 类型 | 例子 | 要求 |
|---|---|---|
| 内置动作 | 识别画面、点击、按键、等待、调音量、启停进程 | 由适配器提供，可回放，失败能定位到步骤 |
| 外部程序 | 调用已有脚本或工具 | 设超时、捕获输出、拍前后截图、记录退出码 |

默认用内置动作。外部程序只用于本程序没有的能力；它不能自己宣布成功，成功由本程序的探针确认。

方舟的准备段顺序：环境准备（音量、防睡眠）→ 清理残留（可关）→ 启动或复用模拟器 → 拉起游戏 → 等登录 → 等主界面。识别到主界面即视为准备好。

## 脚本配置对账

程序侧保存脚本配置的「期望值」与「上次写入指纹」，开跑前执行：

1. 读脚本实际配置。
2. 与期望值逐字段比较。无差异则记录指纹并启动。
3. 有差异则生成冲突记录：差异项、程序侧值、脚本侧值、时间。
4. 判断差异来源：
   - 实际配置等于上次写入指纹：写入没有生效，按「以程序为准」重写。
   - 否则：脚本侧被外部修改，按默认策略处理。
5. 默认策略为「以脚本为主」：把脚本侧的值导入程序。另一端可设为「以程序为主」：把程序的值覆盖到脚本。完成后动作是程序接管字段，按下方规则处理。
6. 处理结果与差异快照写入冲突记录，开跑前完成，不阻塞运行。

写入脚本配置前，先把脚本原配置备份到运行目录，可回滚。

脚本的完成后动作用于控制脚本退出后关闭哪些对象。程序接管这一字段：写入退出脚本，游戏与模拟器由收尾段关闭。该字段不适用「以脚本为主」的默认策略；发现被外部改成退出游戏或退出模拟器，按程序值重写并记一条冲突。

冲突呈现与选择：见 [06 图形界面](06-图形界面.md)。记录结构见 [03](03-数据模型与接口.md)。

## 步骤引擎

编排、前置操作与后置动作共用同一套步骤引擎，任务定义在 YAML 中：

```yaml
steps:
  - id: wait_login
    name: 等登录界面
    action: arknights.wait_for_login
    params: { max_minutes: 15 }
    success_when: arknights.at_login
    timeout: 15m
    on_timeout: retry
    retry: 1
```

引擎对每个步骤：检查进入条件 → 执行动作 → 轮询成功条件 → 超时或失败时按 `on_timeout` 处置 → 记录事件 → 进入下一步。

步骤状态：`pending`、`running`、`ok`、`failed`、`skipped`、`blocked`。

后置动作与前置操作共用同一套步骤引擎；后置动作步骤不进入兜底重试预算。

## 探针与判定

| 探针 | 输入 | 输出 |
|---|---|---|
| 进程 | 进程名或窗口标题 | 存在、退出码 |
| 窗口 | 窗口句柄 | 标题、位置、可见性 |
| 日志 | 日志文件与游标 | 新增行、匹配到的模式 |
| 画面 | 当前截图 | 模板命中、静止时长、区域变化 |

判定等级是脚本运行的一个配置项，取值为脚本口径、画面口径、双证据；默认双证据，运行开始时冻结。

| 等级 | 判据 | 另一来源的用途 |
|---|---|---|
| 脚本口径 | 脚本队列完成、无报错、退出状态 | 画面证据记录，不参与结论 |
| 画面口径 | 后置动作的画面证据 | 脚本结束信号只用于触发核对 |
| 双证据 | 脚本结果与画面证据同时参与 | 两者都参与 |

判定只接受带证据的结论：

- **完成**：按等级选中的证据都指向完成。
- **未完成**：脚本报告未完成，或画面明确停在未完成或错误状态。
- **判不出**：证据矛盾、证据缺失或不可读；双证据下脚本说完成但画面异常也记判不出。

证据可信度按画面、进程与退出码、日志排序。不接入第三方数据接口，不登录游戏账号拉取数据。

## 兜底策略

| 情形 | 处置 |
|---|---|
| 画面长时间无变化 | 尝试安全点击一次；仍无变化则重启脚本 |
| 脚本进程消失 | 重新拉起，沿用当前步骤 |
| 游戏自带错误框 | 识别并关闭，再重试当前步骤 |
| 脚本报告完成但画面不符 | 判不出，等待下一个判定点 |
| 连续失败达到预算 | 停手，发通知，附截图与人话原因 |
| 后置动作拿不到画面 | 记证据缺失；画面口径与双证据记判不出，脚本口径只记录；不进入重试预算 |

预算：每次运行的重试次数与总时长都有上限，写进编排与适配器配置。

## 适配器协议

```python
class Adapter(Protocol):
    id: str

    def actions(self) -> dict[str, Callable[..., ActionResult]]: ...
    def probes(self) -> dict[str, Callable[..., ProbeResult]]: ...
    def read_config(self, ctx) -> dict: ...
    def write_config(self, ctx, config: dict) -> WriteResult: ...
    def diff_config(self, left: dict, right: dict) -> list[ConfigDiff]: ...
```

- 动作签名：`(ctx, params) -> ActionResult`，必须幂等或可安全重试。
- 探针签名：`(ctx, params) -> ProbeResult`，返回 `ok`、`value`、`evidence`。
- 配置读写由适配器负责：每个脚本自己知道它的配置文件长什么样。
- 后置动作的核对能力由适配器的动作与探针提供，不新增协议方法。
- 适配器只使用核心提供的上下文，不依赖界面与 AI。

## 配置分层

优先级从低到高：

1. 代码内默认值。
2. `config/*.yaml` 用户配置。
3. 本次运行参数。

脚本侧配置是程序侧配置的投影，由对账保证一致。

## 失败隔离

| 故障 | 影响 | 处理 |
|---|---|---|
| 界面崩溃 | 无 | 重新打开，核心照常运行 |
| 核心崩溃 | 当前运行中断 | 重启后标记 `interrupted`，发通知 |
| AI 不可用 | AI 相关能力降级 | 退回规则路径，记录一次降级 |
| 网络不可用 | 公告与更新判断降级 | 沿用上次结果并标记过期 |
| 脚本配置写入失败 | 当前脚本不启动 | 记冲突，通知，可重试 |
| 模拟器崩溃 | 当前步骤失败 | 兜底重启，计入预算 |
| 后置动作失败 | 该次判定缺画面证据 | 画面口径与双证据记判不出；脚本口径只记录并通知；不改判为完成 |
