# 04 · AI 服务（Advisor）

[返回总览](00-总览与索引.md)

本文件回答：AI 在平台里以什么身份存在、提供哪五种建议、输入输出契约是什么、失败时平台如何继续运行。

## 定位

Advisor 是可选插件能力，走旁路。作业主路径是「调度 → 环境 → 脚本 → 验证 → 恢复 → 通知」，Advisor 不在这条链的任一步上。

| 项 | 规则 |
|---|---|
| 身份 | 插件能力 `advisor`；一个平台同时只启用一个 Advisor 插件 |
| 调用方 | 内核规则在固定决策点调用；插件之间不互相调用 |
| 输出 | 建议、草稿、解释；不产生 `Verdict`，不改变结论 |
| 失败后果 | 该次建议缺席，作业照常执行、验证与通知 |
| 权限 | 只读证据；无写库、无进程控制、无鼠标键盘、无配置写入 |

规则能判断的场景不调用 Advisor。建议一律先经 schema 校验与规则白名单，再决定是否执行。

## 五个能力

| `kind` | 能力 | 触发点 | 输出用途 |
|---|---|---|---|
| `screen_triage` | 未知画面分诊 | 验证阶段遇到模板未覆盖的画面 | 候选动作，规则校验后执行 |
| `failure_attribution` | 失败归因 | 运行失败或结论为 `unknown` | 人话原因与建议，附通知与运行详情 |
| `announcement` | 公告解读 | 抓取到新公告 | 更新类型、维护时间窗、版本变化 |
| `recognition_assist` | 识别辅助 | 模板连续失配 | 建议采集区域与模板尺寸 |
| `orchestration_draft` | 自然语言编排 | 用户用一句话描述改动 | 配置草稿与差异，确认后生效 |

- 分诊只处理「画面能截到、模板认不出」：规则检查动作类型、坐标范围、禁止区域与置信度，执行一次后判断画面是否变化，未变化按 `fallback` 处理；采用阈值为 `confidence >= 0.7`。
- 归因只用于展示与通知：结果归到一个错误码，不改变 `Verdict`，不触发恢复动作。
- 公告只抽结构化字段：结果进入更新作业草稿，用户确认后成为调度数据；不直接创建或修改调度。
- 识别辅助只给区域建议：用户采集后模板由平台验收入库，Advisor 不写模板文件。
- 编排输出草稿与逐字段差异：经配置 schema 校验、展示差异、用户确认后写入配置修订。风险分低（时间、开关、阈值）、中（增删作业或阶段）、高（删除作业、改恢复策略），高风险二次确认。

## 输入契约

```json
{
  "call_id": "01J9Z6K3T4",
  "schema_version": 1,
  "kind": "screen_triage",
  "job_run_id": "run_7f3a",
  "plugin_id": "maa",
  "deadline_ms": 20000,
  "context": {"phase": "verify", "expected": "主界面", "policy": "dual",
              "recent_events": ["连续 3 帧无变化", "gui.log 末行: 任务已全部完成！"]},
  "evidence": [
    {"id": "ev_01", "kind": "screenshot", "path": "runs/run_7f3a/end.webp", "sha256": "..."},
    {"id": "ev_02", "kind": "log", "path": "runs/run_7f3a/gui.tail.txt", "sha256": "..."}
  ],
  "budget": {"max_output_tokens": 800}
}
```

| 字段 | 规则 |
|---|---|
| `call_id` / `schema_version` | 调用编号；契约版本当前为 1，不匹配直接拒绝 |
| `kind` / `plugin_id` / `job_run_id` | 能力、来源插件、关联运行 |
| `context` / `evidence` | 该能力需要的字段与归档后的只读证据，不含密钥与令牌 |
| `deadline_ms` / `budget` | 默认 20 秒；输出上限由内核按剩余预算截断 |

输入约束：截图最多 1 张并压缩为 WebP；日志只给尾部 50 行；事件摘要最多 20 条；输入总大小不超过 256 KiB。

## 输出契约

```json
{
  "call_id": "01J9Z6K3T4",
  "status": "ok",
  "confidence": 0.82,
  "result": {"observation": "活动公告弹窗，右下角有确认按钮", "diagnosis": "固定弹窗挡路",
             "action": {"type": "click", "target": [1000, 640], "why": "关闭公告"}, "fallback": "wait"},
  "usage": {"input_tokens": 1200, "output_tokens": 180, "cost_cny": 0.01, "latency_ms": 3400},
  "model": "vision-small",
  "prompt_version": "advisor/3"
}
```

`status` 取 `ok`、`abstain`、`error`。`abstain` 表示证据不足或建议不成立，平台按规则路径继续；`error` 表示调用失败，按降级表处理。

| `kind` | `result` 字段 |
|---|---|
| `screen_triage` | `observation`、`diagnosis`、`action{type,target,why}`、`fallback` |
| `failure_attribution` | `cause_code`、`human`、`suggestion`、`related_evidence_ids` |
| `announcement` | `is_update`、`update_kind`、`window_start`、`window_end`、`client_version`、`res_version` |
| `recognition_assist` | `region`、`template_size`、`sample_count`、`reason` |
| `orchestration_draft` | `draft`、`diff[{path,from,to}]`、`explanation`、`risk` |

`action.type` 只允许 `click`、`wait`、`key`、`swipe`；`fallback` 只允许 `none`、`wait`、`reset_environment`；`risk` 只允许 `low`、`medium`、`high`。

## Schema 校验

每个 `kind` 一份 JSON Schema，内核收到响应后立即校验。

| 检查 | 不通过时 |
|---|---|
| 字段符合 schema，`additionalProperties: false` | 建议作废 |
| 必填字段齐全，枚举值合法，`confidence` 在 0 到 1 之间 | 建议作废 |
| 动作要求坐标时，`action.target` 为整数、在环境分辨率内、不落禁止区域 | 建议作废 |
| 草稿能通过平台配置 schema | 草稿不展示 |
| 响应体不超过 64 KiB，`call_id` 与请求一致 | 建议作废 |

校验失败记 `advisor.rejected`，附失败字段与响应摘要；不重试同类请求，不回退到猜测结果。

## 预算

| 项 | 默认值 | 执行者 |
|---|---|---|
| 次数上限/运行 | 8 | 内核按 `job_run_id` 计数 |
| 次数上限/天 | 40 | 内核按自然日计数 |
| 金额上限/运行 | 0.30 元 | 内核按 `usage.cost_cny` 累计 |
| 金额上限/天 | 1.00 元 | 内核按自然日累计 |
| 单次超时 / 重试 | 20 秒 / 1 次，仅网络错误与服务端 5xx | 内核 |
| 并发 / 缓存 | 1 / 键为截图哈希 + `kind` + 上下文摘要，保留 24 小时 | 内核 |

超限时停止调用并记 `advisor.budget_exhausted`，下一个自然日恢复。缓存命中不计次数、不计费用；预算按作业与全局两层独立计算。

## 安全

- 证据按数据对待：日志、公告、截图中的文字都不作为指令执行。
- 输出只走 schema 校验，不接受自然语言动作描述，不提供工具调用。
- 动作白名单为点击、等待、按键、滑动；禁止向游戏输入文字、关闭系统窗口、账号与充值类操作，禁止删除存档与游戏文件。
- 禁止区域清单可配置，默认包含「清除缓存」按钮所在区域；越界或落入禁止区域直接作废。
- 令牌、Cookie、环境变量、绝对路径不进入 prompt；模型密钥存设置，不进插件配置、日志与备份；worker 经内核模型代理联网，便于限额与审计。

## 审计

每次调用写一行 `advisor_calls`。

| 字段 | 内容 |
|---|---|
| `id` / `run_id` | 调用编号与关联运行 |
| `purpose` | 五个能力之一 |
| `model` | 模型标识 |
| `tokens` / `cost` | 用量与费用 |
| `result` | JSON：状态、输入摘要、输出摘要、耗时、置信度、是否采用、降级原因 |
| `created_at` | 调用时间 |

事件：`advisor.requested`、`advisor.responded`、`advisor.rejected`、`advisor.degraded`、`advisor.budget_exhausted`。

接口：`POST /api/v1/advisor/suggest`（服务端校验后调用）；审计记录在 `advisor_calls`，随运行详情查询。

## 降级

| 条件 | 行为 | 记录 |
|---|---|---|
| 未启用、未配置或无密钥 | 不发起调用，界面隐藏相关入口 | `advisor.disabled` |
| 超时或服务端 5xx、限流 | 重试 1 次，仍失败返回 `abstain` | `advisor.degraded` |
| schema 校验失败 | 丢弃响应，返回 `abstain` | `advisor.rejected` |
| 预算用尽 | 当天不再调用 | `advisor.budget_exhausted` |
| 置信度低于阈值 | 记录建议，不执行 | `advisor.responded` |

降级不阻塞作业，不改变 `Verdict`。连续 3 次降级时发通知提示检查配置或网络；恢复后停止提示。

## 验收

关闭 Advisor 时五个决策点都走规则路径，作业可完成、可验证、可恢复。五个 `kind` 的请求与响应都能通过 schema 校验，构造的非法响应全部被拒，越界或落入禁止区域的分诊动作留下拒绝记录。自然语言草稿必须经用户确认才写入配置，配置修订可回滚。每次调用都能在 `advisor_calls` 与事件流中查到输入摘要、输出摘要、用量与耗时。
