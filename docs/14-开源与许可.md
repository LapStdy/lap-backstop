### 为什么是 AGPL-3.0

1. **产品形态决定**：本平台是常驻服务，界面走 HTTP/SSE。AGPL 第 13 条把「通过网络提供服务」也纳入源码提供义务；GPL 只在分发时触发，覆盖不到这种用法。
2. **生态一致**：MAA 以 AGPL-3.0-only 发布，本项目与其同机运行、按其日志与配置约定实现插件。同款许可让「本项目与 MAA 一起分发」的边界最简单。
3. **不取「或更高版本」**：许可固定为 `AGPL-3.0-only`，不授予「或更高版本」，许可升级的选择权留在著作权人手里。
4. **与常见替代的差异**：

   | 替代 | 不选的理由 |
   |---|---|
   | MIT / Apache-2.0 | 允许闭源二次分发；与本项目「改进回流」的目标和 MAA 生态的义务都不对齐。 |
   | GPL-3.0 | 网络使用不触发源码义务，托管场景留口子。 |
   | 自定义许可 / 不开源 | 与「在 GitHub 开源、后续为分发做适配」的目标冲突。 |

### 读者需要做什么

| 场景 | 义务 |

| 分发修改版 | 提供完整源码（含改动）、保留 `LICENSE` 与 `NOTICE`、标明改动。 |
| 通过网络提供修改版服务 | 同上；第 13 条对网络使用同样生效。 |
| 借用图标 | 图标不是 AGPL 内容，先看 [NOTICE](../NOTICE) 第一节。 |

## 第三方引用

| 对象 | 许可 | 本项目的用法 | 义务与边界 |
|---|---|---|---|
| MAA（MaaAssistantArknights） | AGPL-3.0-only | 外部程序：启动、观察、读日志；插件按其公开文档与运行期产物（日志文本、GUI 配置文件）实现环境探测、就绪判定与结果验证 | 仓库不含其源码副本；分发其二进制时随附源码与许可；不使用 MAA Logo |
| MAAEnd | 以 MaaFramework 上游仓库为准 | 外部程序：按命令行与日志观测 | 不复制其源码，不分发其二进制 |
| MaaFramework | 以上游仓库为准 | MAAEnd 的运行时；本项目不直接依赖 | 不复制其 pipeline 结构，只保存路径、哈希与运行结果 |

| opencv-python-headless | Python 包 MIT；OpenCV 本体 Apache-2.0 | 可选 extra `maa-vision` | 保留版权与许可声明 |

## 分发清单

1. **源码包**：仓库全部内容，含 `LICENSE`、`NOTICE`、`docs/`。
2. **构建方式**：`pyproject.toml` 声明运行要求；宿主与打包路径见 [08](08-宿主与运维.md)。
3. **网络服务**：用户能通过网络使用改动版时，提供该改动版的完整源码（第 13 条）。
4. **第三方二进制**：默认不打包；打包则随附上游源码与许可证。
5. **游戏素材**：不打包。
6. **图标**：随 `NOTICE` 提供，或换成自有形象。

## 核对

- 新增或删除第三方代码、素材、字体、图标、运行时依赖，在同一次改动里更新 [NOTICE](../NOTICE) 与本文表格。
- 两者冲突时，以 `NOTICE` 的原文声明为准。
- 仓库不含 MAA、MaaFramework 的源码副本，也不含游戏素材；这条是上面分发口径的前提。
