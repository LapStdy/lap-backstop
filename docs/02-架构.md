# 02 · 架构

[返回总览](00-总览与索引.md)

## 目标与约束

- 内核与具体脚本、游戏解耦：换插件不改内核。
- 时间、资源、状态、契约四类不变量由内核负责。
- 环境启动可能很慢：预热、保温、就绪门控是一等能力。
- 单机、单用户、Windows；常驻进程要能扛住重启、崩溃、磁盘满、断网。
- 界面与执行分离；客户端只经 HTTP API 与 SSE 通信。
- 证据可回放；事件 append-only。
- AI 旁路：不可用时规则路径照常工作。

## 进程模型

| 进程 | 职责 | 生命周期 |
|---|---|---|
| 核心 supervisor | 调度、作业队列、环境/资源状态、插件宿主、恢复、事件、API、存储 | 常驻；开机/登录自启；独立看门狗保活 |
| worker | 执行 prepare/execute/verify/cleanup 阶段；运行插件代码 | 按作业拉起或常驻池；崩溃不带走核心 |
| 电脑端外壳 | 托盘 + WebView2 窗口，加载本机页面 | 随登录启动；退出不影响核心 |
| 手机浏览器/PWA | 访问同一 API | 用时打开 |
| APK 客户端 | 访问同一 API | 用时打开 |

核心默认监听 127.0.0.1:8787；退出码、计划任务名与路径约定见 [08](08-宿主与运维.md)。核心与 worker 通过数据库队列与事件通信；插件只在 worker 内运行。同一环境同一时刻只允许一个作业持有租约。执行器与阶段边界见 [ADR 0007](adr/0007-worker执行器与阶段边界.md)。

## 内核能力

| 能力 | 职责 | 关键约束 |
|---|---|---|
| Scheduler | 持久化 next_run；cron/at/interval；补跑、合并、优先级、deadline | 重启后不丢触发；同一发生点只执行一次 |
| Jobs | JobRun 状态机、队列、attempt、取消、幂等键 | 状态迁移幂等；崩溃可恢复 |
| Environments | 环境状态机、probe、prepare、reset、cleanup、保温 | 状态只能由探针/动作迁移；迁移写事件 |
| Resources | 租约、TTL、续租、排队 | 先租后跑；过期自动回收 |
| Plugins | manifest 校验、注册、能力路由、版本 | 不兼容插件拒绝加载 |
| Recovery | 重试、退避、升级、停手；恢复动作路由 | 预算有限；每次 attempt 留证 |
| Events | 事件日志、证据、快照、回放 | append-only；序号单调 |
| API/Storage | HTTP/SSE、鉴权、SQLite、配置、迁移 | 单一写入者；备份可恢复 |

## 插件模型

插件是可执行扩展包，包含 manifest、能力实现、配置 schema、契约测试入口。

manifest 字段、能力接口、RunContext、Verdict/Evidence/VerificationPolicy 的唯一真源是 [05-插件与适配器](05-插件与适配器.md) 与 `contracts/` 代码；本文不复制接口签名。

能力名称：environment、script、verifier、config_projection、notifier、advisor。插件按需声明，缺少能力时的降级规则见 05。内核只通过 contracts/ 调用插件，不导入插件内部模块；插件不直接写内核数据库。

## 生命周期

~~~text
Scheduler 建 JobRun（幂等键）
  → 队列
  → 获取 ResourceLease
  → prepare：环境 probe / prepare / 预热；未就绪则等待或重试
  → waiting：到 scheduled_at 才进入 executing
  → execute：script.launch / observe / stop
  → verify：verifier.verify → Verdict + Evidence
  → cleaning：environment.cleanup(keep_warm) → 释放租约
  → 通知
  → 事件归档
~~~

失败进入 Recovery：

~~~text
phase 失败 → 记录事件 → recovery policy 决策
  → 重试当前 attempt（退避）
  → 复位环境（reset/restart）
  → 重启脚本
  → 升级到停手，通知
~~~

每个 attempt 有独立的事件与证据；同一 JobRun 的 attempt 递增，超过预算进入 failed。

## 状态机

### Environment

| 状态 | 含义 | 允许迁出 |
|---|---|---|
| unknown | 尚未探测 | off、booting、failed |
| off | 未启动 | booting |
| booting | 启动中 | ready、failed |
| ready | 就绪，可执行 | busy、degraded、off、failed |
| busy | 脚本执行中（租约由资源层管理） | ready、degraded、failed |
| degraded | 部分可用 | ready、failed |
| failed | 不可用 | booting、off |
| 任意状态 | unknown | 休眠恢复或状态不明 |
| 任意状态 | booting | reset |

「任意状态」两行适用于所有非终态，与上表的迁出集合并存。迁移由 probe/动作触发，每次迁移写 `env.state.changed`；同一状态的重复探测只刷新观测时间，不写状态事件，不算迁移。保温策略决定 cleanup 后回到 ready 还是 off。

### JobRun

| 状态 | 含义 |
|---|---|
| scheduled | 已创建，未入队 |
| queued | 等待资源或工作进程 |
| preparing | 准备环境 |
| waiting | 环境就绪，等待计划时间 |
| executing | 脚本运行中 |
| verifying | 收集证据与结论 |
| cleaning | 清理环境、释放租约 |
| recovering | 恢复中 |
| succeeded | 完成 |
| failed | 失败；预算耗尽或错过截止时间 |
| unknown | 证据不足或矛盾 |
| cancelled | 已取消 |

### 状态迁移

JobRun 的迁移穷举如下：

| 当前状态 | 允许迁出 | 条件 |
|---|---|---|
| scheduled | queued、cancelled | |
| queued | preparing、cancelled、failed | failed 仅因截止时间 |
| preparing | waiting、executing、recovering、cancelled、failed、unknown | failed 含阶段失败与截止时间 |
| waiting | executing、recovering、cancelled、failed、unknown | failed 含截止时间 |
| executing | verifying、recovering、cleaning、unknown | |
| verifying | cleaning、recovering、unknown | |
| cleaning | succeeded、failed、unknown、cancelled | |
| recovering | queued、preparing、failed、cancelled、unknown | |
| succeeded / failed / unknown / cancelled | 无 | 终态，不再迁出 |

表中没有的迁移被拒绝：当前状态不变，仍写一条 `run.state.changed` 记录被拒的 from_state、to_state 与 reason，调用方收到 E_CONFLICT。

迁移规则：

- 只有 scheduler 能创建 scheduled；只有 jobs 能迁移运行状态。
- 每次迁移写 `run.state.changed`；迁移前检查当前状态，已在目标状态的重复迁移幂等，不写事件。
- 取消请求在阶段边界生效；执行中取消先 stop 脚本再清理；cleaning 中取消等清理完成后记 cancelled。
- cleanup 完成并释放租约后才进入 succeeded/failed；cleanup 失败按恢复策略处理。
- 崩溃恢复：启动时扫描非终态运行（含 cleaning），按最后事件重建；无法续跑则标记 unknown，或按恢复预算记 failed，并通知。

### Phase

| 状态 | 含义 |
|---|---|
| pending | 未开始 |
| running | 进行中 |
| ok | 成功 |
| failed | 失败 |
| skipped | 跳过（策略允许） |
| timed_out | 超时 |

### ResourceLease

| 状态 | 含义 |
|---|---|
| free | 可租 |
| leased | 已租，带 expires_at |
| expiring | 接近过期，等待续租 |
| released | 已释放 |

## 调度与执行

调度字段、幂等、补跑、合并、优先级、截止时间、预热、保温、租约与恢复语义见 [09-调度与作业语义](09-调度与作业语义.md)。

执行约束：

- 每个 phase 有超时；超时进入 failed 或 recovery。
- 插件调用不得阻塞核心事件循环；worker 单线程执行一个作业。
- 取消通过协作式停止 + 超时强杀；强杀后记录事件并释放租约。
- 所有外部调用带超时；不得出现无超时等待。

### 时钟

- 内核提供统一 Clock：单调时钟用于超时、退避、租约与看门狗，UTC 换算用于调度与展示。
- 调度、超时、退避、租约、看门狗都经 Clock，不直接读系统时间；测试注入虚拟时钟。
- Clock 是内核组件，随 RunContext 注入插件，不作为独立插件能力。
- 时钟实现与虚拟时钟的取舍见 [ADR 0008](adr/0008-统一时钟与虚拟时钟.md)。
- 调度扫描周期 1 秒，触发误差满足 [01](01-需求与边界.md) N-107 的 30 秒要求。

## 事件与证据

事件类型、载荷与 host/core 事件的取值见 [03-数据模型与接口](03-数据模型与接口.md) 的事件注册表；本文不复制清单。

事件 append-only；seq 在运行内单调递增。证据落文件，数据库存路径、来源、类型、哈希与摘要。回放按事件序号重放。

## 配置与存储

- 引导配置：TOML 与环境变量，只放端口、路径、日志级别等启动参数。
- 业务配置：settings 表是唯一真源；密钥走 DPAPI 或进程环境，不进日志与备份。
- 插件配置：JSON Schema 校验后存数据库；插件 payload 不透明。
- 运行状态：SQLite（WAL）；迁移文件 storage/db/migrations/NNNN_<说明>.py，只前滚，回滚走快照；备份包含数据库 + 证据目录。
- 事件与证据保留策略见 [03](03-数据模型与接口.md)。

## 错误分类

| 类别 | 例子 | 处置 |
|---|---|---|
| 配置错误 | schema 校验失败、插件版本不兼容 | 拒绝启动；记事件；不重试 |
| 环境错误 | 模拟器起不来、游戏未就绪 | 按恢复策略重试/复位/停手 |
| 脚本错误 | 进程崩溃、日志报错 | 重启脚本或停手 |
| 验证错误 | 证据缺失、矛盾 | 记 unknown；按策略补救或通知 |
| 资源错误 | 租约冲突、磁盘满 | 排队/降级/通知 |
| 系统错误 | 数据库损坏、权限不足 | 停手；doctor 修复；通知 |

错误码与默认恢复动作见 [03](03-数据模型与接口.md) 的错误码与错误处置两节。

## 失败隔离

| 故障 | 影响 | 处理 |
|---|---|---|
| worker 崩溃 | 当前阶段中断 | 核心重建状态；标记 attempt 失败；按策略重试 |
| 核心崩溃 | 调度与 API 中断 | 看门狗拉起；启动扫描非终态运行；通知 |
| 插件异常 | 当前作业失败 | 捕获、记事件、按恢复策略处理；不拖垮核心 |
| 数据库写失败 | 状态无法落盘 | 停手；保留最后快照；通知 |
| 磁盘满 | 证据写入失败 | 降级：停抽帧、只留判定证据；通知 |
| 断网 | 远程与公告不可用 | 本地照跑；标记 stale |
| 界面崩溃 | 无 | 重新打开；核心照常 |
