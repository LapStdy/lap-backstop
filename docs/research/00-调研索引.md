## 这份文件回答什么

外部调研里哪些结论进入了 v2 设计；原文封存在 archive/，只作材料。

## 远程访问

- 私有网络优先：Tailscale/ZeroTier；不默认开公网 Tunnel。
- 认证交给网络层 + 单 token；不自建配对码、设备台账、Keystore 依赖。
- 外部心跳用 Healthchecks.io 或 Uptime Kuma，覆盖断电断网。

## 手机与界面

- Android 客户端用 Kotlin + Jetpack Compose 单模块；共享 HTTP API。
- 玻璃/动效参考 dsh-mobile 的 MIT 组件；观感是作品线，不进入可靠性关键路径。
- PWA 可作为过渡；Android WebView 已支持 backdrop-filter。

## 事件与同步

- SSE + 快照；断线重连先拉 /status。
- 事件序号单调；客户端按 Last-Event-ID 续传。
- 单人单客户端不需要复杂的多端冲突合并。

## 数据与后端

- FastAPI + SQLite（WAL）；单机单用户。
- 事件 append-only；状态快照可重建。
- 迁移只前进；备份包含数据库与证据。

## 其他产品对照

- AUTO-MAS 覆盖定时、队列、通知、历史、多脚本管理；其边界可作为平台功能清单参照。
- MAA 官方远程控制协议与 Python 绑定可作为 MAA 插件的两条集成路径。
- MAA-Meow 在 Android 原生跑 MaaFramework；作为终端形态的对照，不进入本项目一期。
