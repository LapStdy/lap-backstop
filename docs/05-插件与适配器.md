# 05 · 插件与适配器

[返回总览](00-总览与索引.md)

本文件回答：一个插件由什么组成、内核如何发现与调用它、能力接口长什么样、如何隔离与验收。

本文与 `contracts/` 代码是插件契约的唯一真源；[02](02-架构.md)、[03](03-数据模型与接口.md)、[09](09-调度与作业语义.md) 只引用本文，不复制接口签名。

## 定位

- 内核只认 manifest 与能力接口，不认识具体脚本、游戏与配置文件格式。
- 插件承担脚本差异：启动方式、日志格式、完成信号、配置格式、画面判据。
- 插件不进入内核进程，不直连数据库，不实现调度、队列与恢复预算。

## 插件包

```text
plugins/
  maa/
    plugin.json
    config.schema.json
    plugin.py
    capabilities/
      environment.py
      script.py
      verifier.py
      config_projection.py
    tests/
      test_contract.py
  maaend/
  notifier/
  advisor/
core/plugins/
  registry.py
  loader.py
  channel.py
  rpc.py
  rpc_types.py
  rpc_host.py
  worker.py
tests/
  contract/
  fakes/
```

- 插件只放在 `plugins/<id>/`；入口固定为 `plugin.py`，导出 `PLUGIN` 对象，manifest 不设入口字段。
- 插件包内的私有模块不被内核导入；内核只经 worker 入口调用能力方法。
- `tests/contract/` 与 `tests/fakes/` 由内核维护，所有插件跑同一套契约。

## manifest

`plugin.json`：

```json
{
  "id": "maa",
  "name": "MAA · 明日方舟",
  "version": "1.0.0",
  "api_version": 1,
  "description": "驱动 MAA 完成明日方舟日常并验证结果",
  "capabilities": ["environment", "script", "verifier", "config_projection"],
  "config_schema": "config.schema.json",
  "requires": {
    "contract": ">=1 <2",
    "platform": "windows",
    "python": ">=3.12",
    "executables": [{"name": "MAA.exe"}]
  },
  "config_migrations": [
    {"from": 1, "to": 2, "handler": "migrate_config_1_to_2"}
  ],
  "error_map": {
    "E_ENV_NOT_READY": {"category": "environment", "retryable": true, "recovery": "reset_environment", "message": "环境未就绪"}
  }
}
```

| 字段 | 必填 | 类型 | 规则 |
|---|---|---|---|
| `id` | 是 | string | `^[a-z][a-z0-9_]{1,31}$`，全局唯一，创建后不可改 |
| `name` | 是 | string | 展示名，可改 |
| `version` | 是 | string | 语义化版本；`plugins.version` 记录当前值 |
| `api_version` | 是 | integer | 插件实现的契约版本；不在 `requires.contract` 覆盖范围内时按 manifest 校验失败处理，返回 `E_PLUGIN_MANIFEST` |
| `capabilities` | 是 | array | 至少一项；取值见能力接口；声明了就必须实现 |
| `config_schema` | 是 | string | 包内相对路径，禁止 `..` 与绝对路径；数据库 `plugins.config_schema` 存解析后的 JSON Schema 本体 |
| `requires` | 是 | object | `contract` 是内核允许加载的契约范围；`platform`、`python`、`executables` 在加载时检查。`executables` 为对象数组，每项 `{"name": string, "min_version": string?}`，加载时检查可执行文件存在与版本 |
| `config_migrations` | 否 | array | 配置 schema 升级规则，每项 `{"from": integer, "to": integer, "handler": string}`；`handler` 是插件包内导出的函数名，内核在配置 schema 升级时调用 |
| `description` | 否 | string | 一句话说明插件做什么 |
| `error_map` | 否 | object | 错误码到类别、可重试性、恢复动作与用户文案的映射；键为 `E_*`，值为对象 |

error_map 的值：`category` 取 `environment`/`script`/`config`/`verify`/`resource`/`system`；`retryable` 为布尔；`recovery` 取 `retry`/`reset_environment`/`restart_script`/`abort`；`message` 是用户可读文案模板。未声明的错误码按内核错误表处理。

manifest 的 JSON Schema 本体落在 `contracts/manifest.schema.json`，本文只维护字段表与语义。数据库列名与 manifest 字段名不同：`plugins.requirements` 存 `requires` 的副本，`plugins.config_schema` 存解析后的 JSON Schema 本体。

加载时按顺序校验：JSON 可解析 → 字面规则 → id 唯一 → 契约兼容（插件 `api_version` 落在 `requires.contract` 覆盖范围内）→ schema 可解析 → 声明的能力都能实例化。任一步失败返回 `E_PLUGIN_MANIFEST`，插件不注册，内核记录一次 `plugin.rejected`，其余插件照常运行。

## 版本

| 对象 | 取值 | 规则 |
|---|---|---|
| 契约 `api_version` | 整数，当前为 1 | 内核维护支持集合；插件的 `requires.contract` 必须覆盖内核版本 |
| 插件 `version` | 语义化版本 | 破坏性变更升主版本；`plugins.version` 记录当前值 |
| 配置 schema `x-schema-version` | 整数 | 随插件版本递增；迁移规则见下文 |

`requires.contract` 不覆盖内核支持的契约版本时，内核拒绝加载并返回 `E_PLUGIN_VERSION`；插件 `api_version` 不在自己声明的 `requires.contract` 内属于 manifest 冲突，返回 `E_PLUGIN_MANIFEST`。契约升级时，v1 插件在弃用日期前继续加载；弃用流程见 [13-变更与演进](13-变更与演进.md)。

契约 `api_version=1` 在 fake、MAA、MAAEnd 三者通过契约测试且 [09](09-调度与作业语义.md) 场景用例通过后冻结；冻结前字段变更需 ADR 记录，冻结后按 [13](13-变更与演进.md) 的兼容规则演进。

## RunContext

内核构造、插件只读。所有能力方法的 `ctx` 都是这个对象：

~~~python
@dataclass(frozen=True)
class RunContext:
    run_id: str
    attempt: int
    template_id: str
    plugin_id: str
    environment_id: str
    config: Mapping[str, Any]  # 经 schema 校验后的插件配置
    work_dir: Path  # 本次运行的临时目录
    evidence_dir: Path  # 证据写入目录
    deadline_at: datetime  # 本次调用的硬截止时间（UTC）
    cancel: CancelToken  # is_cancelled() -> bool
    clock: Clock  # monotonic() -> float、utc_now() -> datetime
    secrets: Mapping[str, str]  # 按名读取，只读
    log: Logger  # 结构化日志，字段化，不写自由文本
    emit: Callable[[str, Mapping[str, Any]], None]  # 写 run_events
    record_evidence: Callable[[str, Path, str], str]
    # kind、path、summary -> 证据 id；path 相对 evidence_dir
~~~

- `CancelToken` 由内核持有；插件只能查询，不能取消别的运行。
- `emit` 只允许写事件，不允许写数据库；事件类型必须在 [03](03-数据模型与接口.md) 的注册表中。
- `clock` 是插件唯一的时间来源；等待与超时用它，测试时替换成虚拟时钟。
- `record_evidence` 由内核分配证据 id 并落库，返回的 id 供 `Verdict.checks` 与 `Verdict.evidence_ids` 引用。
- `config` 是不可变视图；插件需要派生值时复制后使用。
- `deadline_at` 到期前必须返回；内核在到期后终止调用并按能力失败处理。

## 能力接口

能力是普通 Python 协议，方法同步执行；内核在 worker 侧按 deadline 控制超时与取消。所有方法接收 `RunContext`，提供路径、密钥、证据写入与日志，不提供数据库句柄。调用经 worker 子进程 RPC：请求、响应、回调与日志都是行分隔 JSON，协议与进程布局见 [ADR 0010](adr/0010-worker子进程与能力调用RPC.md)。

```python
class EnvironmentProvider(Protocol):
    def probe(self, env: EnvironmentRef, ctx: RunContext) -> EnvironmentProbe: ...
    def prepare(self, env: EnvironmentRef, ctx: RunContext) -> PhaseResult: ...
    def reset(self, env: EnvironmentRef, ctx: RunContext) -> PhaseResult: ...
    def cleanup(self, env: EnvironmentRef, ctx: RunContext, keep_warm: bool) -> PhaseResult: ...
    def warm(self, env: EnvironmentRef, ctx: RunContext, minutes: int) -> PhaseResult: ...


class ScriptAdapter(Protocol):
    def launch(self, script: ScriptRef, ctx: RunContext) -> ScriptHandle: ...
    def observe(self, handle: ScriptHandle, ctx: RunContext) -> ScriptObservation: ...
    def stop(self, handle: ScriptHandle, ctx: RunContext, mode: StopMode) -> StopResult: ...
    def recover(
        self, handle: ScriptHandle, ctx: RunContext, action: RecoveryAction
    ) -> RecoveryResult: ...


class Verifier(Protocol):
    def verify(self, ctx: RunContext) -> Verdict: ...


class ConfigProjection(Protocol):
    def diff(
        self, ctx: RunContext, desired: Mapping[str, Any], actual: Mapping[str, Any]
    ) -> list[ConfigDiff]: ...
    def apply(self, ctx: RunContext, desired: Mapping[str, Any]) -> ApplyResult: ...
    def rollback(self, ctx: RunContext, revision: str) -> ApplyResult: ...


class Notifier(Protocol):
    def send(self, ctx: RunContext, message: Notification) -> DeliveryResult: ...


class Advisor(Protocol):
    def advise(self, ctx: RunContext, request: AdvisorRequest) -> AdvisorResponse: ...
```

| 类型 | 字段 |
|---|---|
| `EnvironmentRef` | `id`、`provider_id`、`config`（插件私有的环境参数，JSON） |
| `ScriptRef` | `id`、`plugin_id`、`config`（插件私有的脚本参数，JSON） |
| `EnvironmentProbe` | `state`、`detail`、`observed_at`；状态取值同环境状态机 |
| `PhaseResult` | `ok`、`error_code`、`detail`、`started_at`、`ended_at` |
| `ScriptHandle` | `id`、`pid`、`meta`；由插件解释，内核不解析 |
| `ScriptObservation` | `state`（`running`/`exited`/`hung`）、`signals`（自上次调用后的 Signal 数组）、`last_signal`、`progress`、`since` |
| `Verdict` | `status`（`completed`/`failed`/`unknown`）、`policy_id`、`confidence`、`reason`、`checks`（`list[CheckResult]`）、`evidence_ids`、`created_at` |
| `CheckResult` | `name`、`status`（`ok`/`failed`/`unknown`）、`detail`、`evidence_ids`、`at` |
| `Evidence` | `id`（内核分配）、`kind`（`screenshot`/`log`/`probe`/`exit`/`artifact`）、`source`（`kernel`/`plugin`/`host`）、`path`（相对证据根目录）、`sha256`、`summary`、`created_at` |
| `VerificationPolicy` | `id`、`verifier_plugin_id`、`required_evidence`（证据 kind 数组）、`params`（验证器私有，JSON） |
| `Signal` | `kind`、`payload`、`at`；脚本日志、进度、错误都映射为 Signal |
| `StopMode` | `graceful` / `force` |
| `RecoveryAction` | `retry` / `reset_environment` / `restart_script` / `abort` |
| `ConfigDiff` | `path`、`desired`、`actual`、`kind`（`added`/`removed`/`changed`） |
| `ApplyResult` / `DeliveryResult` / `StopResult` / `RecoveryResult` | `ok`、`error_code`、`detail`、`meta` |
| `Notification` | `level`（`info`/`warn`/`error`）、`title`、`body`、`evidence_ids` |
| `AdvisorRequest` | `kind`、`context`、`evidence`、`budget` |
| `AdvisorResponse` | `status`（`ok`/`abstain`/`error`）、`confidence`、`result`、`usage` |
| `CancelToken` | `is_cancelled() -> bool`；只读 |
| `Clock` | `monotonic() -> float`、`utc_now() -> datetime`；由内核注入 |
| `Logger` | `debug/info/warn/error(fields: Mapping[str, Any])`；结构化字段 |

结果类型的 `error_code` 取 [03](03-数据模型与接口.md) 的错误码表，成功时为 `null`；`detail` 保留人可读说明，供界面与通知显示。

`Verdict.status = completed` 由内核映射为 `JobRun.succeeded`；`failed` 与 `unknown` 同名直传。`Verdict` 只由 `Verifier` 产生，`Advisor` 不能写结论。`Evidence.source` 标明证据由谁写入：`kernel` 为内核机械采集，`plugin` 为插件判定过程，`host` 为宿主与环境。

`ScriptAdapter.observe` 由内核按 5–30 秒轮询；每次返回自上次调用后的 Signal 列表与当前状态，插件自行缓冲，不要求流式。

`VerificationPolicy` 由 JobTemplate 保存完整结构，内核不设策略注册表：`id` 在模板创建时生成 UUID，`Verdict.policy_id` 回填模板里的 `id`；`required_evidence` 至少一项，内核按它检查证据是否齐全，缺失时结论固定记 `unknown`。`Verdict.evidence_ids` 至少一条，否则内核拒绝并记 `E_VERIFY_NO_EVIDENCE`。`params` 由验证器解释，MAA 的脚本/画面/双证据三档就是 `params.mode` 的三个取值，不进入内核。

| 插件 | environment | script | verifier | config_projection | notifier | advisor |
|---|---|---|---|---|---|---|
| `maa` | ✓ | ✓ | ✓ | ✓ | | |
| `maaend` | ✓ | ✓ | ✓ | | | |
| `notifier` | | | | | ✓ | |
| `advisor` | | | | | | ✓ |

能力按需声明，不要求齐全。内核按能力路由；缺少能力时降级：无 `Verifier` 记 `unknown`，无 `Notifier` 只写事件，无 `Advisor` 走规则路径。模板要求的验证能力缺失时，运行照常创建，结论记 `unknown`。

租约在 `prepare` 前获取，一直持有到 `cleanup` 完成：预热的 `prepare` 与 `waiting` 期间持有同一份租约，`cleanup` 完成后释放。`cleanup(keep_warm=true)` 内部调用 `warm` 维持环境就绪并写 `warm_until`；保温期间不持有租约、不续租、不占 worker。`warm` 只负责保持环境就绪，不管理租约。

## 配置 schema

插件配置与脚本侧配置分开：插件配置由用户填写、平台保存；脚本侧配置由 `ConfigProjection` 负责同步。

| 规则 | 内容 |
|---|---|
| 格式 | JSON Schema Draft 2020-12，根为 object，`additionalProperties: false` |
| 注解 | 每个属性有 `title`；可填默认值的给 `default`；枚举字段用 `enum` |
| 密钥 | 标 `"writeOnly": true`；读取接口返回 `null`，不进日志、不进备份 |
| 校验 | 保存、加载、升级后各校验一次；失败返回 `E_CONFIG` |
| 表单 | 内核按类型、枚举、标题生成表单；界面不硬编码插件字段 |
| 迁移 | 新 schema 的 `default` 补齐缺失字段；已删除字段丢弃；类型变化或新增必填且无默认值时，配置标为无效，相关作业被拒到用户重填。跨 `x-schema-version` 的迁移由 manifest 的 `config_migrations` 指定处理函数，内核按 `from` 升序逐个调用 `handler` |
| 存储 | payload 原样保存为插件配置修订，每次保存写 `config_revisions`；插件只收到校验后的字典 |

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "$id": "plugin://notifier/config/1",
  "x-schema-version": 1,
  "type": "object",
  "additionalProperties": false,
  "required": ["channel", "endpoint"],
  "properties": {
    "channel": {"type": "string", "title": "渠道", "enum": ["serverchan", "ntfy"], "default": "serverchan"},
    "endpoint": {"type": "string", "title": "地址", "format": "uri"},
    "token": {"type": "string", "title": "令牌", "writeOnly": true}
  }
}
```

## 隔离

| 面 | 规则 |
|---|---|
| 执行 | 插件在 worker 子进程运行；内核与 worker 只交换 JSON 消息，不共享内存 |
| 超时 | 每次调用带 deadline；到期内核终止调用，按能力失败处理 |
| 取消 | 内核发送取消；未在宽限期内返回则终止 worker 并重启 |
| 存储 | 插件不得打开平台数据库；全部读写经 `RunContext` |
| 文件 | 只访问配置声明的路径；写入操作由内核记事件 |
| 网络 | 默认禁止；`Advisor` 经内核模型代理，`Notifier` 只访问配置中的渠道地址 |
| 密钥 | 经 `ctx.secrets` 按名读取；不落日志、不进事件载荷 |
| 崩溃 | worker 退出 → 当前 attempt 失败并记 `E_PLUGIN_CRASH`；连续 3 次重启失败标 `degraded` 并停止路由到该插件 |

隔离的目标是让插件故障只损失一个能力，不拖垮调度与其它插件。内核不信任插件返回的数据：类型、枚举、证据引用都要校验。

## 契约测试

每个能力一套测试，所有插件跑同一套；插件仓库附带入口，判据由内核维护。

| 能力 | 最低断言 |
|---|---|
| manifest | 字段、id 规则、`api_version` 落在 `requires.contract` 内、声明能力与实现一致、schema 可解析 |
| environment | `probe` 返回合法状态；`prepare` 可重复调用；`reset` 后回到 `booting`；`cleanup` 可重复 |
| script | `launch` 返回句柄；`observe` 只读且可重复；`stop` 可重复；`recover` 只执行声明动作 |
| verifier | 返回三态之一；`evidence_ids` 全部存在；同一证据与 policy 结果稳定 |
| config_projection | `diff` 对称；`apply` 后 `diff` 为空；`rollback` 恢复原值 |
| notifier | 渠道失败返回 `ok=false`，不抛异常 |
| advisor | 响应通过 schema；超时返回 `abstain` |

fake 插件覆盖内核需要的时间与故障形态：`fake-instant`、`fake-slow`、`fake-never-ready`、`fake-fail`、`fake-hang`、`fake-partial`、`fake-crash`。内核测试只用 fake，不依赖真实脚本；真实插件在接入前必须通过契约测试。

## 开发流程

1. 建 `plugins/<id>/`，写 `plugin.json` 与 `config.schema.json`。
2. 在 `plugin.py` 导出 `PLUGIN`，按声明实现能力；不在插件内做调度、队列与预算。
3. 用 fake 数据跑契约测试，覆盖成功、失败、超时、取消四条路径。
4. 接真实环境跑一次 `prepare → launch → observe → stop`，记录耗时与失败信号。
5. 把成功、失败、挂起三类样本放进 `tests/fixtures/`，作为回归输入。
6. 在 `plugins` 表注册，配置先置为 `disabled`，验证加载、表单与校验。
7. 打开一条低风险调度，连续观察 3 次运行，核对事件与证据。
8. 把实测耗时、已知故障与恢复动作写进插件文档。

交付判据：`python -m pytest tests/contract -q` 通过；真实环境一次闭环成功；失败样本能复现并留下证据。

## 错误

插件层使用 [03-数据模型与接口](03-数据模型与接口.md) 的错误码，具体场景优先用专码：manifest 校验失败用 `E_PLUGIN_MANIFEST`，契约版本不兼容用 `E_PLUGIN_VERSION`，worker 崩溃用 `E_PLUGIN_CRASH`，配置未通过 schema 用 `E_CONFIG`。基础码 `E_PLUGIN`、`E_CONFIG`、`E_SCRIPT` 只作兜底；事件的 `detail` 写明具体原因，完整错误码表由 03 维护。

## 边界

插件不修改游戏客户端，不注入、不绕过检测；不修改内核数据库，不直接打开 UI；不写配置声明之外的路径。插件失败只影响当前能力，不影响调度器、其它插件与已归档证据。
