# 13 · 变更与演进

[返回总览](00-总览与索引.md)

本文回答：一次改动凭什么算完成、什么时候写 ADR、接口与数据库怎么兼容演进、债与事故怎么收口。工程底线见 [10](10-工程宪法.md)，代码写法见 [11](11-代码规约.md)，门禁命令见 [12](12-测试与质量门禁.md)。

## 变更类型

| 类型 | 前置条件 | 需要 ADR | 门禁 |
|---|---|---|---|
| 修 bug | 先写失败用例，能复现才改 | 否 | 全部 |
| 小功能 | 对应 [01](01-需求与边界.md) 的 P-/M-/A-/E- 编号 | 否 | 全部 |
| 重构 | 行为不变，测试护航；跨模块时先列影响面 | 跨模块时 | 全部 |
| 契约变更 | manifest、能力、API、事件、错误码、表结构；附兼容方案与迁移 | 是 | 全部 + 兼容用例 |
| 结构变更 | 分包、进程模型、存储选型；影响面清单与分期方案 | 是 | 全部 |
| 紧急修复 | 先止血，后补证 | 否 | 24 小时内补齐 |

- 一次改动只做一件事；同一提交里混两类变更，评审按未完成处理。
- 契约变更先改 [05](05-插件与适配器.md) 与 [03](03-数据模型与接口.md)，再改代码。

## 完成定义

一项改动同时满足九条才算完成：

1. 可追溯：对应需求编号，或说明属于维护。
2. 有测试：新增或修改的行为有用例；修 bug 的用例先红后绿。
3. 门禁全过：[12](12-测试与质量门禁.md) 的七条命令全部通过。
4. 文档同步：按本文末的矩阵修改对应文档。
5. 证据可查：运行、判定、通知都能在事件与证据里找到。
6. 回滚明确：写清出问题时怎么退回上一个可用状态。
7. 无未登记绕行：所有绕行都进了 `DEBT.md` 并带到期日。
8. 兼容检查：API、插件 `api_version`、数据库迁移三处都核对过。
9. 评审清单逐条过，任何一条为否都有书面理由。

## 评审清单

- [ ] 依赖方向是否被违反（插件 import 内核、内核 import 具体插件、`contracts` import 内核或存储）。
- [ ] 内核是否知道了具体脚本：出现 MAA、明日方舟、`gui.new.json` 这类字段即违规。
- [ ] 是否出现第二个真源：同一配置在库、文件、插件侧各写一份。
- [ ] 状态机转移是否穷举，非法转移是否被拒绝且状态不变。
- [ ] 幂等键是否覆盖补跑、双击、崩溃恢复三条路径。
- [ ] 失败路径是否有明确处置，是否计入 policy 预算，是否可能无限重试。
- [ ] 是否打印或落库了 token、口令、截图内容、完整个人路径。
- [ ] 是否引入了无超时的外部调用或无限等待的锁。
- [ ] 新增配置项是否带类型、默认值、范围、说明，是否进了 schema。
- [ ] 结论是否带证据：每条 `Verdict` 能否追到 `Evidence`。
- [ ] 文档与代码是否一致；不一致时文档算错。
- [ ] 是否留下绕行而没有登记债务。

## 架构决策记录

满足任一条件即写 ADR，放在 `docs/adr/NNNN-标题.md`，编号四位递增，索引在 [00](00-总览与索引.md)：

1. 难回退：改动成本高，事后修正代价大。
2. 反直觉：后来的人一定会问「为什么这么做」。
3. 有取舍：存在真实替代方案，且选择有明确理由。
4. 触及内核与插件边界，或冻结点之后修改 `/api/v1`。

格式固定为：标题、状态、日期、背景、决策、后果、替代方案。状态取 `proposed`、`accepted`、`superseded`、`rejected`；被取代的 ADR 保留原文，只加一行指向新 ADR，不修改正文。ADR 与 CHANGELOG 是允许记述决策当时取舍的两个通道。

## API 与插件版本

| 对象 | 规则 |
|---|---|
| `/api/v1` 冻结 | [05](05-插件与适配器.md) 契约冻结（`api_version=1`），fake、MAA、MAAEnd 三个插件通过契约测试，[09](09-调度与作业语义.md) 场景用例通过后冻结 |
| 冻结后允许 | 新增端点、新增可选字段、新增事件类型；消费方必须忽略未知字段 |
| 必须开 v2 | 删除或重命名字段、改变字段语义、改变状态取值、改变鉴权方式 |
| 并行期 | v1 与 v2 同时提供至少一个发布周期；v1 标记弃用后保留 90 天 |
| 插件 `api_version` | 整数；内核维护支持的契约版本集合，manifest 的 `requires.contract` 必须覆盖内核版本，否则拒绝加载并返回 `E_PLUGIN_VERSION` |
| 能力演进 | 新增能力使 `api_version` 加一；已有能力语义变化用新能力名，不悄悄改语义 |
| 配置 schema | JSON Schema；加字段必须有默认值；删字段分两个版本（先标弃用，再移除） |

冻结点之前，`/api/v1` 是草案，允许破坏性调整并在提交说明中记录；MAAEnd 通过契约测试后才承诺兼容。

## 数据库迁移

- 文件 `storage/db/migrations/0001_<说明>.py`，编号四位递增；每个迁移含 up 与验证脚本，没有 down，回滚只走快照。
- 一个迁移一个事务；SQLite 迁移期间不并发写，执行前由核心进入 drain。
- 迁移前强制生成快照，命名 `pre-migrate-<version>-<时间>.sqlite`，见 [08](08-宿主与运维.md)。
- 结构变更走 expand/contract 三步：加列加表并兼容读写 → 停用旧列（仍保留） → 下一个大版本删除。
- 保证前一版本程序能读当前库：新增列必须有默认值或可空，删除列必须晚一个版本。
- 迁移里不调用插件、不访问网络、不读用户目录。
- 大表回填分批，每批 5000 行，批次之间可中断可续跑。
- 每个迁移在空库与「前一版本库」两份夹具上各跑一次，见 [12](12-测试与质量门禁.md)。

## 弃用

1. 标记：文档写明替代方案与移除版本；响应对弃用字段带 `Deprecation` 与 `Sunset` 头。
2. 告警：首次使用时记一条 `deprecation.used` 事件，同一对象只记一次。
3. 移除：到期版本删除字段、端点或能力，同时删掉文档里的条目。

期限不少于一个发布周期且不少于 30 天；每个弃用项在 `DEBT.md` 有对应条目与到期日。数据列按 expand/contract 走，不随接口同一天消失。

## 技术债

台账在 `DEBT.md`，字段与规则见该文件。记账触发条件：

- 绕过了门禁或评审清单。
- 行为没有测试，或测试只覆盖成功路径。
- 已知该重构但按计划后置。
- 保留兼容层、双写、旧字段。
- 用手工步骤代替本应自动化的运维动作。

每笔债必须有归还期限（日期或版本号）；写不出期限的不入账，当场决定要么现在做，要么不做。

## 事故复盘

真实事故写进 `docs/incidents/YYYY-MM-DD-简述.md`，24 小时内出初稿，7 天内定稿：

1. 时间线：发生了什么，几点几分，谁先发现。
2. 影响：哪些 JobRun、什么结论、用户看到什么、有没有误报。
3. 根因：直接原因与深层原因分开写；深层原因指缺失的检查、契约或规矩。
4. 处置与回归：止血处置、永久修复、回归用例文件路径。
5. 规矩更新：是否改宪法、门禁、评审清单或本文。

复盘对事不对人；必须产出至少一条回归用例；没有可补的用例时，写明为什么现有测试本应拦住而没拦住。

## 阶段体检

| 周期 | 做什么 | 产出 |
|---|---|---|
| 每月 | 债务盘点与逾期项、依赖方向抽查、覆盖率趋势、失败运行归类 | `DEBT.md` 更新、`TASKS.md` 条目 |
| 每季度 | 全量回归、性能基线复测、soak 72 小时、ADR 复审、文档与代码一致性抽查、保留策略与磁盘水位核对 | 体检记录进 `TASKS.md`，基线更新进 [12](12-测试与质量门禁.md) |
| 每次发版前 | 迁移在前一版本库上验证、备份可恢复、升级与回滚演练 | 发版清单勾选 |

体检发现的问题进 `TASKS.md`，不口头记；问题属于规矩缺失时按 [10](10-工程宪法.md) 提修订。

## 版本号

- 采用 `MAJOR.MINOR.PATCH`；冻结点之前 `/api/v1` 是草案，只承诺插件 `api_version` 与数据库迁移的兼容。
- 冻结点之后 `/api/v1` 的兼容承诺生效，破坏性变更走 v2。
- 每个版本在 `CHANGELOG.md` 有一条记录；CHANGELOG 是历史通道，不在本文重复。
