# 03 · 数据模型与接口

[返回总览](00-总览与索引.md)

## 这份文件回答什么

平台存哪些数据、字段是什么、HTTP API 与 SSE 长什么样、错误码与鉴权规则。

## 设计原则

- 主键使用 UUID 或 ULID；时间存 UTC；展示按用户时区。
- 状态字段用英文小写枚举；枚举变化属于接口变更。
- 插件配置以 JSON 存储，schema 由插件提供；内核不解释 payload。
- 事件 append-only；运行状态可由事件重建。
- 所有外部写操作带幂等键；所有修改带版本号或 ETag。
- 数据库迁移只前进；破坏性变更走 ADR。

## SSE 事件

| 事件 | 载荷 |
|---|---|
| run.created | run_id、template_id、schedule_id、scheduled_at、merged_scheduled_ats（被合并的其它发生点，UTC ISO8601，升序） |
| run.state.changed | run_id、from_state、to_state、reason |
| run.queued | run_id、priority |
| run.phase.started | run_id、phase、attempt |
| run.phase.finished | run_id、phase、status、duration_ms |
| run.signal | run_id、kind、payload |
| run.verdict | run_id、status、policy_id、reason、confidence、evidence_ids |
| run.finished | run_id、status、duration_ms |
| run.interrupted | run_id、reason |
| env.state.changed | environment_id、from_state、to_state、probe |
| resource.leased | resource_id、run_id、expires_at |
| resource.renewed | resource_id、run_id、expires_at |
| resource.released | resource_id、run_id、reason |
| recovery.started | run_id、action、attempt |
| recovery.finished | run_id、action、result |
| evidence | run_id、kind、path、sha256 |
| notify.sent | run_id、channel、result |
| notify.failed | run_id、channel、error、attempts |
| advisor.requested | run_id、purpose、budget |
| advisor.responded | run_id、purpose、status、confidence、duration_ms |
| advisor.rejected | run_id、purpose、reason |
| advisor.degraded | run_id、purpose、reason |
| advisor.budget_exhausted | run_id、scope、limit |
| advisor.disabled | run_id、purpose、reason |
| plugin.loaded | plugin_id、version |
| plugin.rejected | plugin_id、reason |
| config.applied | plugin_id、target、revision、result |
| config.rolled_back | plugin_id、target、from_revision、to_revision |
| deprecation.used | object、field、sunset |
| host.state | state、detail |
| host.event | event、detail |
| core.event | event、detail |
| heartbeat | ts，每 15 秒 |

事件 id 分两套：运行事件为 `r:<run_id>:<seq>`，全局事件为 `g:<global_seq>`。带 run_id 的事件写入 run_events，其余事件写入 events_global；全局序号由 events_global 表维护，服务端保留最近 1000 条。GET /runs/{id}/events 只推该运行的事件，GET /events 推全局事件与运行事件。

断线续传按客户端收到的最后一个事件 id 重连，只补缺失段；服务端补齐不了缺口时返回 reset 提示，客户端重拉 GET /api/v1/status 重建快照。host.* 与 core.* 属于全局事件，不绑定单个 run。

插件经 `ctx.emit` 只能写 `run.signal`，载荷必须含非空的 `kind` 与对象形态的 `payload`；其它事件由内核写。插件写内核生命周期事件或载荷不符时，本次调用按 `E_PLUGIN` 失败。

host.event 的 event 字段取值：

| 值 | 含义 |
|---|---|
| host.autologon_checked | 自动登录自检结果 |
| host.clock_skew | 墙钟漂移超阈值 |
| host.suspended | 休眠恢复，环境状态置 unknown |
| host.disk_low | 磁盘低于告警线 |
| host.disk_full_guard | 磁盘低于 2 GB，拒绝新建运行 |
| host.tailscale_down | Tailscale 未运行 |
| host.tasks_registered | 计划任务注册结果 |
| host.upgrade_failed | 升级失败并回滚 |
| host.watchdog_gave_up | 看门狗连续拉起失败，停止拉起 |

文档中的 `host.autologon_checked` 等写法是 `host.event` 的 event 字段简写；顶层 type 只有 `host.event`，不是独立事件类型。

core.event 的 event 字段取值：

| 值 | 含义 |
|---|---|
| core.second_instance | 第二个核心实例被拒绝 |
| core.port_conflict | 监听端口被占用 |
| core.lease_expired | 租约过期被回收 |
| core.config_migrated | 配置 schema 迁移完成 |

`core.second_instance` 等写法是 `core.event` 的 event 字段简写。

## 错误码

| 码 | 含义 | 触发条件 | 可重试 |
|---|---|---|---|
| E_BAD_REQUEST | 请求格式或参数错误 | 入参校验失败 | 否 |
| E_AUTH | 令牌缺失或不匹配 | 鉴权失败 | 否 |
| E_NOT_FOUND | 资源不存在 | 查询不到 id | 否 |
| E_CONFLICT | 版本冲突、幂等键冲突或非法状态迁移 | If-Match 过期、幂等键复用、状态机拒绝迁移 | 否 |
| E_BUSY | 资源被占用 | 队列或租约暂不可用 | 是 |
| E_PLUGIN | 插件加载或调用失败，兜底码 | 未细分到具体场景的插件异常 | 是 |
| E_PLUGIN_VERSION | 插件 api_version 不兼容 | requires.contract 不覆盖内核 | 否 |
| E_PLUGIN_MANIFEST | manifest 缺字段或字面规则不通过 | 加载校验失败 | 否 |
| E_PLUGIN_CRASH | 插件进程崩溃 | worker 退出 | 是 |
| E_CONFIG | 配置校验失败，兜底码 | 保存或加载校验不通过，未细分到具体场景 | 否 |
| E_ENV_RESOLUTION | 分辨率、缩放或窗口布局不符合要求 | 环境预检失败 | 否 |
| E_ENV_DISCONNECTED | 环境连接中断 | 模拟器、adb、控制器断开 | 是 |
| E_ENV_UNREACHABLE | 环境通道不可达 | 重连后仍不可用 | 是 |
| E_ENV_WAKE_TIMEOUT | 唤醒或进入就绪状态超时 | probe 或 prepare 等待超上限 | 是 |
| E_CONFIG_LOCKED | 配置目标正被外部程序占用 | MAA 运行中写配置 | 是 |
| E_CONFIG_CONFLICT | 外部配置与期望值冲突 | projection 发现差异 | 否 |
| E_CONFIG_INVALID | 写入后读回校验不通过 | 读回不一致 | 是 |
| E_SCRIPT_TASK_FAILED | 脚本任务项失败 | 任务级错误信号 | 是 |
| E_SCRIPT_EXITED | 脚本意外退出 | 进程消失 | 是 |
| E_SCRIPT_RESOURCE_TIMEOUT | 脚本资源加载超时 | 启动等待超上限 | 是 |
| E_VERIFY_UNKNOWN_SCREEN | 画面无法归类 | 模板未覆盖 | 是 |
| E_VERIFY_NO_EVIDENCE | 证据缺失 | 证据未落盘 | 是 |
| E_ENV_NOT_READY | 环境未就绪时收到执行请求 | 执行前检查发现环境状态不是 ready | 是 |
| E_PREPARE_TIMEOUT | 准备阶段超时 | phase deadline 到期 | 是 |
| E_SCRIPT | 脚本启动或运行失败，兜底码 | 未细分到具体场景的脚本异常 | 是 |
| E_VERIFY_UNKNOWN | 证据不足或矛盾 | 验证器无法给结论 | 否 |
| E_RECOVERY_EXHAUSTED | 恢复预算耗尽 | attempt 上限 | 否 |
| E_DEADLINE | 超过截止时间 | scheduled_at + deadline | 否 |
| E_RESOURCE | 租约冲突或过期 | 资源不可用 | 是 |
| E_RESOURCE_LEASE_LOST | 租约过期或回收后未重新获取 | TTL 到期 | 是 |
| E_STORAGE | 数据库或文件写入失败 | 磁盘/权限/IO 错误 | 是 |
| E_DISK | 磁盘水位不足 | 低于 2 GB | 否 |
| E_NOTIFY | 通知渠道失败 | 渠道 4xx/5xx/超时 | 是 |
| E_INTERNAL | 未分类内部错误 | 未捕获异常 | 否 |

插件错误码使用 E_<DOMAIN>_<DETAIL>；域为 ENV、SCRIPT、CONFIG、VERIFY、PLUGIN。manifest 的 error_map 把码映射到类别、恢复动作与用户可读原因；未映射的码按默认处置处理并附原始日志片段。

同一场景只用一个码，具体场景优先用带 DETAIL 的码：

| 场景 | 码 |
|---|---|
| manifest 缺字段或字面规则不通过 | E_PLUGIN_MANIFEST |
| worker 进程崩溃 | E_PLUGIN_CRASH |
| 环境连接中断 | E_ENV_DISCONNECTED |
| 唤醒或进入就绪超时 | E_ENV_WAKE_TIMEOUT |
| 脚本资源加载超时 | E_SCRIPT_RESOURCE_TIMEOUT |
| 配置目标被外部程序占用 | E_CONFIG_LOCKED |

基础码 E_PLUGIN、E_CONFIG、E_SCRIPT 只作兜底：能用上表场景码的用场景码，没有更细码的异常才用基础码。

## 错误处置

按类别给默认恢复动作；作业模板的 recovery_policy 覆盖默认值。

| 类别 | 归入本类的码 | 默认恢复动作 |
|---|---|---|
| environment | E_ENV_ 前缀、E_PREPARE_TIMEOUT | reset_environment |
| script | E_SCRIPT_ 前缀、E_PLUGIN_CRASH | restart_script |
| config | E_CONFIG、E_CONFIG_ 前缀、E_PLUGIN_VERSION | abort；policy 允许时先修复再重试 |
| verify | E_VERIFY_ 前缀 | abort；结论记 unknown 并通知 |
| resource | E_RESOURCE、E_RESOURCE_LEASE_LOST、E_BUSY | retry |
| system | E_INTERNAL、E_STORAGE、E_DISK | abort，停手并通知 |

错误码到类别的归属由 [05](05-插件与适配器.md) 的 error_map 与内核内置映射决定；未归类的码按 system 处置。通知失败（E_NOTIFY）走通知重试并记 notify.failed，不触发运行的恢复动作。恢复动作取值见 05 的 RecoveryAction，退避与升级顺序见 [09](09-调度与作业语义.md)。

HTTP 状态按错误码映射：

| HTTP 状态 | 错误码 |
|---|---|
| 400 | E_BAD_REQUEST、E_CONFIG |
| 401 | E_AUTH |
| 404 | E_NOT_FOUND |
| 409 | E_CONFLICT、E_PLUGIN_VERSION |
| 429 | E_BUSY |
| 507 | E_DISK |
| 500 | 其余错误码 |

## 鉴权与网络

- 服务默认只监听 127.0.0.1:8787；远程访问经 Tailscale 或其他私有网络。
- 认证：固定 Bearer token；token 存本地，不进日志。
- 不实现自建配对码、设备台账、Keystore 依赖。
- 跨域默认关闭；本机 WebView2 与同源页面直接访问。

## 版本与迁移

- API 版本在路径：/api/v1；破坏性变更升 /api/v2。
- 插件契约版本为整数 api_version；内核声明兼容范围。
- 数据库迁移只前进：文件 storage/db/migrations/NNNN_<说明>.py，含 up 与验证；没有 down，回滚走快照。
- 插件配置 schema 版本随插件版本变化；迁移由插件声明，内核执行。

## 保留与备份

| 数据 | 保留 | 清理方式 |
|---|---|---|
| 运行记录 | 30 天 | 每日 03:30 删除最旧终态运行 |
| 判定（verdict） | 90 天 | 独立清理；证据过期后保留结论 |
| 证据 | 30 天；总量超过 20 GB 时只保留 verdict 引用的证据 | 删除文件，保留 verdict 并标注 |
| 结构化日志 | 14 天，之后压缩为 .gz | jsonl 按天切分 |
| 全局事件 | 最近 1000 条 | 超出时删除最旧 |
| 数据库快照 | 14 份日备 + 8 份周备 | 最旧优先 |
| 配置备份 | 最近 20 份 | 最旧优先 |
| Advisor 调用记录 | 90 天 | 最旧优先 |

- 配置备份保留最近 20 份；外部目标写入前先备份。
- 每日 04:00 生成数据库快照与 settings/plugins 导出；每周日 04:30 增量镜像证据目录；迁移前强制生成 pre-migrate 快照。
- 导出：GET /api/v1/export 返回配置、模板、调度与运行摘要的 zip。
- 备份内容：SQLite、证据目录、平台配置；不包含 token 与密钥。
