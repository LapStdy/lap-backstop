# 03 · 数据模型与接口

[返回总览](00-总览与索引.md)

## 这份文件回答什么

平台存哪些数据、字段是什么、HTTP API 与 SSE 长什么样、错误码与鉴权规则。

## 设计原则

- 主键使用 UUID 或 ULID；时间存 UTC；展示按用户时区。
- 状态字段用英文小写枚举；枚举变化属于接口变更。
- 插件配置以 JSON 存储，schema 由插件提供；内核不解释 payload。
- 事件 append-only；运行状态可由事件重建。
- 所有外部写操作带幂等键；所有修改带版本号或 ETag。
- 数据库迁移只前进；破坏性变更走 ADR。

## HTTP API

### 总则

- 前缀 `/api/v1`；端点一览表中的路径都省略该前缀。
- 鉴权：每个请求都要带 `Authorization: Bearer <token>`（流式端点在开流前校验）；缺失或不匹配返回 401 与 E_AUTH，服务未配置 token 时拒绝一切请求。
- 请求与应答正文都是 JSON（`application/json; charset=utf-8`），字段名 snake_case；同名查询参数出现多次时取最后一个值。
- 请求体上限 1 000 000 字节，超限返回 400 与 E_BAD_REQUEST。
- 错误应答体固定为 `{"error": {"code": "<错误码>", "message": "<人话说明>"}}`，HTTP 状态按「错误处置」的映射表取值。唯一例外是证据文件已清理的 410 应答，见对应端点小节。
- 版本与条件请求：调度与模板的详情、新建、修改应答带 `ETag` 头，取值为应答内容 SHA-256 的前 16 位十六进制并带双引号；对应写操作的 `If-Match` 请求头填该值或 `*`，与当前版本不符返回 409 与 E_CONFLICT，头缺省视为不校验。
- 能力清单：`GET /health` 的 capabilities 是端点一览表路径首段去重加 `events`（流式端点）的字母序数组。
- 行结构：列表与详情应答的行即「数据表」对应字段表的 JSON 形态——0/1 整数列应答为 boolean，时间列应答为 RFC3339 文本，可空列应答为 null，JSON 列原样内嵌；端点小节另有说明的以小节为准。

### 流式端点（SSE）

两条 SSE 流不进端点一览表，也不走请求-响应形态；帧格式、事件载荷、续传与 reset 判定见「SSE 事件」一节。

| 方法 | 路径 | 流 |
|---|---|---|
| GET | /events | 全局事件流 |
| GET | /runs/{id}/events | 单运行事件流；未知运行在开流前返回 404 与 E_NOT_FOUND |

两条流都要求鉴权，失败返回 401 与 E_AUTH；`Last-Event-ID` 请求头可选，值不合事件 id 文法时开流前返回 400 与 E_BAD_REQUEST。开流应答为 200，响应头 `Content-Type: text/event-stream; charset=utf-8` 与 `Cache-Control: no-cache`，此后逐帧写出。

### 系统与设置

#### GET /health

服务存活与自身信息。无路径参数、查询参数与请求体。

响应 200：

| 字段 | 类型 | 说明 |
|---|---|---|
| status | string | 固定 `ok` |
| version | string | 发行包版本号；源码直跑为 `dev` |
| server_id | string | 服务实例标识，32 位十六进制；首次访问生成并写入 settings，进程重启后不变 |
| capabilities | string[] | 能力清单，字母序，口径见总则 |

错误：401 E_AUTH。

#### GET /status

当前运行、队列、环境状态与最近结论的快照。无路径参数、查询参数与请求体。

响应 200：

| 字段 | 类型 | 说明 |
|---|---|---|
| active_runs | 运行行[] | 全部非终态运行，按 created_at、id 升序 |
| queue | 运行行[] | state 为 queued 的运行，按出队顺序：priority 降序、scheduled_at 升序、created_at 升序 |
| environments | 环境行[] | 与 GET /environments 同一映射 |
| recent_verdicts | 结论摘要[] | 最近 10 条结论，created_at 降序、id 兜底 |

结论摘要是 verdicts 表的子集：id、run_id、status、confidence、reason、created_at。

错误：401 E_AUTH。

#### GET /settings

全部配置项。无路径参数、查询参数与请求体。

响应 200：`{"settings": {<配置键>: <值>}}`；值按落库 JSON 原样，类型由键决定。

错误：401 E_AUTH。

#### PUT /settings

整批写入配置项。无路径参数与查询参数。

请求体：JSON 对象，键为配置键、值为任意 JSON；逐键写入或覆盖，未提及的键保持不变。

响应 200：与 GET /settings 相同的全量，写后立即可见。

错误：401 E_AUTH；请求体缺失或不是 JSON 对象返回 400 E_BAD_REQUEST。

### 调度

#### GET /schedules

调度列表。无路径参数、查询参数与请求体。

响应 200：`{"schedules": <调度行>[]}`，按 created_at、id 升序；调度行即 schedules 表字段表的 JSON 形态。

错误：401 E_AUTH。

#### POST /schedules

新建调度。无路径参数与查询参数。

请求头：`Idempotency-Key` 可选；携带时调度 id 由键派生，同一键重复提交命中同一行返回 200 不再新建，无键每次新 id。

请求体：JSON 对象，字段如下；未知字段返回 400 E_BAD_REQUEST。

| 字段 | 类型 | 必填 | 约束 |
|---|---|---|---|
| name | string | 是 | 非空 |
| kind | string | 是 | cron / at / interval |
| job_template_id | string | 是 | 必须是已存在的模板 id，否则 400 E_BAD_REQUEST |
| expr | string 或 integer | 按 kind | kind 为 cron 时必填非空表达式；kind 为 interval 时是正整数分钟数，整数与数字文本都收，落库存数字文本 |
| at | string | 按 kind | kind 为 at 时必填，RFC3339 且必须带时区；kind 不是 at 时若给了非空值，同样按 RFC3339 校验后原样落库 |
| timezone | string | 否 | IANA 时区名 |
| catch_up | string | 否 | run_once / skip / window |
| window_minutes | integer | 否 | ≥ 0 |
| deadline_minutes | integer | 否 | ≥ 0，且不得小于 window_minutes，否则 400 E_CONFIG |
| preheat_minutes | integer | 否 | ≥ 0 |
| keep_warm_minutes | integer | 否 | ≥ 0 |
| coalesce | boolean | 否 | — |
| priority | integer | 否 | — |
| enabled | boolean | 否 | — |

可选字段缺省取 config/defaults.toml 的 [scheduler] 基线（enabled 缺省 true）。

响应：新建 201、幂等命中 200，`{"schedule": <调度行>}`，附 ETag。

错误：401 E_AUTH；400 E_BAD_REQUEST（缺必填、类型或取值非法、未知字段、模板不存在）；400 E_CONFIG（window_minutes 超过 deadline_minutes）。

#### GET /schedules/{id}

调度详情。路径参数 `id`；无查询参数与请求体。

响应 200：`{"schedule": <调度行>}`，附 ETag。

错误：401 E_AUTH；404 E_NOT_FOUND。

#### PUT /schedules/{id}

修改调度。路径参数 `id`；无查询参数。

请求头：`If-Match` 可选，口径见总则。

请求体：与 POST /schedules 同一字段集，全部可选；出现的字段覆盖当前值，未出现的保留当前值；未知字段返回 400 E_BAD_REQUEST。

响应 200：`{"schedule": <调度行>}`，附新 ETag。

错误：401 E_AUTH；400 E_BAD_REQUEST 或 400 E_CONFIG；404 E_NOT_FOUND；409 E_CONFLICT（If-Match 不符）。

#### DELETE /schedules/{id}

删除调度。路径参数 `id`；无查询参数与请求体。

响应 204：无响应体。

错误：401 E_AUTH；404 E_NOT_FOUND；409 E_CONFLICT（仍被运行记录引用）。

#### POST /schedules/{id}/run

立即跑一次。路径参数 `id`；无查询参数与请求体。

请求头：`Idempotency-Key` 必填，缺失或空白返回 400 E_BAD_REQUEST；同一键重复提交返回同一运行，登记作用域为 run_now。

响应：新建 201、幂等命中 200，`{"run": <运行行>}`。手动运行的行口径：schedule_id 为 null，idempotency_key 为 `manual:<键>`，scheduled_at 与 created_at 为当前时刻，priority 与 deadline_minutes 取自调度，detail 为 `{"trigger": "manual"}`；运行行即 job_runs 表字段表的 JSON 形态。

错误：401 E_AUTH；400 E_BAD_REQUEST（缺 Idempotency-Key）；404 E_NOT_FOUND（调度不存在，或调度引用的模板不存在）。

### 运行

#### GET /runs

运行列表。无路径参数与请求体；查询参数如下。

错误：401 E_AUTH；404 E_NOT_FOUND。

响应 200：`{"config": <新 payload>, "revision": <新修订号>}`，附新 `ETag`。

错误：401 E_AUTH；400 E_BAD_REQUEST；404 E_NOT_FOUND；409 E_CONFLICT。

## SSE 事件

| 事件 | 载荷 |
|---|---|
| run.created | run_id、template_id、schedule_id、scheduled_at、merged_scheduled_ats（被合并的其它发生点，UTC ISO8601，升序） |
| run.state.changed | run_id、from_state、to_state、reason |
| run.queued | run_id、priority |
| run.phase.started | run_id、phase、attempt |
| run.phase.finished | run_id、phase、status、duration_ms |
| run.signal | run_id、kind、payload |
| run.verdict | run_id、status、policy_id、reason、confidence、evidence_ids |
| run.finished | run_id、status、duration_ms |
| run.interrupted | run_id、reason（取 `user_cancel` 或 `shutdown`；`shutdown` 是停机收尾的保留值，不视为取消请求） |
| env.state.changed | environment_id、from_state、to_state、probe |
| resource.leased | resource_id、run_id、expires_at |
| resource.renewed | resource_id、run_id、expires_at |
| resource.released | resource_id、run_id、reason |
| recovery.started | run_id、action、attempt |
| recovery.finished | run_id、action、result |
| evidence | run_id、kind、path、sha256 |
| notify.sent | run_id、channel、result |
| notify.failed | run_id、channel、error、attempts |
| advisor.requested | run_id、purpose、budget |
| advisor.responded | run_id、purpose、status、confidence、duration_ms |
| advisor.rejected | run_id、purpose、reason |
| advisor.degraded | run_id、purpose、reason |
| advisor.budget_exhausted | run_id、scope、limit |
| advisor.disabled | run_id、purpose、reason |
| plugin.loaded | plugin_id、version |
| plugin.rejected | plugin_id、reason |
| config.applied | plugin_id、target、revision、result |
| config.rolled_back | plugin_id、target、from_revision、to_revision |
| deprecation.used | object、field、sunset |
| host.state | state、detail |
| host.event | event、detail |
| core.event | event、detail |
| heartbeat | ts，每 15 秒 |

事件 id 分两套：运行事件为 `r:<run_id>:<seq>`，全局事件为 `g:<global_seq>`。带 run_id 的事件写入 run_events，其余事件写入 events_global；全局序号由 events_global 表维护，服务端保留最近 1000 条。

两条 SSE 流共用帧编码、心跳与 reset 判定，差异只在数据来源与续传锚点：

| 流 | 端点 | 数据来源 | 推送的事件 id | Last-Event-ID 锚点 |
|---|---|---|---|---|
| 全局流 | GET /events | events_global 与 run_events 的并集 | `g:<seq>` 与 `r:<run_id>:<seq>` | g、r 均可；跨源按锚点时刻补两表 |
| 单运行流 | GET /runs/{id}/events | 该运行在 run_events 的行 | 仅 `r:<该运行 id>:<seq>` | 仅本运行的 r 锚点，按 seq 精确补 |

单运行流对未知运行返回 404（E_NOT_FOUND）；锚点不是本运行的事件——g 锚点、别的运行的 r 锚点、已不存在的序号——按无法续传处理，发 reset 后从当前尾部继续追新。

断线续传按客户端收到的最后一个事件 id 重连，只补缺失段；服务端补齐不了缺口时返回 reset 提示，客户端重拉 GET /api/v1/status 重建快照。同刻已交付的事件会重发，客户端按 id 去重吸收。host.* 与 core.* 属于全局事件，不绑定单个 run，单运行流不推。

插件经 `ctx.emit` 只能写 `run.signal`，载荷必须含非空的 `kind` 与对象形态的 `payload`；其它事件由内核写。插件写内核生命周期事件或载荷不符时，本次调用按 `E_PLUGIN` 失败。

host.event 的 event 字段取值：

| 值 | 含义 |
|---|---|
| host.autologon_checked | 自动登录自检结果 |
| host.clock_skew | 墙钟漂移超阈值 |
| host.suspended | 休眠恢复，环境状态置 unknown |
| host.disk_low | 磁盘低于告警线 |
| host.disk_full_guard | 磁盘低于 2 GB，拒绝新建运行 |
| host.disk_critical | 磁盘低于 500 MB，写事件后核心退出码 5 |
| host.tailscale_down | Tailscale 未运行，远程访问不可用 |
| host.tailscale_bind_failed | tailnet 地址绑定失败，仅保留已成功的监听地址 |
| host.tasks_registered | 计划任务注册结果 |
| host.upgrade_failed | 升级失败并回滚 |
| host.watchdog_gave_up | 看门狗连续拉起失败，停止拉起 |

文档中的 `host.autologon_checked` 等写法是 `host.event` 的 event 字段简写；顶层 type 只有 `host.event`，不是独立事件类型。

core.event 的 event 字段取值：

| 值 | 含义 |
|---|---|
| core.second_instance | 第二个核心实例被拒绝 |
| core.port_conflict | 监听端口被占用 |
| core.lease_expired | 租约过期被回收 |
| core.config_migrated | 配置 schema 迁移完成 |
| core.global_events_pruned | 全局事件保留清理完成，detail 含 deleted 与 retained |
| core.retention_pruned | 过期数据保留清理完成，detail 含 date、evidence_files_deleted、evidence_bytes_freed、evidence_bytes_after、run_events_deleted、run_phases_deleted、verdicts_deleted、runs_deleted、advisor_deleted、log_files_deleted |

`core.second_instance` 等写法是 `core.event` 的 event 字段简写。

| E_NOTIFY | 通知渠道失败 | 渠道 4xx/5xx/超时 | 是 |
| E_INTERNAL | 未分类内部错误 | 未捕获异常 | 否 |

插件错误码使用 E_<DOMAIN>_<DETAIL>；域为 ENV、SCRIPT、CONFIG、VERIFY、PLUGIN。manifest 的 error_map 把码映射到类别、恢复动作与用户可读原因；未映射的码按默认处置处理并附原始日志片段。

同一场景只用一个码，具体场景优先用带 DETAIL 的码：

| 场景 | 码 |
|---|---|
| manifest 缺字段或字面规则不通过 | E_PLUGIN_MANIFEST |
| worker 进程崩溃 | E_PLUGIN_CRASH |
| 环境连接中断 | E_ENV_DISCONNECTED |
| 唤醒或进入就绪超时 | E_ENV_WAKE_TIMEOUT |
| 脚本资源加载超时 | E_SCRIPT_RESOURCE_TIMEOUT |
| 配置目标被外部程序占用 | E_CONFIG_LOCKED |

基础码 E_PLUGIN、E_CONFIG、E_SCRIPT 只作兜底：能用上表场景码的用场景码，没有更细码的异常才用基础码。

## 错误处置

按类别给默认恢复动作；作业模板的 recovery_policy 覆盖默认值。

| 类别 | 归入本类的码 | 默认恢复动作 |
|---|---|---|
| environment | E_ENV_ 前缀、E_PREPARE_TIMEOUT | reset_environment |
| script | E_SCRIPT_ 前缀、E_PLUGIN_CRASH | restart_script |
| config | E_CONFIG、E_CONFIG_ 前缀、E_PLUGIN_VERSION | abort；policy 允许时先修复再重试 |
| verify | E_VERIFY_ 前缀 | abort；结论记 unknown 并通知 |
| resource | E_RESOURCE、E_RESOURCE_LEASE_LOST、E_BUSY | retry |
| system | E_INTERNAL、E_STORAGE、E_DISK | abort，停手并通知 |

错误码到类别的归属由 [05](05-插件与适配器.md) 的 error_map 与内核内置映射决定；未归类的码按 system 处置。通知失败（E_NOTIFY）走通知重试并记 notify.failed，不触发运行的恢复动作。恢复动作取值见 05 的 RecoveryAction，退避与升级顺序见 [09](09-调度与作业语义.md)。

HTTP 状态按错误码映射：

| HTTP 状态 | 错误码 |
|---|---|
| 400 | E_BAD_REQUEST、E_CONFIG |
| 401 | E_AUTH |
| 404 | E_NOT_FOUND |
| 409 | E_CONFLICT、E_PLUGIN_VERSION |
| 429 | E_BUSY |
| 507 | E_DISK |
| 500 | 其余错误码 |

## 鉴权与网络

- 服务默认只监听 `127.0.0.1:8787`，地址与端口由 `api.host` / `api.port` 配置；首次启动没有可用的 `api.token` 时，内核生成强随机 token 写入 settings（同 `server.id` 的幂等口径，已配置不覆盖），日志只记「已生成访问令牌」，token 值不进日志、不进事件。
- 认证：固定 Bearer token；token 存本地 settings，不回显、不进备份。
- 远程监听由设置键 `api.remote_enabled`（布尔，缺省 false）控制：为真时启动阶段读 `tailscale status --json`，`BackendState` 为 Running 才把 tailnet IPv4（100.64.0.0/10）追加进监听集（与主地址同端口）；非 Running 或不可查只监听回环，并写一次 `host.tailscale_down`（载荷 `{"event": "host.tailscale_down", "detail": <BackendState 或不可查原因>}`，同一进程生命周期只记一次）并走通知渠道。
- 监听集合只在启动时确定：开启远程、Tailscale 恢复 Running 或更换 tailnet 地址后，需重启内核生效。
- 回环监听成功而 tailnet 地址绑定失败时，写 `host.tailscale_bind_failed` 并继续只回环，不退出；全部地址都起不来按端口被占退 4（`core.port_conflict`）。
- 不监听公网网卡，不做端口映射；远程访问只经 tailnet 地址。
- 不实现自建配对码、设备台账、Keystore 依赖。
- 跨域默认关闭；本机 WebView2、手机浏览器与手机 App 都访问同一源，不需要跨域配置。

## 版本与迁移

- API 版本在路径：/api/v1；破坏性变更升 /api/v2。
- 插件契约版本为整数 api_version；内核声明兼容范围。
- 数据库迁移只前进：文件 storage/db/migrations/NNNN_<说明>.py，含 up 与验证；没有 down，回滚走快照。
- 插件配置 schema 版本随插件版本变化；迁移由插件声明，内核执行。

## 保留与备份

| 数据 | 保留期限与处理 |
|---|---|
| 全局事件 | 保留最近 1000 条；新一天的第一个 tick 清理一次，日期记在 settings 键 `maintenance.global_events_pruned_on` |
| 证据文件 | 终态运行的文件保留 30 天，证据根总量不超过 20 GB；超过 20 GB 时按 `evidence.created_at` 从旧到新继续删终态运行的文件，可能早于 30 天 |
| 证据索引 | `evidence` 行保留到 90 天随运行整棵删除；文件清理后下载按 410 返回可读说明 |
| 运行事件与阶段 | 终态运行保留 30 天 |
| 判定与运行行 | 终态运行保留 90 天；删除时先断开 `job_runs.verdict_id`，再按外键顺序删证据索引、判定、运行事件、阶段、幂等键、通知、租约与 advisor 行 |
| advisor_calls | 保留 90 天；所属运行整棵删除时一并清理 |
| 原始日志文件 | `core-YYYY-MM-DD[.N].jsonl` 按 UTC 日界保留 14 天 |
| 压缩日志文件 | `core-YYYY-MM-DD[.N].jsonl.gz` 按 UTC 日界保留 90 天 |
| 看门狗日志 | `watchdog.jsonl` 不清理 |
| 数据库快照 | 日备 14 份 + 周备 8 份，超出按最旧删除 |
| 配置导出 | 最近 20 份，超出按最旧删除 |

- 保留清理每天本地 03:30 执行一次（时区取 `scheduler.timezone`，缺省 `Asia/Shanghai`）：serve 循环在到点后的第一个 tick 执行，日期记在 settings 键 `maintenance.retention_pruned_on`；运行相关的删除只作用于终态运行，结果写全局事件 `core.retention_pruned`。清理失败只记日志、不写日期键，下个 tick 重试。
- 备份由 `lap-backstop backup` 执行：`VACUUM INTO` 生成快照、导出 `settings.json` 与 `plugins.json`、按份数修剪；迁移前强制生成 pre-migrate 快照。
- 备份内容：SQLite 快照与平台配置；不包含 token 与密钥，证据目录不在备份范围内。
- 导出：GET /api/v1/export 返回配置、模板、调度与运行摘要的 zip。
- 保留期目标见 [01](01-需求与边界.md) 的 P-505 与 N-106。
