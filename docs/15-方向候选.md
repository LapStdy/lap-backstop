# 15 · 方向候选

[返回总览](00-总览与索引.md)

## 这份文件是什么

记录用户提出过、但没有方案与排期的功能方向。条目出现在这里表示「已提出」，不表示承诺实现；一条方向进入 [TASKS](../TASKS.md) 才表示排入在途任务。每条只写四件事：方向是什么、可能的价值、依赖什么、什么条件下值得展开评估。

## 候选方向

### 方舟事件提醒

- 是什么：把卡池活动开启与结束、版本更新等节点，经已配置的通知渠道推送。
- 可能的价值：活动与版本节点不靠人翻游戏公告，直接到达手机。
- 依赖：事件来源与判据（游戏内公告、官方公告页、活动时间表）；提醒节点（开启前预提醒、结束前多久）；消息正文与静默期。投递复用 `core/notify` 与 `E_NOTIFY` 口径，不另起通道。
- 评估入口：事件来源能稳定取得后再展开；否则只剩渠道参数可用，价值有限。

### 更多通知渠道

- 是什么：在 serverchan、dingtalk、ntfy 之外增加通知渠道实现。
- 可能的价值：按使用场景选渠道，避开单渠道限流或不可达。
- 依赖：渠道清单与优先级、各渠道凭据形态与限流口径。实现走 `Notifier` 能力，挂进 `core/notify/config.py` 的 `CHANNELS` 注册表，投递与重试逻辑不动。
- 评估入口：现有三渠道出现实际使用反馈（投递失败、限流、不可达）后展开。

## 写法约束

- 一条方向一行标题，下面四行：是什么 / 可能的价值 / 依赖 / 评估入口。
- 只写方向，不写实现步骤；方案、判据与排期进 [01 需求](01-需求与边界.md)、[TASKS](../TASKS.md) 与对应设计文档。
- 方向实现后从本文件移除，实现过程进 [13-变更与演进](13-变更与演进.md)。
