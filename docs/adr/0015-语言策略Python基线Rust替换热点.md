# ADR 0015 · 语言策略：Python 为基线，Rust 只替换实测热点

- 状态：accepted
- 日期：2026-11-15

## 背景

平台以 Python 3.12+ 实现：`contracts/`、`core/`、`storage/`、`plugins/` 四包；内核零运行时依赖（只用标准库），视觉部分按需依赖 `opencv-python-headless` 与 `numpy`（`pyproject.toml` 的 `maa-vision` 可选组）。

规模与验证面：生产代码 22,465 行（core 15,578、plugins 3,534、storage 2,222、contracts 1,131），测试 26,109 行、1,663 条用例，七条门禁一轮约 9 分钟。

实测性能基线（见 [01-需求与边界](../01-需求与边界.md) 第 4 节）：全屏单模板匹配 100–190 毫秒、ROI 约 7 毫秒；MuMu 原生取帧 3–6 毫秒、adb 通道 236–822 毫秒；单帧预算 200 毫秒。非功能指标 N-102 为常驻内存 ≤300 MB、空闲 CPU ≤2%。

使用面是单机自用：一个内核、一份数据库、一台常开机器。对外分发是备选路线，当前不承诺分发与支持；打包形态只服务本机部署（见 [08-宿主与运维](../08-宿主与运维.md)）。

稳定性风险与语言无关：原生取帧卡死（[DEBT](../../DEBT.md) 的 D-024）来自 Windows 原生 IPC 的阻塞调用，进程内的任何语言都中断不了它；这类问题的处置通道是 worker 子进程与带超时的封装。

## 决策

1. **内核、插件、调度与存储继续 Python 3.12+**，不整体重写。
2. **Rust 只在「测量证明的单一热点」上接入**，形态二选一：独立子进程（跨进程接口，隔离最好）或 PyO3 扩展（Python 的原生扩展绑定，同进程、免数据拷贝）；对外端口契约不变。
3. **触发判据**（任一条成立才立项，不凭感觉）：
   - 单帧处理 P95 超过 200 毫秒预算，且三次独立真机实测复现；
   - 浸泡期因单一模块导致假死或超时，每周 ≥1 次且能定位到该模块；
   - 常驻内存超过 240 MB（N-102 上限的 80%）且归因到单一模块；
   - 单机并发环境数或运行数达到当前规模的 10 倍。
4. **替换前先取基准**：同一负载 ≥5 次采样，记录中位数与四分位距；替换后同口径对比，数据写进提交说明与 `DEBT.md` 的归还记录。
5. **替换顺序**：先在同语言内优化（算法、ROI、参数、缓存）；仍是热点才换子进程；同进程扩展是最后一步。
6. **分发不构成换语言的理由**：即使将来立项对外分发，运行时依赖也用打包解决（单文件可执行），数据根可配置已具备（`LAP_BACKSTOP_DATA_ROOT` 与 `--data-root`）。
7. **每次热点替换单独记账**：写清命中的触发判据与前后基准；不把整个模块顺带换语言。

## 理由

- 当前瓶颈不在算力：判定与门控的实测耗时在预算内；视觉准确性取决于真机帧、模板与阈值，真机迭代次数比单帧速度更决定成败。
- 成本不对称：整体重写要重建 22,465 行生产代码、26,109 行测试、1,663 条用例、七条门禁与契约测试体系；按当前节奏估算 2–3 个月，期间里程碑停摆。
- 生态风险集中在视觉：模板匹配依赖 OpenCV；Rust 侧要么绑定预编译 OpenCV（Windows 构建成本高），要么自建匹配实现（准确率与阈值要重新标定）。
- 分发诉求有更便宜的解法：若将来立项分发，「先装 Python」的痛点由打包成单文件可执行解决，不需要换语言。
- 语言无关的故障仍是主要风险：阻塞式原生调用与超时靠进程隔离与超时封装，两种语言同等需要。

## 后果

- 里程碑不被语言迁移打断；现有测试、门禁与契约测试资产继续有效。
- 对外分发不在当前范围：安装方式、升级方式、单实例、日志与数据目录、故障排查口径按本机部署书写（见 [08-宿主与运维](../08-宿主与运维.md)）；一旦立项，这些另立专项，语言选择不在其中。
- 视觉模块继续绑定 OpenCV；将来替换时优先「子进程持有 OpenCV」，而不是纯 Rust 重写匹配。
- 双工具链成本只在触发后出现；触发前不引入 Rust 依赖，门禁不增加构建步骤。
- 定位与范围以 [01-需求与边界](../01-需求与边界.md) 为准：单人自用，不做对外服务；ADR 不代改需求。

## 替代方案

| 方案 | 不采纳的原因 |
|---|---|
| 整体用 Rust 重写 | 生产与测试代码全部归零，估 2–3 个月，里程碑停摆；算力不是当前瓶颈 |
| 现在为内核引入 Rust 扩展 | 没有命中触发判据，等于为假设的瓶颈付双工具链成本 |
| Go / Node / C# 重写 | 视觉与 Windows 原生库生态不占优，重写成本与 Rust 同级或更高 |
| 永远只用 Python | 分发与浸泡一旦出现实测热点，缺少退出通道 |
| 用 C++ 写视觉扩展 | 与 OpenCV 同源，但内存安全与构建风险高于 Rust，收益不额外 |
