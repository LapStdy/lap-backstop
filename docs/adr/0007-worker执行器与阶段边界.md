# ADR 0007 · worker 执行器与阶段边界

- 状态：accepted
- 日期：2026-10-24

## 背景

插件代码会挂起、崩溃、超时返回；内核不能因此丢状态或停止服务。执行过程要能按阶段观察、按 attempt 留证、按策略恢复，同时保持「内核不导入插件实现」的分层约束。当前实现把插件调用放在处理进程内同步执行，未来要能换成子进程 RPC，而生命周期与调用方不改。

## 决策

1. `core/worker` 只放执行器与取消标记，不承担调度、队列、租约规则；这些由 supervisor 与各自的能力模块负责。
2. 一次 `JobRun` 拆成 prepare → execute → verify → cleanup 四个阶段，`WorkerExecutor.execute` 只做流程编排，阶段动作在独立方法里，共享状态收敛到 `RunScope`。
3. 插件异常不拖垮内核：执行器捕获后按 `E_PLUGIN_CRASH` 进入恢复；恢复、取消、清理、停脚本自身的异常降级为 WARN 日志，不覆盖已经确定的终态。
4. 超时与取消都在注入的 `Clock` 与阶段边界上判断：观察循环到截止时间返回无结论，调用方按 `E_DEADLINE` 收尾；取消标记由内核置位，执行器在观察边界停脚本，先 graceful 后 force。
5. 插件只按 `contracts/` 的 Protocol 调用；worker 不读写插件内部模块，也不把数据库连接交给插件。
6. 单进程实现是当前形态；换成子进程 RPC 时保留四个阶段、`RunScope` 字段与执行器方法签名，只替换调用通道。

## 后果

- 执行器可以注入虚拟时钟与 fake 插件，覆盖成功、失败、挂起、崩溃、取消各条路径。
- 内核进程不会被执行器的单个插件异常终止；失败原因以错误码与事件记录，而不是异常堆栈。
- 阶段边界是唯一的取消与超时检查点；插件内部的长阻塞由 worker 子进程隔离解决（[ADR 0010](0010-worker子进程与能力调用RPC.md)），执行器不假设能强杀同步调用。
- 每次 attempt 的阶段记录与证据独立，可回放。

## 替代方案

| 方案 | 不采纳的原因 |
|---|---|
| 内核直接 import 插件并调用 | 破坏分层，插件升级会连带坏内核；无法隔离崩溃。 |
| worker 立即独立成进程 | 需要 RPC、序列化与进程管理，当前单机规模收益不足；阶段契约已按可迁移设计。 |
| 每个阶段各自持有连接与上下文 | 参数表膨胀、状态分散，失败路径容易漏清理。 |
