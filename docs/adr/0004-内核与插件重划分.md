# ADR 0004 · 内核与插件重划分

- 状态：accepted
- 日期：2026-10-23

## 背景

平台要托管多个外部脚本与游戏。若内核内置某个脚本的配置对账、判定等级、任务/流程/步骤模型，插件就会被追着适配内核；第二个脚本进来时，通用性会被证明是表面的。

## 决策

内核只负责四类不变量：

1. 时间：调度、补跑、合并、优先级、截止时间、幂等；
2. 资源：环境、账号、GPU 的租约与排队；
3. 状态：环境状态机、JobRun 生命周期、崩溃恢复；
4. 契约：manifest、能力、配置 schema、事件、证据、版本。

内核拆成八个能力：Scheduler、Jobs、Environments、Resources、Plugins、Recovery、Events、API/Storage。

插件按能力实现：EnvironmentProvider、ScriptAdapter、Verifier、ConfigProjection、Notifier、Advisor。

以下内容属于插件，不进内核：

| 内容 | 归属 |
|---|---|
| MAA 配置读写、差异、回滚 | MAA 插件的 config_projection |
| 脚本/画面/双证据三等级 | MAA 插件的 VerificationPolicy |
| MAA 任务、流程、步骤 | MAA 插件的 config payload |
| 方舟/终末地的画面模板 | 对应环境插件 |
| 通知渠道 | notifier 插件 |
| AI 建议 | advisor 插件 |

## 后果

- 内核可以在没有真实脚本的情况下用 fake 插件测试。
- 新脚本只需实现能力并注册 manifest，不改内核。
- 插件不能直接写内核数据库；通过内核命令与事件落库。
- 配置 schema 由插件提供，界面表单由 schema 生成。

## 替代方案

| 方案 | 不采纳的原因 |
|---|---|
| 内核提供通用步骤 DSL | 会把平台变成工作流引擎；执行逻辑不是数据，塞进 DSL 后调试与迁移成本高。 |
| 内核内置 MAA 适配 | 第二个脚本必须适配 MAA 形状；平台退化为单一应用。 |
| 插件直接继承内核基类 | 插件依赖内核实现，升级内核时一起坏。 |
