# ADR 0014 · 主界面判定用主题无关锚点

- 状态：accepted
- 日期：2026-11-08

## 背景

明日方舟主界面可以更换主题。主题改变配色、字体与背景美术，部分主题带动态效果；干员立绘与背景也能更换，立绘带动态版本；左上角有每次活动的临时横幅。可点的功能入口（任务、终端、基建、仓库）文字与图标随主题变，而主界面顶部与左侧的一排固定件由基础界面层绘制。

平台需要两个能力：交给 MAA 之前的就绪门控，以及平台自身方舟导航的定位基元（例如从终端退出后确认已回到主界面）。两者都要求判定跨主题稳定，差别在容错方向：交接可以宽容，导航必须确认。

## 决策

1. **判定只使用主题无关的 chrome 锚点。** 设置齿轮、公告三角、日历、寻访凭证、主界面 ⟳ 圆按钮，各占一个固定位置框，不读任何文字。
2. **双通道打分。** 外观通道（模板匹配，`TM_CCOEFF_NORMED` ≥ 0.85 且偏移 ≤ 16 像素）记 2 分；位置通道（同位素位置检测，只看该位置有没有图标结构）记 1 分，只用于左上三个图标。五锚点满分 15。
3. **状态变体与角标抑制。** 每个锚点允许 1–2 个状态变体（例如日历带未读角标与不带角标两态）；匹配前把高饱和像素置为灰度 128，消除橙黄角标影响。
4. **两套参数。** 交接：总分 ≥ 8 且外观命中 ≥ 2，连续 2 帧；导航：总分 ≥ 10 且外观命中 ≥ 4，连续 3 帧。同一判定器，不同门槛与后续动作。
5. **导航用星型拓扑。** 所有页面切换以主界面为中转，因此只需可靠识别主界面一个页面，其它页面只判「不是主界面」，配合有界返回循环。
6. **逐主题模板集只作备用链末段。** 主判定失效时的顺序是结构几何兜底、主题归一化、停手通知；不把逐主题模板作为第一道判定。
7. **判定归属插件。** 主界面判定属于 MAA 插件 `prepare` 的契约，内核门控只做通用动作：进程、分辨率、画面稳定、已知覆盖层排除。

## 理由

- 锚点来自基础界面层，主题包只覆盖贴图与字体，这是主题无关的物理依据；实测五个主题下锚点位置偏移为 0 像素。
- 模板匹配在 5 个主题 22 帧主界面上最低总分 11，20 张非主界面帧总分全为 0，单帧 4–6 毫秒，判别力与成本都满足门控与导航循环。
- 位置通道让图标被主题重绘时仍有得分渠道，同时不单独参与判定，避免把「该位置有亮块」当成主界面。
- 状态变体与角标抑制把「未读角标」「重绘图标」这两类已知变化收进模板层，判定规则不随主题增加分支。

## 后果

- 新增主题不需要新增模板，只需要在验收时跑冻结样本回归；连续两次回归不通过才重新采集模板。
- 判定结果带锚点级证据（锚点名、得分、偏移、票数），`unknown` 可复盘。
- 导航循环依赖截图通道性能：adb 通道一轮「返回 + 验证」约 700 毫秒，原生通道约 200 毫秒。
- 位置通道阈值按主题划分拟合集与验证集，防止同批数据自证。
- 若某个主题重绘或移动整簇 chrome，判定进入备用链，按停手通知处理，不做猜测。

## 替代方案

| 方案 | 不采纳的原因 |
|---|---|
| 逐主题模板集 | 主题数量增长使每个入口都要维护一套模板；新主题出现即要采集与验收 |
| 运行时把主题切成固定主题再判定 | 改变用户可见的游戏设置；切换流程本身要处理主题列表、锁定与形近字 |
| 读取游戏内部状态 | `shared_prefs` 中没有主题键，主界面状态不落盘 |
| 无障碍树 | Unity 自绘，只能拿到 Android 容器节点 |
| 游戏日志事件 | 没有持续的界面状态事件，只有启动瞬间的栈输出 |
| 小范围文字 OCR 参与放行 | 正判已满、误判为零，OCR 只增加误放行风险；装饰字体下字迹最不可靠 |
| 只做位置通道（零模板） | 负样本在位置上能拿到 2 分，单独判定安全边际不足 |
