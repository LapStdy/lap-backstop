# ADR 0011 · 手机端改为同一页面的安装壳

[返回总览](../00-总览与索引.md)

- 状态：accepted
- 日期：2026-10-25
- 关联：[07-Android客户端](../07-Android客户端.md)、[06-图形界面](../06-图形界面.md)、[ADR 0002](0002-手机端采用Android原生客户端.md)（被本 ADR 取代）

## 背景

手机端的目标是：人不在电脑边（只带手机）时，电脑端能做的手机也能做——六个页面的读写全部可用，不因宽度分叉。

ADR 0002 选的是 Kotlin + Compose 原生三屏，并把完整编辑留在桌面。它与这个目标不兼容：对等只能靠第二套实现维持，每次契约与表单变化都要改两处，单人维护下必然漂移；观感与作品线移出一期目标后，原生实现失去主要理由。

约束不变：单人维护；业务真相与判定在电脑侧；手机只经局域网或私有组网访问；手机端要是可安装的 App。

## 决策

1. 手机 App 是同一份页面（见 [06](../06-图形界面.md)）的安装壳：Kotlin 单 Activity 承载 WebView，加载内核托管的页面。
2. 不内嵌前端构建产物：页面随内核升级，App 不随内核发版；只有壳改动才发版。
3. 壳只做四件事：地址引导页、WebView 承载、返回键、下载交给系统。页面、表单、证据查看、断线提示全部在页面里。
4. 能力与电脑端相同：六页全部读写；宽度只改布局密度，不隐藏字段、不禁用写操作。
5. token 由页面保存在 WebView 本地存储；壳不读不写、不落日志；撤销访问仍是更换 token。
6. 不做本地通知与前台服务：运行结束、停手、环境 failed 由服务端 Notifier 推外部通道（ntfy、Server酱）。
7. 分发仍是签名 APK + GitHub Releases，覆盖安装保留 WebView 数据，卸载清空。

## 后果

- 删掉第二套页面实现（Compose 三屏、原生表单、DataStore、OkHttp/SSE 客户端、CameraX 扫码）；对等由结构保证。
- 手机与桌面只有一份页面，字段与操作不会漂移；契约变化只改一处。
- 壳的维护面很小：一个 Activity、一个引导页、一份 WebView 配置；前端升级不用重新打包。
- 代价：WebView 版本随系统，老机型上玻璃与动效降级（观感不在本期目标）；token 存在 WebView 本地存储，强度低于 Keystore，卸载即失效；换主机地址后 token 需重新粘贴，因为存储按源隔离。
- 页面与内核同源，App 不再只是 API 客户端：安全边界由同源与 token 决定。
- 真机验收从「三屏功能」改成「壳能否完整承载页面 + 六页全写」。

## 替代方案

| 方案 | 不采纳的原因 |
|---|---|
| Trusted Web Activity | 要求 HTTPS 源与网站关联文件；内核在局域网内是 HTTP，不满足前置条件。 |
| Capacitor 内嵌构建产物 | 前端产物进 APK，页面升级要重新打包，一份页面变成两份副本。 |
| 保留 ADR 0002 的原生三屏 | 对等要靠第二套实现维持，单人维护下必然漂移；观感已移出一期目标。 |
| 纯 Web PWA、不装 App | 手机上没有可安装的 App，与「手机端要有 App」的要求冲突。 |
| 远程桌面 | 依赖电脑在线与桌面会话，手机不能独立做事。 |
