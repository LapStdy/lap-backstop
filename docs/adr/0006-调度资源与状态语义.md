# ADR 0006 · 调度、资源与状态语义

- 状态：accepted
- 日期：2026-10-23

## 背景

外部脚本有状态、启动慢、会失败；同一模拟器与账号不能并发；无人值守要求重启后不丢触发、不重复执行。调度、资源与状态必须一起设计。

## 决策

1. 调度持久化 next_run 到数据库，每秒扫描一次到期点；启动时计算错过点，按 catch_up 策略补跑。
2. 幂等键为 `<schedule_id>:<scheduled_at>`（UTC，截断到整秒）；job_runs 唯一约束；补跑、双击、崩溃恢复、重试复用同一运行；手动运行按请求头 Idempotency-Key 派生 `manual:<key>`，请求键与运行的对应关系单独存表。
3. 资源使用租约：先租后跑，TTL + 续租，过期回收；environment 类型容量固定为 1，同一环境同一时刻只允许一个租约与一个执行者。
4. 预热把 prepare 提前到 scheduled_at - preheat_minutes，预热期间持有租约；保温让环境在运行后保持 ready。保温期间不持有租约、不占用 worker、不续租；cleanup 释放租约后进入保温。
5. JobRun 增加 cleaning 状态：cleanup 完成并释放租约后才进入 succeeded/failed/unknown；cleanup 中取消等清理完成后记 cancelled。
6. 租约过期：核心回收并写事件；attempt 仍有预算则进入 recovering 并在最早 60 秒后重新申请，否则记 failed（E_RESOURCE_LEASE_LOST）。
7. 截止时间：scheduled_at + deadline_minutes；到点未进入 executing 记 failed（E_DEADLINE），不自动补跑。补跑窗口必须不大于截止时间，配置保存时校验。
8. 队列按 priority 降序、scheduled_at 升序、created_at 升序出队，不使用入队时间。
9. 失败进入 Recovery，attempt 在同一个 JobRun 内递增；恢复预算耗尽进入 failed。
10. 超时与退避使用单调时钟；数据库存 UTC。重启后单调时钟不跨进程，按持久化的 UTC 截止时间与下次尝试时间重建剩余量。

## 后果

- 慢机器上，冷启动被预热移出关键路径；保温窗口内的第二次运行免于冷启动。
- 重启、补跑、双击不会重复消耗理智或药。
- 资源冲突在排队层解决，不在插件里各自加锁。
- 状态可重建：事件日志是事实来源，数据库状态是快照。

## 替代方案

| 方案 | 不采纳的原因 |
|---|---|
| 每次运行新建 JobRun，不去重 | 补跑与崩溃恢复会重复执行，外部副作用不可逆。 |
| 插件自己加锁 | 锁语义分散，跨插件无法协调；租约必须在核心。 |
| 运行结束即关闭环境 | 慢机器每次冷启动；失败率与耗时都被放大。 |
| 用墙钟计算超时 | 系统时间漂移会改变超时与退避行为。 |
