# ADR 0001 · 分层与目录结构

- 状态：accepted
- 日期：2026-10-23

## 背景

平台要同时满足两件事：内核与具体脚本解耦；插件可以独立开发、测试、升级。目录结构与依赖方向必须先固定，否则插件会反向依赖内核实现，通用性会慢慢消失。

## 决策

采用六层结构：

~~~text
contracts/   接口、数据类型、错误码、manifest schema；不依赖业务实现
core/        调度、作业、环境、资源、恢复、事件、API、存储
plugins/     环境、脚本、验证、配置投影、通知、Advisor
web/         FastAPI 路由、静态资源、SSE
storage/     SQLite、迁移、证据文件
tests/       单元、契约、集成、场景、故障注入、端到端
scripts/     运维与开发脚本
~~~

依赖方向：

~~~text
web → core → storage → contracts
              ↑
plugins ──────┘（只依赖 contracts 与插件 SDK）
tests → 任意层（只读或 fake）
~~~

规则：

1. contracts/ 不导入 core/、plugins/、web/、storage/。
2. core/ 不导入 plugins/；插件通过注册表注入。
3. plugins/ 不导入 core/ 的内部模块；只能使用 contracts/ 与 sdk/。
4. web/ 不直接访问数据库与插件内部；只调用 core/ 的应用服务。
5. storage/ 不依赖 web/、plugins/。
6. tests/ 可以依赖所有层，但不得修改真实外部环境。

## 目录

~~~text
contracts/
  manifest.py       插件 manifest 与能力枚举
  manifest.schema.json  manifest 的 JSON Schema 本体
  context.py        RunContext 与 Clock
  environment.py    EnvironmentProvider 协议
  script.py         ScriptAdapter 协议
  verifier.py       Verifier / Verdict / CheckResult / Evidence / VerificationPolicy
  config_projection.py  ConfigProjection 协议
  notifier.py       Notifier 协议
  advisor.py        Advisor 协议
  errors.py         错误码与异常类型
  events.py         事件类型与载荷
core/
  scheduler/        调度与 next_run
  jobs/             作业状态机、队列、attempt
  environments/     环境状态机、预热、保温
  resources/        租约与排队
  plugins/          manifest 校验、注册、能力路由
  recovery/         重试、退避、升级、停手
  events/           事件日志、证据、快照
  api/              HTTP/SSE、鉴权
storage/
  db/               SQLite、WAL、迁移
  evidence/         证据文件
plugins/
  fake/             内核测试用
  maa/              MAA 插件
  maaend/           MAAEnd 插件
  notifier/         钉钉、ServerChan、ntfy
  advisor/          AI 建议

  static/           构建产物

tests/

  check_artifacts.py
~~~

## 后果

- 插件无法触碰内核数据库；状态变更只能通过 contracts 的事件与命令。
- 内核可以在没有真实 MAA 的情况下用 fake 插件测试。
- 目录结构变化属于结构变更，需要 ADR。

## 替代方案

| 方案 | 不采纳的原因 |
|---|---|
| 按技术层分（models/services/api） | 平台的核心是生命周期与状态，不是 CRUD；按层分会让状态机散落。 |
| 插件直接继承内核基类 | 插件会依赖内核实现细节，升级内核时插件一起坏。 |
| 单包目录 | 无法用 import-linter 约束依赖方向。 |
