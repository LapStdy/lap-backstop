# ADR 0013 · HTTP 与 SSE 传输用标准库

[返回总览](../00-总览与索引.md)

- 状态：accepted
- 日期：2026-11-01
- 关联：[ADR 0001](0001-分层与目录结构.md)、[02-架构](../02-架构.md)、[03-数据模型与接口](../03-数据模型与接口.md)、[11-代码规约](../11-代码规约.md)

## 背景

本机服务只服务单用户，请求量小，打包件要小。ADR 0001 把 `web/` 定为 FastAPI 路由、静态资源与 SSE；仓库没有 FastAPI 依赖，`web/` 目录不存在，HTTP 与 SSE 在 `core/api` 用标准库落地：35 条路由、2 条事件流，每个请求一条线程、一条独立 SQLite 连接，鉴权、路由与传输分离。文档里的技术选型需要与实现一致，接口契约以 [03](../03-数据模型与接口.md) 为唯一真源。

## 决策

1. HTTP 与 SSE 传输用 Python 标准库 `http.server`：`ThreadingHTTPServer` 按请求起线程，处理器不依赖框架类型；不引入 Web 框架，不生成 OpenAPI。
2. 传输层在 `core/api`：`server.py` 只做字节与 HTTP 的往返，`app.py` 做鉴权与路由，端点按资源分模块；新增端点在同一张路由表登记。
3. `web/` 只放前端页面与静态产物（浏览器端代码），不承载 HTTP 路由与 SSE；产物由内核托管。
4. ADR 0001 中 `web/` 的「FastAPI 路由、SSE」两职并入 `core/api`；六层结构的其余部分不变。

## 后果

- 打包件不含 Web 框架与 ASGI 服务器，依赖面只剩标准库；依赖升级与供应链风险随之缩小。
- 传输可替换：换传输只改 `core/api/server.py`，鉴权、路由与端点不动。
- 代价：分页、内容协商、自动生成接口文档由手写承担；漏登记路由的端点返回 404，由端点表的测试拦住。

## 替代方案

| 方案 | 不采纳的原因 |
|---|---|
| FastAPI + uvicorn | 引入第三方依赖与 ASGI 服务器，打包与升级面变大；单用户本机场景下框架的校验与文档收益不抵依赖成本。 |
| Flask | WSGI 同步模型对 SSE 长连接不友好，同样引入第三方依赖。 |
