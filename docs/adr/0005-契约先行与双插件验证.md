# ADR 0005 · 契约先行与双插件验证

- 状态：accepted
- 日期：2026-10-23

## 背景

平台抽象是否成立，不能由文档证明。需要至少两个真实插件在同一套契约上跑通；否则接口会是第一个插件的投影。

## 决策

1. 契约的唯一真源是 docs/05（能力、类型与 manifest 语义）、docs/03（事件注册表与错误码）与 contracts/ 代码；02、09 只引用，不复制签名。冻结范围：manifest 必填字段、RunContext、六种能力签名、VerificationPolicy、事件类型注册表、错误码。
2. 先写内核骨架与 fake 插件；fake 覆盖瞬时/慢/永不就绪、成功/失败/挂起/部分完成。
3. MAA 插件作为第一条真实纵向切片；MAAEnd 插件作为第二条。
4. 契约 `api_version=1` 在 fake、MAA、MAAEnd 三者通过契约测试且 docs/09 场景用例通过后冻结；在此之前 `/api/v1` 是草案。
5. 文档分两类：契约文档（收敛后冻结）与实现文档（落地后回填）。

## 后果

- 内核开发可以脱离真实环境，用虚拟时钟与 fake 插件跑场景。
- 第二个插件会暴露第一个插件带来的隐性假设，修正发生在 API 冻结之前。
- 文档不再一次写全量实现细节；接口与契约先稳定。

## 替代方案

| 方案 | 不采纳的原因 |
|---|---|
| 先写全量设计文档再实现 | 抽象没有经过第二个插件验证，返工发生在最贵的时候。 |
| 只做一个插件就冻结 API | 接口会变成 MAA 的形状，MAAEnd 接入时被迫适配。 |
| 先做 UI 再做内核 | 界面会围绕不稳定的接口反复重写。 |
