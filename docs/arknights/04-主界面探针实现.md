# 04 · 主界面探针实现

[返回总览](../00-总览与索引.md) · [返回方舟日常](00-方舟日常.md)

本文件规定主界面判定器的归属、模块切分、帧来源、参数表、模板、冻结样本、证据与测试口径。判定规则与验收判据见 [03-主界面判定与导航](03-主界面判定与导航.md)，决策理由见 [ADR 0014](../adr/0014-主界面判定用主题无关锚点.md)。

## 归属

| 项 | 规定 |
|---|---|
| 代码位置 | `plugins/maa/vision/`，属 MAA 插件的内部模块 |
| 可见面 | 内核与 `contracts/` 不含页面概念；判定结果只经 prepare 的成功/失败、错误码与证据出现 |
| 输入 | 一帧 BGR 图像与时间戳；不点击、不按键、不启停程序 |
| 输出 | 页面状态（`HOME` / `OTHER`）、逐锚点明细、截图与判定证据 |
| 依赖 | `opencv-python-headless`、`numpy`，经可选 extra `maa-vision` 引入；缺依赖时判定器与帧端口抛 `RuntimeError` 并提示 `pip install -e .[maa-vision]`，不影响其他插件加载 |

## 帧端口

| 项 | 规定 |
|---|---|
| 方法 | `FrameSource.capture()`：截到一帧返回 `Frame`；超时、非零退出、字节不是 PNG 一律返回 `None`，不抛异常 |
| Frame 字段 | `image`（BGR `np.ndarray`，高×宽×3）、`width`、`height`、`captured_at`（UTC）、`sha256`（原始 PNG 字节的十六进制摘要）、`source`（`adb` / `native`）、`png`（原始 PNG 字节，证据落盘用原字节，保证登记哈希与 `sha256` 一致） |
| adb 实现 | `AdbFrameSource`：`adb -s 127.0.0.1:16384 exec-out screencap -p`，单次超时 30 秒；进程执行器可注入，测试注入假执行器不跑真 adb |
| 宿主通道 | `WindowsMachineHost.capture()`：整帧 PNG 字节，只读；失败返回 `None`，不抛异常 |
| 原生实现 | `MumuFrameSource`：调 `external_renderer_ipc.dll` 取 RGBA 帧，翻成自下而上→自上而下并转 BGR；门控默认走这条通道，`frame_source=adb` 时退回截帧命令；取帧有超时上限（默认 5000 毫秒，构造时可覆盖），DLL 卡死按截帧失败收口并照常断开连接，下一次取帧照常；超时事件经当次运行上下文的写入口记录；判定器按 `source` 记证据来源，逻辑不随通道变化 |
| 尺寸核对 | 帧端口只如实报宽高，不缩放也不判环境；宽高不是 1280×720 由门控接线映射 `E_ENV_RESOLUTION`，不缩放继续 |

## 模板

- 5 个锚点 6 张裁片：`gear.png`、`warning.png`、`calendar.png`、`calendar-clean.png`、`redeem.png`、`loop.png`。
- 裁片只取字形主体，不含角标数字与状态带；日历的干净变体按 53×29 紧裁（去掉 NEW 缎带所在的顶部 7 行）。该变体已由 `MuMu-20261115-1657-native`（2026-11-15 真机主界面帧，日历无角标）验证：外观得分 0.9995、偏移 `(0, 7)`，与缎带高度一致。
- 文件名 `<锚点>[-<变体>].png`，随插件放在 `plugins/maa/templates/`。

## 冻结样本

- 42 帧：主界面 22 帧（默认主题 12、节日 3、水墨 1、暗紫 3、红龙 3）；非主界面 20 帧（公告面板、仓库、活动页各 1，签到面板 3 帧含两个滚动位置，基建 3 帧含总览 1，登录与载入 11）。
- 每帧存锚点覆盖区裁片与 manifest：帧名、来源批次、主题标签、期望判定、每个覆盖区的裁片文件名与偏移，另记生成时的逐锚点判定明细供等价性回归比对。
- 裁片覆盖区由锚点表生成（5 个位置框各外扩 18 像素）；manifest 与判定器共用同一张表，新增读取区域时覆盖区同步变化。
- 回归时按锚点表把裁片贴回 1280×720 画布再判定；判定器读取的区域与裁片覆盖区逐像素一致，其余像素不参与判定。
- manifest 为 UTF-8 JSON；裁片单文件 ≤ 300 KB。

## 证据

| 证据 | kind | 内容 |
|---|---|---|
| 截帧 | `screenshot` | 本帧 PNG；`sha256` 与 `summary` 记页面状态与总分 |
| 判定明细 | `probe` | JSON：每锚点得分、偏移、外观与位置命中、通道、总分、门槛档、结论、耗时毫秒、帧哈希、帧来源通道（`adb` / `native`） |

- 交接用途判为 `OTHER` 时另写一条 `run.signal`，`kind=maa.gate.unknown`，载荷带总分、外观命中数与帧哈希。
- 证据路径相对证据根目录，id 由 `RunContext.record_evidence` 分配。

## 测试与门禁

| 层 | 内容 |
|---|---|
| 单元 | 总分边界（7、8、9）、外观命中 1 与 2 的分界、偏移 16 与 17 像素的分界、角标抑制前后命中变化、状态机连续 1/2/3 帧、两档门槛切换、帧端口成功与失败语义、原生取帧超时收口与恢复、adb 命令与超时参数 |
| 冻结回归 | 42 帧按期望判定：主界面全部 `HOME` 且最低总分 ≥ 8；非主界面全部 `OTHER` 且最高总分 ≤ 2 |
| 合成 | 模板贴到黑画布成满帧；逐锚点移除覆盖门槛两侧；高饱和小块贴在锚点上验证抑制 |
| 等价性 | 每个冻结帧的重建画布与整帧在判定器读取矩形内逐像素相同（容差 0） |

- 冻结回归与合成用例都在 `pytest` 内跑，不依赖真机与模拟器。
- 单帧判定 ≤ 20 毫秒；42 帧回归总时长 < 5 秒。

## 错误映射

| 情形 | 结果 |
|---|---|
| 截帧失败或字节不是 PNG | `E_ENV_UNREACHABLE`，detail 记帧来源与失败原因 |
| 分辨率不是 1280×720 | `E_ENV_RESOLUTION`，不缩放 |
| 交接用途连续 2 帧未达门槛 | prepare 失败 `E_ENV_NOT_READY`，写 `run.signal`（`maa.gate.unknown`）与证据 |

## 边界

判定器只做「这一帧是不是主界面」：不点入口、不发返回键、不切换主题、不写游戏与 MAA 配置。覆盖层识别与原生截图实现由对应模块承担；导航控制器的返回循环在 `vision/navigation.py`。
