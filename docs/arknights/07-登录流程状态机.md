# 07 · 登录流程状态机

[返回总览](../00-总览与索引.md)

本文回答：平台怎样把「游戏启动 → 主界面」做成可测的状态机，让 prepare 门控不再停在启动页；覆盖层在流程内处置，识别不了就停手。

## 状态与转移

| 状态 | 识别依据 | 动作 | 超时 |
|---|---|---|---|
| `LAUNCH` | 游戏进程在前台（probe 已判） | 等待准备画面出现 | 180 秒 → `FAILED` |
| `READY_SCREEN` | 准备画面（`START` 按钮模板或位置命中） | 点一次 `START` | 60 秒 → `FAILED` |
| `LOGIN_SCREEN` | 登录界面（`开始唤醒` 按钮模板，且按钮非灰态） | 点 `开始唤醒` | 60 秒 → `FAILED` |
| `AGREEMENT` | 协议更新弹窗（「协议更新」标题 + 三项协议 + 「下一步」或「阅读并同意」） | 停手，`E_ENV_NOT_READY` | — |
| `CONNECTING` | 连接中（服务器名 + 进度百分比 + 底部「取得神经连接」） | 等待 | 30 秒 → `FAILED` |
| `LOADING` | 加载屏（黑色正三角）或主界面加载条（「在提交」「至神经」） | 等待 | 120 秒 → `FAILED` |
| `OVERLAY` | 覆盖层类型（见下表） | 按类型处置 | 每类 60 秒 → `FAILED` |
| `HOME` | 主界面判定（导航档连续 2 帧） | 完成 | - |
| `FAILED` | 截帧失败、超时、未知画面 | 停手，`E_ENV_NOT_READY` | - |

- `LAUNCH` 的 180 秒来自实测：冷启动黑底图标 82 秒、闪屏与黑屏 27 秒，从游戏进程起来到准备画面 109 秒。
- 准备画面是 8 页随机轮播、`START` 跨页位置不变，所以 60 秒内必然出现可点帧；一轮轮播不改变判定。
- 登录界面「开始唤醒」呈灰态表示账号已被登出，点它不会推进；按未知画面停手并通知，平台不代填账号与密码。
- 协议更新是硬阻断：勾选同意属于用户的法律行为，平台不代办；识别到即停手。
- 全程截不到帧立即 `FAILED`（帧源失败优先于超时）。
- 同一状态内重复动作有上限：`START` 与 `开始唤醒` 各只点一次；覆盖层处置按类型计次数。
- 状态只前进不后退；回退到更早状态视为未知画面，按 `FAILED` 收口。

## 覆盖层类型与处置

| 类型 | 识别依据 | 处置 |
|---|---|---|
| 每日签到覆盖层 | 月历面板标题区的日历图标（锚点模板，两套面板 0.986–1.0） | 点面板关闭回主界面；领取在打开面板时自动完成 |
| 限时活动覆盖层 | 首页左上签到卡（`签到` 文字或卡片模板） | 点卡进入，领取后关闭 |
| 公告覆盖层 | 三种关闭按钮 ROI（见 [06](06-登录与覆盖层素材.md) 的 MAA 对照表） | 点关闭 |
| 回归专属覆盖层 | `WELCOME BACK TO RHODES ISLAND` 字样、「14 天累计签到」面板、「欢迎回到罗德岛」横幅 | 记录证据，不处置；主界面已达成 |
| 协议更新覆盖层 | 「协议更新」标题 + 三项协议清单 + 「下一步」或「阅读并同意」 | 停手，`E_ENV_NOT_READY` |
| 通行证登录面板 | 手机号输入框 + 验证码/密码 + 「注册/登录」 | 停手，`E_ENV_NOT_READY` |
| 掉线覆盖层 | 掉线确认框模板 | 开始唤醒阶段点重连；其余阶段停手 |
| 维护、更新覆盖层 | 模板或 OCR 文案 | 停手并通知 |
| 退出确认覆盖层 | 确认框模板 | 点取消 |
| 未知覆盖层 | 无法归类 | 停手 `E_ENV_NOT_READY` |

## 实现覆盖

判读来源目前只认每日签到：`LoginVision` 用签到锚点模板判 `OVERLAY`，先于主界面判定——覆盖层盖住主界面时主界面锚点全部落空，不先认覆盖层就会把它当未知画面等到超时。处置只点面板关闭，不代做领取。

真机验收（2026-11-15，adb 通道）：准备画面点 `START`、登录界面点「开始唤醒」、加载屏、主界面，共 161.7 秒到家；随后点开签到面板判 `OVERLAY`（0.987），点关闭后回主界面。

公告与限时活动在 `_handle_overlay` 里有处置分支，判读来源还没有对应模板，真机上不会命中。回归专属、协议更新、通行证登录一律停手并写证据。停手不等于失败：证据里带最后状态、判读结果与帧哈希，由恢复策略决定重试或通知。

`LAUNCH` 的超时上限在实现中是 90 秒，本表的目标值是 180 秒。

## 端口

| 端口 | 契约 | 实现来源 |
|---|---|---|
| `FrameSource` | 截一帧，失败返回 `None` | `vision/frames.py`、`vision/mumu_frames.py` |
| `LoginJudge` | 一帧 → 登录阶段判读：`START` / `LOGIN` / `CONNECTING` / `LOADING` / `HOME` / `OVERLAY`（带类型） / `UNKNOWN` | 模板匹配，模板来自真机帧 |
| `Clicker` | 点一次安全坐标，越界拒绝并报错 | 模拟器宿主 |
| `Clock` / `Wait` | 单调时钟与等待，测试注入零等待 | `RunContext.clock` |

## 证据与事件

- 每个状态转移记一条证据：状态、判读、动作、坐标、是否成功、耗时。
- `FAILED` 时写 `run.signal`（`maa.login.unknown`），载荷带最后状态、判读与帧哈希。
- 判读置信度不足时写证据但不点，按未知覆盖层停手。

## 与 MAA 的边界

MAA 的任务链见 [06](06-登录与覆盖层素材.md) 的「MAA 同类流程参考」。本模块只做平台自己的登录流程，不复用 MAA 的模板、识别结果与执行逻辑；借用的部分是它已验证的判据语义：

- 判据多通道：模板失败转 OCR，OCR 失败转 ROI 点击位置，任一命中即推进。
- 重试与先后语义：同一动作有次数上限，命中加载条后固定等待，顺序不可交换。
- ROI 与阈值只作对照：MAA 的 ROI 在其分辨率与版式下成立，本机逐条在真机帧上核对后才写入模板。

执行仍由本模块的状态机负责，理由是平台要出帧级证据：哪一帧判成什么、点了哪个坐标、耗时多少。MAA 的执行是黑盒，失败只回报任务失败，MAAEnd 与其它脚本也用不上它。

## 测试

合成帧驱动，不依赖真机与模拟器：

| 场景 | 断言 |
|---|---|
| 正常链路 | `LAUNCH → READY_SCREEN → LOGIN_SCREEN → CONNECTING → LOADING → HOME`，每步动作与坐标正确 |
| 准备画面跨页 | 8 页轮播任取一页，`START` 均命中，只点一次 |
| 每日签到覆盖层 | 识别为 `OVERLAY`（每日签到），点面板关闭后回 `HOME` |
| 覆盖层优先 | 画面同时有 `START` 与签到锚点时判 `OVERLAY`，不点 `START` |
| 限时活动覆盖层 | 识别为 `OVERLAY`（限时活动），处置后回 `HOME` |
| 公告覆盖层 | 识别为 `OVERLAY`（公告），点关闭后回 `HOME` |
| 回归专属覆盖层 | 记录证据，不点任何坐标，`HOME` 判定照常成立 |
| 协议更新弹窗 | 停手，`E_ENV_NOT_READY`，不点勾选框 |
| 登录界面灰态 | 不点 `开始唤醒`，停手 `E_ENV_NOT_READY` |
| 未知覆盖层 | 停手，`E_ENV_NOT_READY`，不点 |
| 超时 | 各状态超时按表收口 `FAILED` |
| 截帧失败 | 立即 `FAILED`，不重试循环 |
