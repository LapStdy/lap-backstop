# 01 · 识别与动作

[返回总览](../00-总览与索引.md) · [返回方舟日常](00-方舟日常.md)

本文件回答：平台看什么画面、用什么通道截图、怎么匹配、什么时候允许点、哪些动作永远不点，以及与 MAA 内部识别的边界。

## 分工边界

- MAA 负责 `execute` 内部的游戏识别与操作：任务队列、战斗、基建、公招、信用、奖励。
- 平台只在 `prepare` 与 `verify` 读写画面：登录门控、主界面门控、卡住判定、结束画面核对。
- `execute` 期间平台只截图、只读日志，不向游戏注入点击或滑动；同一时刻只有一个输入者。
- 平台不读取、不复用 MAA 的模板与识别结果；两套模板各自维护。
- 六个判断点：

| 判断点 | 期望 | 动作 |
|---|---|---|
| 模拟器就绪 | 进程、窗口、adb、游戏进程 | 无 |
| 登录界面 | 登录模板命中并稳定 | 点固定安全坐标的登录按钮 |
| 主界面 | 任一主界面主题模板命中并稳定 | 无，交给 MAA |
| 运行中卡住 | 连续抽帧无变化，日志无新行 | 交给恢复策略 |
| 结束状态 | 主界面模板命中，无异常画面 | 无，交给 Verifier |
| 弹窗与错误框 | 安全类模板命中 | 关闭，或停手 |

## 截图通道

| 通道 | 调用 | 实测耗时 | 用途 |
|---|---|---|---|
| adb | `adb -s 127.0.0.1:16384 exec-out screencap -p` | 约 600 毫秒/帧 | 默认证据通道、冷路径 |
| MuMu 原生 | `external_renderer_ipc.dll` 的 `nemu_capture_display` | 10 到 150 毫秒 | 实时抽帧与门控 |
| Windows 窗口 | `PrintWindow` 抓 MuMu 主窗口 | 约 14 毫秒 | 窗口未遮挡时的快速备选 |

```text
H:\MuMuPlayer\nx_device\15.0\shell\sdk\external_renderer_ipc.dll
```

DLL 导出 11 个函数：`nemu_connect`、`nemu_disconnect`、`nemu_get_display_id`、`nemu_capture_display`、`nemu_input_event_touch_down`、`nemu_input_event_touch_up`、`nemu_input_event_finger_touch_down`、`nemu_input_event_finger_touch_up`、`nemu_input_event_key_down`、`nemu_input_event_key_up`、`nemu_input_text`。

调用签名未公开；MAA 的 `MumuExtras` 已在使用，MAA 日志记录最快截图 7 毫秒。平台接入原生截图前必须用探针确认句柄、宽高与像素格式，未确认不走该通道。门控与抽帧优先原生，不可用时退到 adb；每条证据记录通道与耗时，截图存 WebP，原图不长期保留。

## adb 命令

```powershell
$adb = 'H:\MuMuPlayer\nx_main\adb.exe'; $addr = '127.0.0.1:16384'
& $adb connect $addr
& $adb -s $addr exec-out screencap -p > shot.png
& $adb -s $addr shell input tap 640 640
& $adb -s $addr shell input keyevent 4
```

- 每条命令都带 `-s 127.0.0.1:16384`，避免 `emulator-5554` 残留导致多设备错误。
- 坐标空间是模拟器的 1280×720，与窗口位置、Windows 显示缩放无关。
- 输入事件之间至少间隔 1 秒；同一坐标两次点击至少间隔 2 秒。

## 分辨率与缩放

- 模拟器固定 1280×720，Windows 显示缩放固定 100%。
- `prepare` 启动前校验；不一致时停手并返回 `E_ENV_RESOLUTION`，不自动改系统设置。
- 截图尺寸不是 1280×720 时按失败处理，不缩放后继续识别。

## ROI

先定 ROI 再匹配，不做全屏扫描。ROI 集中定义，单位是 1280×720 坐标。

| ROI | 范围 | 用途 | 实测 |
|---|---|---|---|
| 主界面 | `(700,530,930,720)` | 主界面模板、结束画面 | 单模板约 7 毫秒 |
| 登录区 | 登录模板命中框外扩 1.5 倍 | 登录按钮与登录界面 | 按帧计算 |
| 顶栏 | `y < 90` | 公告、签到、邮件入口 | 按帧计算 |
| 弹窗区 | 屏幕中心 60% 区域 | 错误框、公告、更新提示 | 按帧计算 |

- ROI 外命中一律忽略；ROI 内连续未命中时扩大一档复测一次，仍不命中记证据缺失。
- 单帧模板数上限 5 个；全屏单模板 100 到 190 毫秒，全屏五模板 775 毫秒，超出 200 毫秒/帧预算。门控只用 ROI 匹配。

## 模板

- 来源：目标界面 adb 截 1280×720 原图，裁主体；主体尺寸 40 到 80 像素。
- 命名：主界面多主题用 `main_<主题>.png`；其余按用途命名，如 `login_button.png`、`login_ver.png`、`ready_top.png`、`error_dialog.png`、`disconnect.png`、`maintenance.png`。
- 匹配：`cv2.matchTemplate` + `TM_CCOEFF_NORMED`，阈值 0.85；得分写入证据。
- 验收：新模板在至少 10 帧目标画面命中，在非目标画面（主界面、战斗、基建、公告）不误命中；记录最低得分与最高误命中得分。
- 主界面支持多套主题，任一命中即可；新增主题只加模板，不改判定代码。
- 游戏改版导致连续失配时停手，不猜坐标；重新采集模板后回归验收。

## 稳定帧

- 定义：间隔至少 300 毫秒的连续两帧，灰度哈希汉明距离 ≤ 2，或变化像素占比 ≤ 1%。
- 稳定帧是动作与结论的前置条件：画面在动时只记录，不点击、不下结论。
- 动作后 3 秒内画面无变化视为动作未生效；重试前重新取稳定帧。
- 最长等 3 秒仍不稳定时按卡住处理，交给恢复策略。
- 加载转圈、过场动画、弹窗淡入都属于不稳定帧，不用阈值边缘的得分做判断。

## 动作白名单

| 动作 | 允许场景 | 约束 |
|---|---|---|
| `tap` | 登录、确定、继续、关闭弹窗、页签、更新与下载 | 目标在安全区；坐标做钳制 |
| `swipe` | 列表翻页、页面切换 | 起点与终点都在安全区 |
| `keyevent 4` | 关闭对话、返回上一层 | 不在战斗中发送 |
| 无动作 | 识别、截图、等待 | 默认选择 |

禁止：清除缓存、资源修复、卸载、退出账号、注销、登出、购买、充值、支付、兑换、消耗源石、抽卡、删除。识别不确定时不点。

- 点击点固定取模板命中区域的中心；命中位置偏移超过 24 像素时拒绝点击。
- 坐标必须落在安全区内；越界直接拒绝并记事件。
- 先干跑：只识别、只打印坐标与得分，通过后才允许真实点击；连续失败 2 次即停，不进入盲点循环。

## 决策循环

```text
截图 → ROI 匹配 → 候选与得分 → 优先级 → 动作 → 等画面变化 → 记录证据
```

1. 每步声明期望画面，只认期望，其他命中先当干扰。
2. 优先级：安全类（错误框、掉线、维护）最高，其次是当前期望，再次是挡路弹窗，其余忽略。
3. 去抖：期望画面连续 2 帧命中才允许动作；动作后 3 秒内画面变化，否则重试。
4. 互斥：一帧只取一个最高优先级目标，其余写日志。
5. 中断：任何时刻命中安全类模板，立即中断当前步骤优先处理。

## 证据

每次动作或判断记录：截图（WebP 或内容哈希）、通道、ROI、模板名、得分、点击坐标、动作类型、动作后是否变化、时间戳。缺任一项记证据缺失，结论记 `unknown`，不补猜。

## 实测耗时

| 动作 | 耗时 |
|---|---|
| `adb connect` / adb 点击 / adb 返回键 | 32 / 55 / 50 毫秒 |
| adb 滑动 | 350 毫秒（含 300 毫秒动画） |
| adb 截图（1280×720 PNG） | 约 600 毫秒 |
| MuMu 原生截图 | 10 到 150 毫秒 |
| PrintWindow | 约 14 毫秒 |
| ROI 单模板匹配 | 约 7 毫秒 |
| 全屏单模板匹配 | 100 到 190 毫秒 |
| 全屏五模板单帧 | 775 毫秒 |

单帧预算 200 毫秒：门控与抽帧只做 ROI 匹配；需要多模板时拆到多帧，不在一帧里堆五个全屏匹配。

## 失败处置

| 情形 | 处置 |
|---|---|
| 截图连续 3 次失败 | 切换通道；仍失败返回 `E_ENV_UNREACHABLE` |
| 模板得分低于阈值 | 重新取稳定帧复测；连续 3 次低分记 `unknown`，不点击 |
| 坐标越界或偏移过大 | 拒绝动作，记事件，交人工或 Advisor |
| 3 秒无稳定帧 | 按卡住处理，交恢复策略 |
| 画面无法归类 | 记 `unknown`，交 Advisor 分诊，不点 |
