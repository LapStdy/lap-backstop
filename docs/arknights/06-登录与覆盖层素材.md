## 画面顺序

链路主干固定，中间有三处按账号状态与版本插队：账号被登出时插入通行证登录与协议更新，版本更新时插入游戏协议更新，长期未登录的账号在主界面之后插入回归流程。

启动器 → 黑底图标 → 鹰角网络 → STUDIO MONTAGNE → 明日方舟标题 → 黑屏 → 准备画面（8 页随机轮播，点一次 `START`）→ 转场 → 登录界面 → 连接中 → 加载屏 → 主界面 → 每日签到 → 限时活动 → 公告 → 主界面完整。

## 覆盖层的到达形态

每日签到与公告有两种到达方式，识别时两种都要认：

| 覆盖层 | 形态一 | 形态二 |
|---|---|---|
| 每日签到 | 加载屏结束后自动弹出月历 | 主界面「今日配给」入口点开月历，领取后回主界面 |
| 公告 | 主界面出现后自动弹出 | 由主界面公告入口点开 |

## 操作事实

- 准备画面是多页介绍轮播，页面自动切换、顺序随机；点一次 `START` 即进入登录界面，不需要连续点击。
- 登录界面正常流程只点「开始唤醒」；底部中央是「扫码登录」，点它会弹系统相机授权，不属于正常链路。
- 账号被登出时「开始唤醒」呈灰态，点它不会推进；须走「账号管理」的通行证登录。
- 协议更新（游戏层）不勾选同意、不点「下一步」时画面停在协议页，后续动作不会发生。
- 点「开始唤醒」后先连接、再进加载屏；主界面出现时底部「正在提交反馈至神经…」加载条仍在，覆盖层随后淡入，加载条消失后主界面才完整。
- 每日签到每日首次可领，当天再次进入不再弹出。
- 公告覆盖层由游戏外渲染，打开过程分三段：主界面背景、半模糊遮罩、公告版面。

## 剔除的画面

- 相机权限弹窗：系统「扫一扫」授权，是误点扫码登录的产物。
- 崩溃回桌面帧与 MuMu 启动器 splash：环境异常产物。
- 回归专属画面：`WELCOME BACK TO RHODES ISLAND` 动画、「14 天累计签到 / 回归任务 / 回归礼包」面板、「欢迎回到罗德岛」横幅、黑色物资包开箱、理智溢出状态。这些画面只在长期未登录的账号上出现。
- 一次性协议与通行证画面：协议更新（通行证层与游戏层）、通行证登录面板。只在账号被登出或版本更新时出现，不作稳定模板。
- 限时活动画面只作样例，不用于稳定模板：补给签到 11/22 03:59 结束、联合行动 12/19 03:59 结束。

## MAA 同类流程参考

MAA 的任务链（`D:\MAA-Test\resource\tasks\tasks.json`，安装副本只读）覆盖同一条启动链路，识别文案、ROI 与先后可直接对照；下列 ROI 都是 1280×720 坐标。

| 阶段 | MAA 任务 | 做法 |
|---|---|---|
| 闪屏「开始」 | `GameStart` | 点击 roi `[550,600,200,120]`，模板阈值 0.7 |
| 开始唤醒 | `StartToWakeUp` / `StartToWakeUpOCR` | 点 roi `[520,460,240,100]`；OCR「开始唤醒/登录/登/录」兜底 |
| 连接中 | `StartUpConnectingFlag` | 点 roi `[0,635,450,85]` |
| 加载三角 | `LoadingIcon` | roi `[480,210,320,280]` 的黑色正三角，循环等待 |
| 加载条 | `LoadingText` | OCR「在提交」「至神经」（对应「正在提交反馈至神经…」），命中后等 2 秒 |
| 主界面 | `StartUp` / `MainThemes` | 主界面模板反复确认，一直在主界面才算完成 |
| 公告 | `CloseAnnos`：`CloseAnno` / `CloseAnnoTexas` / `CloseAnnoSpecialAccess` | 三种关闭按钮 ROI：`[1100,0,180,200]`、`[1125,24,138,139]`、`[998,87,143,143]` |
| 每日签到 | `TodaysSupplies` | OCR「今日配给」，点 roi `[1000,1,270,340]` |
| 限时签到活动 | `SignInEvent` 链 | 首页左上签到卡（OCR「签到」、roi `[5,21,203,258]`）→ OCR「结束时间」确认弹窗 → 匹配 `LOGIN` 标签点未领卡 → OCR「获得物资」关闭 |
| 掉线 | `OfflineConfirm` | 开始唤醒中点击重连，其它任务直接停止 |

这些 ROI 是 MAA 在其分辨率下的坐标，本机同为 1280×720，但版式随版本与账号状态变化（活动版式、回归横幅都会挪动入口），只能作对照，逐条要在本机帧上核对。

与实测的差异：

- 每日签到在本机有两种到达形态：自动弹出，或从主界面「今日配给」入口点开；MAA 的 `TodaysSupplies` 只覆盖后者。
- 实测「加载条」在主界面出现后仍在；MAA 用 OCR 判它并等 2 秒。

## 用途与边界

- 用途：登录流程（就绪状态机）与覆盖层模板（每日签到、限时活动、公告、维护、更新、掉线、退出确认）的素材来源。
- 素材本身不入库为冻结样本；入册冻结基线走 `add_frozen_frame.py`，覆盖层模板必须来自真机帧。
- 回归专属画面与一次性协议画面只作链路证据，不进模板。
