# 12 · 测试与质量门禁

[返回总览](00-总览与索引.md)

本文回答：哪些行为必须有测试、测试放在哪一层、门禁跑哪几条命令、性能与覆盖率的线画在哪。需求编号见 [01](01-需求与边界.md)，代码写法见 [11](11-代码规约.md)，变更流程见 [13](13-变更与演进.md)。

## 测试分层

| 层级 | 测什么 | 依赖 | 速度 | 跑在哪 |
|---|---|---|---|---|
| 单元 | 状态机转移、调度计算、策略选择、错误映射 | 无 IO，虚拟时钟 | 毫秒 | 每次提交 |
| 契约 | 插件 manifest、能力 Protocol、API 请求响应、SSE 帧格式 | fake 插件 | 毫秒 | 每次提交 |
| 集成 | SQLite 仓储与迁移、配置校验、鉴权、幂等键 | 临时数据库 | 秒级 | 每次提交 |
| 场景 | 一条完整生命周期：调度→准备→执行→验证→清理→通知 | fake 环境与 fake 脚本 | 秒级 | 每次提交 |
| 故障注入 | 崩溃、挂起、断网、磁盘满、时钟跳变、取消 | 场景骨架加注错点 | 秒级 | 每次提交 |
| 端到端 | MuMu + MAA + 真机画面 | 真实宿主 | 分钟 | 手动或夜间 |
| soak | 连续多日运行的内存、句柄、库体积 | 真实宿主或长期运行的测试机 | 小时级 | 每季度与发版前 |

原则：能下沉到下一层的，绝不在上一层测；端到端只证明「拼起来能用」，不承担逻辑覆盖。

## 必须测

| 范围 | 需求 | 为什么必须 |
|---|---|---|
| 调度发生点、补跑、合并、幂等键 | P-100 | 重复执行会真的跑两遍脚本 |
| 环境状态机、probe/prepare/reset、预热与保温 | P-200、A-100 | 环境没就绪就执行，等于白跑 |
| JobRun 状态机、队列、attempt、取消 | P-300 | 卡在中间态会让后续全部排队 |
| 资源租约与排队 | P-200 | 两个运行抢同一账号或 GPU |
| manifest 校验、能力路由、版本拒绝 | P-400 | 不兼容插件混进来会静默错 |
| Verdict 合成与证据缺失 | P-500 | 结论错了，整条链路白跑 |
| 恢复策略：重试、退避、复位、停手、升级 | P-600 | 无人值守的成败在这里 |
| 通知路由、失败重发、远程鉴权 | P-700 | 出问题时人必须收得到 |
| 事件写入与回放、SSE | P-800 | 界面与复盘都依赖它 |
| MAA 插件的完成信号与配置投影 | M-100 | 首批插件的实际能力 |

## 单元测试

- 状态迁移用例由 [02](02-架构.md) 的迁移表生成（`tests/state_tables.py` 解析表格，测试只做断言）：每条合法边一条用例；每条非法边一条拒绝用例（断言状态不变、抛领域异常、写 `run.state.changed`）。环境与 JobRun 两张迁移表各生成一套。
- 调度用参数化表：`kind`、`expr`、时区、`catch_up`、`window_minutes`、`coalesce` 的组合各取代表点。
- 幂等键用例必须覆盖：同一 `scheduled_at` 重复建 run 只成功一次；同一 `Idempotency-Key` 提交两次只建 1 个 JobRun（`scope=run_now`），第二次返回同一 id。
- 错误码用例：每个码按 [03](03-数据模型与接口.md) 的错误处置表断言类别与默认恢复动作；未归类的码归 system。
- 虚拟时钟注入到所有时间逻辑；测试里不出现 `sleep`、不读系统时间；时段边界取三处：发生点前 1 秒、正好发生点、发生后 1 秒。

## 契约测试

每个插件跑同一套 capability 测试，不因为插件是自研的而例外。

| 检查 | 判据 |
|---|---|
| manifest | 必填字段齐全；`api_version` 为整数；`capabilities` 非空且取值在允许集合内 |
| 能力签名 | Protocol 的参数与返回类型一致；缺方法即拒绝加载 |
| 版本兼容 | `requires.contract` 不覆盖内核版本时返回 `E_PLUGIN_VERSION`，内核继续运行 |
| 隔离 | 插件进程拿不到数据库连接；崩溃只影响当次调用 |
| 超时与取消 | 超过配置超时被终止；取消后不留子进程 |
| 返回值 | `Verdict` 三态齐全；`Evidence` 带类型、来源、时间与校验和 |
| 幂等 | 同一调用重复执行不产生两次副作用 |

fake 插件矩阵（内核测试与契约测试共用）：

| fake | 行为 | 用于 |
|---|---|---|
| `fake-instant` | 环境瞬时就绪，脚本立即完成 | 绿灯路径、性能上限 |
| `fake-slow` | 就绪与执行各延迟 N 秒 | 预热、超时、取消 |
| `fake-never-ready` | 环境永不就绪 | 停手、升级通知、租约释放 |
| `fake-fail` | 脚本返回失败并带证据 | 重试、退避、attempt 递增 |
| `fake-hang` | 调用挂起不返回 | 超时、worker 回收 |
| `fake-partial` | 部分任务完成 | `unknown` 结论、双证据冲突 |
| `fake-crash` | 调用中进程退出 | 崩溃恢复、`E_PLUGIN_CRASH` |

## 集成测试

- 进程内闭环冒烟（`tests/integration/test_end_to_end_run.py`）：`run_serve` 装配 fake 插件，到点调度触发一次运行，运行结束前经真 HTTP 取回详情、verdict 与证据文件，并在事件流上收到 `run.finished`。它只证明各层拼起来能跑通，逻辑覆盖仍由单元、契约与场景各层承担。
- 每个迁移在空库与「前一版本库」两份夹具上各跑一次，断言迁移后 `PRAGMA integrity_check` 为 ok。
- 仓储测试用临时目录的真实 SQLite 文件（WAL 模式），不用内存库替代，避免漏掉文件与锁行为。
- API：鉴权缺失返回 401；`If-Match` 不匹配返回 409；`E_BAD_REQUEST`、`E_AUTH`、`E_NOT_FOUND`、`E_CONFLICT`、`E_PLUGIN_VERSION`、`E_BUSY`、`E_DISK` 各一条用例断言 HTTP 状态（映射见 [03](03-数据模型与接口.md)），其余码落到 500。
- 手动立即跑：不带 `Idempotency-Key` 返回 400 与 `E_BAD_REQUEST`；同一 key 提交两次只建 1 个 JobRun，第二次返回同一 `run_id`。
- SSE：连接后 1 秒内收到首帧心跳；运行事件 id 为 `r:<run_id>:<seq>`，全局事件 id 为 `g:<global_seq>`；断线重连按 `Last-Event-ID` 只补缺失段；服务端补不齐时客户端收到 reset 提示并重拉 `GET /api/v1/status`。

## 场景测试

场景测试跑一条完整生命周期，由三件东西拼成：虚拟时钟、fake 环境、fake 脚本。它不启动模拟器，也不读真实画面。

| 场景 | 给定 | 断言 |
|---|---|---|
| 正常一轮 | `preheat_minutes=10`、环境 `fake-slow` | 提前进入 prepare；`scheduled_at` 时环境已 `ready`；`executing` 准点开始 |
| 错过补跑 | 停止 3 小时后启动，`catch_up=run_once` | 只补最近一次发生点；幂等键命中不新建 |
| 窗口内补跑 | `window_minutes=60`，错过 30 分钟 | 补跑一次；超出窗口则放弃 |
| 合并 | 同时到点两个 schedule 抢同一资源 | 第二个排队，不并发执行 |
| 租约过期 | 持有者无心跳超过 TTL | 租约转 `expiring` 再 `released`；运行按 09 进入 `recovering` 或 `failed`，排队者获租 |
| 重试后成功 | 第一次脚本失败、第二次成功 | attempt 从 1 增到 2，最终 `succeeded`，事件链完整 |
| 停手 | 连续失败达到 policy 上限 | 状态 `failed`，发通知，环境按保温策略处置 |
| 取消 | 运行中取消 | 转 `cancelled`，worker 结束，租约释放，不留子进程 |
| 崩溃恢复 | 进程在 `executing` 时被杀 | 重启后按最后事件重建；无法续跑标 `unknown`，按 policy 决定重试或放弃 |
| 证据缺失 | 验证器返回空证据 | 结论 `unknown`，不写成 `completed` |

## 故障注入

| 注入点 | 手段 | 期望 |
|---|---|---|
| 插件进程崩溃 | 在调用中 `os._exit` | 标记 `E_PLUGIN_CRASH` 并写事件，按 policy 重试，内核不受影响 |
| 插件挂起 | fake 的 `hang` | 超时后终止 worker，状态可继续推进 |
| 数据库锁 | 另一连接持写锁 10 秒 | 请求等到 `busy_timeout` 后返回明确错误，不静默丢写 |
| 磁盘满 | 限制证据目录可用空间 | 拒绝新 run，事件入库，不产生半张截图 |
| 断电/重启 | 结束进程树后重启核心 | 无重复执行，无孤立租约，状态一致 |
| 时钟跳变 | 虚拟时钟前跳 1 小时 | 补跑按窗口判定，不连发多次 |
| 网络中断 | 断 Tailscale 与外部心跳 | 本地功能照常，通知排队重发，事件记录 |
| 环境就绪后崩溃 | 环境转 `ready` 后杀模拟器 | probe 发现 `failed`，不直接执行脚本 |
| 通知失败 | 通知端点返回 500 | 重试有限次后记失败，不阻塞运行收尾 |

## soak

- 连续运行 72 小时，期间至少 100 次 JobRun，覆盖成功、失败、取消、重试。
- 判据：进程常驻内存增长不超过 5%；句柄数不随运行次数线性增长；数据库体积增长与事件数成正比；无孤立租约、无卡在中间态的 run。
- soak 结束导出报告到 `tests/soak/reports/<日期>.md`，含内存、句柄、库体积、失败运行清单。

## 覆盖率

| 范围 | 门槛 | 说明 |
|---|---|---|
| `core/scheduler`、`core/jobs`、`core/environments`、`core/resources`、`core/recovery` | 90%（行与分支） | 状态机与策略是内核价值所在 |
| 插件契约 | 全能力 | 每个声明的能力至少有成功与失败各一条契约用例 |
| `storage` | 迁移 100% 语句，仓储 85% | 迁移漏一条就是数据事故 |
| `web` | 主要端点 80% | 鉴权、幂等、错误码必须覆盖 |
| 整体 | 80% | 低于此不进主干 |

- 门槛只升不降；降低需要 ADR 与人确认。
- 覆盖率由 `pytest --cov` 生成，CI 上传报告；新增代码行覆盖率不得低于对应范围门槛；断言实现细节或只断言调用次数的用例不算覆盖。

## 门禁

按顺序执行，任一失败即未完成：

```bash
ruff check .
ruff format --check .
mypy
pytest -q
lint-imports
python scripts/check_contracts.py
python scripts/check_artifacts.py .
```

`mypy` 无参数运行，检查范围由 `pyproject.toml` 的 `files` 配置给出。

| 检查 | 拦住什么 |
|---|---|
| ruff | 风格漂移、未使用变量、可疑写法 |
| mypy | 类型不一致、返回值漏判、`Any` 逃逸 |
| pytest | 行为回归、状态机非法转移 |
| import-linter | 跨层调用、循环依赖、插件越界 |
| check_contracts | docs 里重复定义契约：事件清单、错误码表、字段表、能力签名 |
| check_artifacts | 交付物里的过程文字与施工用语 |

- 七条命令合并在 `scripts/gate.py`，本地与 CI 共用一套口径；每条命令 600 秒超时，超时按失败处理。
- 本地用 pre-commit 钩子跑同一条命令；钩子失败不允许提交。
- 全部命令在仓库根执行，路径与工作目录无关。

## 端到端

- 端到端跑真实宿主：MuMu 12 + MAA 6.20.x + 明日方舟，分辨率 1280×720。
- 用标记 `@pytest.mark.e2e`，默认不选；命令 `pytest -m e2e`。
- 每次至少覆盖：环境冷启动到 `ready`、脚本一轮跑完、验证产出证据、收尾关闭或保温。
- 一次端到端的记录（时间、耗时、结论、截图路径）存 `tests/e2e/records/<日期>.md`，作为冻结证据。
- 端到端失败不自动重跑；重跑前先看日志，避免掩盖环境问题。

## 性能基线

| 指标 | 门槛 | 实测 |
|---|---|---|
| adb 截图（1280×720 PNG） | 700 ms 内 | 约 600 ms |
| MuMu 原生截图 | 200 ms 内 | 10 到 150 ms |
| ROI 内模板匹配 | 20 ms 内 | 约 7 ms |
| 全屏单模板匹配 | 200 ms 内，一帧只查一个模板 | 100 到 190 ms |
| adb 点击 | 100 ms 内 | 约 55 ms |
| adb connect | 200 ms 内 | 32 ms |
| MAA 启动到资源加载完成 | 120 s 内，超过记 warn；180 s 判失败 | 约 72 s |
| 环境冷启动到 `ready` | 180 s 内 | MuMu 冷启动约 55 s，就绪另计 |
| 调度触发偏移（p95） | 2 s 内 | — |
| `GET /api/v1/health` | 50 ms 内 | — |
| `GET /api/v1/status` | 100 ms 内 | — |

- 性能改动必须给出前后对比（同一机器、同一夹具、至少 5 次取中位数）。
- 基线只升不降；新增指标先测再写进门禁。

## 持续集成

| 触发 | 跑什么 | 上限 |
|---|---|---|
| 每次 push 与 PR | 六条门禁命令 | 10 分钟 |
| 合并到主干 | 门禁 + 集成 + 场景 + 故障注入 | 20 分钟 |
| 夜间 | 门禁 + 端到端（宿主在线时） | 60 分钟 |
| 每季度与发版前 | soak 72 小时 | 无硬上限 |

- CI 跑在 `windows-latest`：本项目的路径、进程、编码行为都依赖 Windows，换平台等于换一套实现。
- CI 失败必须修；不允许用跳过标记让红变绿，除非记入 `DEBT.md` 并说明到期日；测试产物（覆盖率、junit）保留 30 天，失败时保留日志与截图。

## 事故回归

- 每条真实事故对应一条回归用例，放在 `tests/regression/`，命名 `<日期>-<简述>.py`。
- 用例先复现事故现象，再断言修复后的行为；不复现的用例不算回归。
- 事故复盘见 [13](13-变更与演进.md)；复盘里的「回归用例」一栏必须填文件路径。
- 回归集每次 PR 都跑，不单独安排。

## 测试数据与假实现

- 截图与日志用录制件，放 `tests/fixtures/`；截图裁到 ROI 后入库，单文件不超过 300 KB。
- 敏感信息（账号、令牌、手机号、路径中的用户名）脱敏后再入库。
- fake 插件放 `plugins/fake/`，与真实插件实现同一 Protocol；测试不引用真实网络与真实模拟器。
- 时间、随机数、UUID 全部可注入；测试里不依赖当前时间与随机结果。

## 不必测

- 界面像素级样式与动效曲线。
- 游戏内部行为与第三方程序自身的正确性。
- 一次性脚本与手工迁移工具（迁移本身仍需在夹具上验证）；Windows 自身行为（计划任务、自动登录）以手工核对与事件记录为准。

## 紧急例外

线上故障可以先修后补，但必须：

1. 在 `DEBT.md` 记一笔，写清绕过哪几条检查、原因、归还期限。
2. 24 小时内补齐用例与门禁，补齐后删除该笔。
3. 补不齐时把期限顺延一次并写明；第二次顺延视为未完成。
