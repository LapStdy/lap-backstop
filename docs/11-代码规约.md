# 11 · 代码规约

[返回总览](00-总览与索引.md)

本文回答：代码放在哪里、谁可以依赖谁、命名与类型怎么写、失败怎么表达。分层依据见 [02](02-架构.md) 与 [ADR 0001](adr/0001-分层与目录结构.md)，插件契约见 [05](05-插件与适配器.md)，门禁命令见 [12](12-测试与质量门禁.md)。

## 语言与工具链

| 用途 | 工具 | 要求 |
|---|---|---|
| 语言 | Python 3.12+（宿主实测 3.14.3） | 只用标准库与锁定的依赖 |
| 格式与静态检查 | ruff | `ruff check` 与 `ruff format --check` 无输出 |
| 类型 | mypy | `strict`；公开函数全部标注；不允许 `Any` 逃逸 |
| 依赖方向 | import-linter | 契约写在 `pyproject.toml` |
| 交付物文字 | `scripts/check_artifacts.py` | 无高风险命中 |

行宽 100，缩进 4 空格，UTF-8，LF；每个模块首行 `from __future__ import annotations`；依赖用锁文件固定版本。

## 目录与依赖方向

```text
core ──► storage ──► contracts
  │                     ▲
  └──► plugins ─────────┘（只依赖 contracts 与插件 SDK）
```

| 包 | 放什么 | 允许依赖 | 禁止依赖 |
|---|---|---|---|
| `contracts` | manifest、能力 Protocol、配置 schema、错误码、状态枚举、事件类型 | 标准库、`pydantic` | `core`、`storage`、`plugins` |
| `storage` | SQLite 连接、仓储、迁移、快照、证据文件 | `contracts`、标准库、`sqlite3` | `core`、`plugins` |
| `core` | scheduler、jobs、environments、resources、plugins(host)、recovery、events、api | `contracts`、`storage`、插件加载器（不导入插件实现） | 具体插件模块 |
| `plugins/<id>` | 一个插件的能力实现 | `contracts`、插件 SDK | `core`、`storage`、其他插件 |
| `tests` | 单元、契约、场景、回归 | 全部 | 无（生产代码不得 import `tests`） |

- 依赖单向，禁止环；新增跨层调用先写 ADR。
- 内核不 import 具体插件模块；插件由 `PluginHost` 按目录约定加载：入口固定为 `plugins/<id>/plugin.py`，导出 `PLUGIN` 对象，manifest 不设入口字段；能力通过 Protocol 调用。
- `contracts` 是插件唯一可见的内核面，只含数据类型与 Protocol，不含实现与数据库访问；它不导入 `core`、`storage`、`plugins`。
- `web/` 放前端页面与静态产物，不含 Python 代码；前端经 `/api/v1` 读写，HTTP 与 SSE 在 `core/api`（[ADR 0013](adr/0013-HTTP传输用标准库.md)）。

分层契约写在仓库根的 `.importlinter`，由 import-linter 门禁执行：`contracts` 不依赖内核、存储与插件；`core → storage → contracts` 单向；看门狗只用标准库；插件只依赖 `contracts`。

## 模块与文件

- 一个模块一个主题；文件名小写蛇形，不带版本号与序号。
- 内核 8 个能力各占一个子包：`scheduler`、`jobs`、`environments`、`resources`、`plugins`、`recovery`、`events`、`api`。
- 禁止 `utils.py`、`helpers.py`、`common.py` 这类无主题模块；代码归属写清在哪个能力的哪个子包。
- 插件目录 `plugins/<plugin_id>/`：`plugin.json`、`config.schema.json`、`plugin.py`（导出 `PLUGIN` 对象）；迁移文件 `storage/db/migrations/0001_<说明>.py`，编号四位递增，只前滚。

## 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 模块与包 | 小写蛇形 | `job_run_service.py` |
| 类 | 大驼峰 | `LeaseManager` |
| 函数与变量 | 小写蛇形，动宾短语 | `acquire_lease()` |
| 常量 | 大写蛇形 | `MAX_ATTEMPTS` |
| 布尔 | `is_`、`has_`、`can_` 前缀 | `is_ready` |
| 时间字段 | `_at` 后缀存 UTC 时刻 | `scheduled_at` |
| 时长字段 | `_seconds`、`_minutes` 后缀带单位 | `deadline_minutes` |
| 事件 | `域.动作`，小写 | `run.phase.started`、`env.state.changed`、`resource.leased`、`run.verdict` |
| 错误码 | `E_` 前缀，大写下划线 | `E_ENV_NOT_READY`、`E_PLUGIN_VERSION`、`E_DISK` |
| 配置键 | `段.键`，蛇形 | `scheduler.catch_up` |

状态值一律英文小写，取值集合见 [02](02-架构.md) 与 [09](09-调度与作业语义.md)。中文只出现在用户可见文案、日志消息、文档与注释里；标识符、表名、事件名、错误码一律英文。

## 函数

- 单一职责，名字能读出副作用；不加 `do_`、`handle_`、`process_` 这类空心前缀。
- 不超过 50 行、4 个参数、圈复杂度 10；超过时用 dataclass 收敛参数或拆函数。
- 不修改入参；领域对象用 `frozen=True` 的 dataclass，需要变化时返回新对象。
- 可预期的失败用返回值表达（`Verdict`、`Result`、状态枚举）；程序错误用异常。
- 禁止裸 `except`，禁止 `except Exception: pass`；捕获后要么处置，要么带上下文重抛。
- 业务逻辑里不出现 `time.sleep`；等待走注入的 clock，测试用虚拟时钟；每个外部调用都必须带超时。

## 类型

- 公开函数与方法的参数、返回值必须标注；mypy 以 `strict` 运行。
- 不用 `Any` 绕过；无法表达时用 `object` 并在调用处收窄，或抽 Protocol。
- 领域对象用 frozen dataclass；跨边界载荷用 `TypedDict`；模块之间不传裸 `dict`；状态与能力标识用 `StrEnum`。
- 时间一律 `datetime` 且带 UTC 时区；时长用 `timedelta`；不外传 naive datetime。
- 插件 payload 在内核里的类型是 `Mapping[str, object]`：按插件 schema 校验并原样存取，不解释字段。
- JSON payload 例外：形态完全由插件 schema 或事件 schema 决定的字段（JobTemplate 的 `config`、`VerificationPolicy.params`、事件载荷）用 `Mapping[str, Any]`；例外止于契约层的读写函数签名，取出具体值前用 `isinstance` 收窄，跨模块传递的领域对象仍用 `Mapping[str, object]`。

## 错误

| 类别 | 例子 | 表达方式 |
|---|---|---|
| 调用方错误 | 参数非法、状态转移不允许 | 领域异常，API 映射 4xx，消息指出字段与合法取值 |
| 环境错误 | 模拟器起不来、截图超时、租约超时 | 返回值里的失败结果，交 Recovery 按 policy 处理 |
| 契约错误 | manifest 缺字段、`api_version` 不兼容、能力缺失 | `PluginContractError` 加 `E_PLUGIN_MANIFEST` 或 `E_PLUGIN_VERSION`，拒绝该插件，内核继续运行 |
| 程序错误 | 断言失败、类型不符、不可达分支 | 抛异常，记 ERROR，当前 JobRun 转 `failed` |

- 异常携带上下文：`job_run_id`、`phase`、`plugin_id`、`attempt`。
- 堆栈只进日志；界面与通知只显示人话与错误码；每个错误码在 [03](03-数据模型与接口.md) 有定义、触发条件与处置建议。
- 不把 `failed` 降级成 `unknown`，也不把 `unknown` 说成 `completed`。

## 日志

- 结构化输出，key-value；每行含 `at`（UTC）、`level`、`event`、`run_id`、`plugin`、`fields`。
- 级别：`DEBUG` 只在本机排障开启；`INFO` 生命周期节点；`WARNING` 已自愈的异常；`ERROR` 需要人看。
- 用 `event=` 与字段，不拼自由文本；同一条日志的字段名固定。
- 不打印 token、口令、Cookie、截图字节与完整个人路径；URL 打印时脱敏；不在轮询循环里逐帧打 INFO。
- 日志与事件分工：事件入库、可回放、可作证据；日志只供排障，不作判定依据。
- 核心日志文件名文法 `core-YYYY-MM-DD[.N].jsonl`（含 `.gz` 归档形态）的单一定义点是 `core/log_names.py`（仅标准库）：日志写入、保留清理与看门狗共用同一对象。
- 实现与字段约定见 [ADR 0009](adr/0009-结构化日志与事件分工.md)。

## 配置

- 默认值集中在一处（`settings` 表的默认行与 `config/defaults.toml`），业务代码不写魔法数字。
- 每个配置项有：类型、默认值、取值范围、单位、一句话说明；启动时校验，非法拒绝启动并指出键名。
- 引导配置用 TOML 加 `LAP_BACKSTOP_*` 环境变量（数据目录、监听地址、日志级别），只在启动时读一次；业务配置（调度、模板、插件配置、通知）的唯一真源是数据库 `settings` 表。
- 密钥用 DPAPI 或进程环境保存，不回显、不落日志、不进备份。
- 插件配置由插件 schema 定义，内核只校验与存储，出错时把字段路径回给调用方。

## 并发与超时

- SQLite 用 WAL 与 `busy_timeout=5000`：内核 tick 线程持一条长期连接；执行线程推进一次运行时自开连接、收尾时关闭；HTTP 请求线程与手动环境动作在各自线程按需自开连接。写事务短，不在事务里做 IO。
- 一条连接不跨线程使用（保留 `check_same_thread` 默认检查）；跨连接的读改写要么由单一写者串行，要么由调用方加锁，评审时写明这条数据的写者归属。
- 环境状态的「读 → 判迁移 → 写」在同一 IMMEDIATE 事务内完成，以事务外记录的前置状态仲裁跨连接竞争：先提交者赢，后写者丢弃结果（不写状态与 `env.state.changed`，写 `core.env_action_conflict`）并向调用方抛状态冲突异常；插件调用不进事务，其结果只在发起调用前记录的前置状态仍成立时应用。
- 插件在 worker 子进程内运行，内核不执行插件代码；作业经数据库队列进入执行器，能力调用走 worker 侧 RPC（行分隔 JSON），带调用 id、调用超时与取消宽限，见 [ADR 0010](adr/0010-worker子进程与能力调用RPC.md)。
- 锁一律带超时，禁止嵌套获取；跨调用持有时改用租约（TTL + 续租）。
- 异步代码用 `asyncio.timeout` 包住每个外部调用，不用无超时的 `await`；长任务拆阶段，每阶段独立超时与取消点。

## 外部调用

- HTTP：显式超时、重试上限、指数退避、关闭系统代理（除非配置打开）、校验 TLS。
- 进程：记录 pid 与启动时间，防 PID 复用误杀；启动前查同名进程；结束时结束整棵进程树。
- 文件：只用 `pathlib.Path`；显式 UTF-8；写入用临时文件加原子替换；不删除正在读写的文件。
- 命令与脚本参数用列表传参，不拼字符串、不经 shell。

## 注释与文档字符串

- 注释只写为什么，不写改了什么，也不写施工状态。
- 公开函数写 docstring：做什么、参数、返回、抛什么异常。
- 插件实现注明对应的能力契约名与依赖的 `api_version`；判定与恢复逻辑注明证据来源。

## 规模上限

| 项 | 上限 |
|---|---|
| 函数行数 | 50 |
| 参数个数 | 4 |
| 圈复杂度 | 10 |
| 类行数 | 300 |
| 模块行数 | 500 |
| 单次提交有效改动 | 400 行（迁移与生成代码除外） |

超限要在评审里说明理由；同一文件连续两次超限，按应重构处理。

## 插件边界

- 插件只实现 manifest 里声明的能力，不实现内核职责（不调度、不排队、不写事件表）。
- 插件通过 `RunContext` 拿配置、日志、时钟（`clock`）、取消令牌、事件写入（`emit`）与证据写入（`record_evidence`）；成员清单以 [05](05-插件与适配器.md) 的 RunContext 为准，插件拿不到数据库连接与内核模块。
- 插件返回 `Verdict` 与 `Evidence` 描述，不自行通知用户；通知由内核按 Policy 发出。
- 插件不假设独占机器或单实例；需要环境与资源时申请租约；超时或崩溃由内核标记 `E_PLUGIN_CRASH` 并记事件。
- 插件不得依赖其他插件；跨插件共享的逻辑下沉到 `contracts` 或内核能力。
- fake 插件与真实插件实现同一 Protocol，放在 `plugins/fake/`，供内核测试与契约测试使用。

## 测试代码

- 命名 `test_<行为>_<条件>_<期望>`。
- 不 `sleep`、不连真实网络、不启真实模拟器；用虚拟时钟、录制帧与 fake 插件。
- 每个测试独立，不依赖执行顺序，不共享可变全局状态；断言信息写清实际值与期望值。
