# lap-backstop

给 Windows 上的外部自动化脚本配一个**调度与监督层**：按计划在正确的时间、正确的环境状态下执行，监督过程，验证结果，失败按策略恢复，任何地方可看可停。

## 项目定义

| 项 | 内容 |
|---|---|
| 一句话目标 | 把一台 Windows 电脑上的自动化脚本托管起来：按时触发，环境就绪才执行，过程可观测，结果有证据，失败能恢复，救不回来立即通知。 |
| 产品定位 | 通用调度与监督平台。平台内核不依赖具体脚本与游戏；MAA、MAAEnd 是首批插件。 |
| 目标用户 / 场景 | 单人自用。一台常开的 Windows 电脑，托管《明日方舟》日常（MAA）与《终末地》日常（MAAEnd）；运行时段通常在睡觉或外出。 |
| 形态 | 本机常驻核心 + HTTP API/SSE；电脑端 WebView2 + 托盘；手机端浏览器/PWA；Android APK 作为客户端作品线。 |
| 首个里程碑 | MAA 插件完成「预热 → 就绪 → 执行 → 验证 → 通知」闭环，在慢机器上连续 7 天无人值守。 |
| 验收方式 | 平台验收与首批插件验收见 [docs/01](docs/01-需求与边界.md)。 |

## 为什么是平台

外部脚本有三个共同点：运行环境有状态、启动可能很慢、失败方式各不相同。平台把四件事做成稳定内核：

1. **时间**：什么时候跑、错过怎么办、能不能并发、何时算超时；
2. **资源**：模拟器、游戏账号、GPU 互斥使用，谁在跑、跑到哪；
3. **状态**：环境是否就绪、作业走到哪一步、崩溃后如何恢复；
4. **契约**：插件提供什么能力、返回什么、如何版本化。

脚本差异（怎么启动、怎么读日志、怎么判完成、怎么改写配置）全部由插件承担。平台不假设每个脚本都有配置文件，也不把某款游戏的判定口径写进内核。

## 核心概念

| 概念 | 含义 |
|---|---|
| 插件（Plugin） | 扩展包：manifest + 能力实现 + 配置 schema。 |
| 环境（Environment） | 外部运行环境，例如 MuMu + 方舟、终末地客户端；有独立状态机。 |
| 脚本（Script） | 被托管的外部程序，例如 MAA、MAAEnd。 |
| 作业模板（JobTemplate） | 环境 + 脚本 + 验证策略 + 恢复策略。 |
| 调度（Schedule） | 何时触发作业：cron、时间点、间隔；带补跑、合并、优先级、预热与保温。 |
| 运行（JobRun） | 一次执行，包含准备、执行、验证、收尾四个阶段。 |
| 资源租约（ResourceLease） | 环境、账号、GPU 等资源的互斥使用凭证，带 TTL。 |
| 事件（Event） | 运行过程中追加写入的事实记录。 |
| 证据（Evidence） | 截图、日志片段、探针结果、退出状态等可复核材料。 |
| 结论（Verdict） | completed / failed / unknown，附证据与验证策略。 |
| 建议（Advisor） | AI 旁路能力：未知画面分诊、失败归因、公告解读等，只出主意。 |

## 平台做什么

- 调度：cron、时间点、间隔；补跑、合并、优先级、截止时间；预热与保温。
- 资源：环境、账号、GPU 的租约与排队；单实例；崩溃恢复。
- 作业：四阶段生命周期、attempt、取消、超时、恢复策略。
- 插件：manifest、能力路由、配置 schema、版本、契约测试。
- 验证：Verdict + Evidence + VerificationPolicy；证据可回放。
- 恢复：重试、退避、复位环境、重启脚本、停手通知。
- 观测：事件流、运行详情、证据、通知、外部心跳。
- 客户端：电脑端窗口、手机浏览器、APK 客户端。
- 多机：Runner 插件化，长期支持。

## 平台不做什么

- 不重写 MAA / MAAEnd，不修改游戏客户端，不做游戏内作弊或绕过检测。
- 不做多用户、多租户、SaaS、对外服务。
- 不做跨平台（Linux / macOS）。
- 不追求 100% 自动：救不回来就停手叫人。
- 不把某款游戏的判定口径、配置格式、任务模型写进内核。

## 四条地基

1. **内核不依赖具体脚本与游戏。** 插件换掉，内核行为不变。
2. **配置是数据，执行是插件代码。** 用户可编辑的内容由插件 schema 定义；执行逻辑不塞进通用 DSL。
3. **平台数据库是唯一真源。** 外部系统通过插件的 config projection 同步；差异由插件声明处理策略。
4. **结论有证据，动作有事件。** 没有证据的结论不算结论，没有事件的动作查不到。

## 技术栈

| 选择 | 理由 |
|---|---|
| Python 3.12+ | 图像识别、Windows 窗口操作、MAA 生态都在 Python。 |
| FastAPI | 本机 HTTP 服务与接口，异步，自带 OpenAPI。 |
| SQLite（WAL） | 单机单用户，免部署、可备份；事件与状态同库。 |
| React + Vite + TypeScript + Tailwind + shadcn/ui | 电脑端界面；构建产物由 FastAPI 托管。 |
| SSE | 运行事件实时推送；断线重连拉快照。 |
| Kotlin + Jetpack Compose | APK 客户端；作品线，不作为一期可靠性关键路径。 |
| Tailscale | 私有网络访问；认证交给网络层 + 单 token。 |
| Windows 10/11 | 目标运行环境；MuMu 需要已登录的交互会话。 |

## 工作方式

- **证据优先**：每个任务有可验收判据；没有测试、数据或差分证据，不宣布完成。
- **契约先行**：内核与插件接口先写 ADR 与契约测试，再写实现。
- **函数级质量**：改函数先过 function-spec；新增或修改函数后用 function-attack 找漏；性能问题用 perf-evidence 拿基线。
- **交付物通道**：文档、界面文案、注释只写「此刻为真」；交付前跑 python scripts/check_artifacts.py .。
- **结构留痕**：顶层目录、技术选型、公共接口变化写进文档或 ADR。
- **任务清单**：没做的事记在 TASKS.md。
